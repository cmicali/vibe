# Unit tests

`make test` runs these (always Debug). The `VibeTests` target is defined in `project.yml`; editing its source list means re-running `xcodegen generate`.

`iOSDriver/` is **not** part of this suite — it is the `vibe-debug` skill's interactive touch driver, a resident XCUITest started by `drive-ios.sh` and never run as a test. It has its own target (`VibeiOSDriver`) and is excluded from `VibeTests`' `Tests` source entry.

## What belongs here

Deterministic host-less logic and machinery only — code whose outcome is controlled by its inputs or narrow injected I/O boundaries and needs no running app: sample and geometry math, archive encode/decode and validation, string and duration formatting, precedence and fallback rules, cache-key derivation, coordinator accounting, queue/barrier/retry orchestration, and local temporary-file wrappers. The suite is **host-less** (no `TEST_HOST`), so it runs in seconds with no window server, no audio hardware, no permissions and no Vibe instance — and it does not inherit the app's sandbox, which is what lets it read fixtures from the repo.

Anything that needs the app running — shell transport routing, menus, drag-and-drop, layout, screen rendering, Now Playing, device switching — belongs in the `vibe-debug` skill's command channel instead, which drives a live app and reads back state as JSON. Player transport and FX also have a separate device-free audio suite below.

**Where rendering is the whole class, extract the arithmetic into a seam.** `AudioPlayer` and `AudioFX` decisions that can be expressed without rendering live in header-only `*Rules.h` / `*Math.h` files that the shipping class **calls** rather than restates: `FadeMath.h` (`VibeIncomingFadeMilliseconds` and the per-frame curves, called from `AudioPlayer.m` and `AudioVoiceBus.m`), `AudioFXMath.h` (called from `AudioFX.m`), `TransportMath.h`, `NowPlayingRules.h`, `PlayerScreenRules.h`. The voice bus itself is tested host-less in `AudioVoiceBusTests`: the tests own the output buffers and call `VibeVoiceBusRender` directly, with inline decoding, so every frame the audio thread would produce is compared against the file it came from; `AudioFXChainTests` hosts the FX chain on its own and calls `VibeFXChainRender` through the debug pump's frame-driven clock, the same one the render suite drives the whole player on. Reach for that before concluding a class cannot be tested.

**The boundary is uncontrolled I/O.** `AudioWaveformLoaderTests` writes a WAV through `Tests/AudioFixtures.h` and reads it back through the real loader. It also streams one into a part file behind a `CloudFileAvailability`, and runs the real `AudioWaveformCache` over a store under its temp directory (`initWithRootPath:`), never the user's caches. `DropboxMirrorTests` drives the real `DropboxClient` and `DropboxMirror` over an `NSURLProtocol` stub at the HTTP boundary and a temp root; `DropboxClientInternal.h` (`adoptRefreshToken:accountID:`, `useSessionConfiguration:`, and `retryDelayScale`, so a scripted drop or 429 waits milliseconds, not the real seconds that once made the class most of the suite's wall time) is that seam, and the debug channel's `VibeFakeDropbox` stands on the same two methods. `HTTPTransferClientTests` drives the plain `HTTPTransferClient` over `HTTPStub`, an `NSURLProtocol` with a host of its own per instance, handed to the client only through its session configuration. `RemotePlaceholderStoreTests` drives `RemotePlaceholderStore` over the same stub and a temp root, through a test subclass that names only each placeholder's URL and whether it reads by range. `LinkStoreTests` drives the real `LinkStore` over the same stub and a temp root. `answerHost:` lets one stub answer a public name too, so a test sees that nothing was sent there. `VibeFakeHTTPTests` drives the debug channel's `VibeFakeHTTP` through the plain client, as the running app does, and a `LinkStore` over it. `VibeTests` keeps its fast logic/orchestration scope; `VibeAudioTests` drives the production renderer through the debug pump, with no output device or app. Neither suite opens hardware.

**A network mount is forced, never found.** `AudioFileHandleStreamingTests` reads ahead on files in its own temp directory. `AudioFileHandle+Debug.h` forces the mount rule for those URLs, and its before-read hook scripts each `pread` the read-ahead makes. `VibeReadAheadScript` is that script's shape: it counts reads by offset, and it throttles them, stalls them from an offset until released, fails them with an errno once or always, or ends the file at an offset. A stall can be released one read at a time. A failure can be held after it is signalled, until the test releases it. A stalled read holds its thread as a dead mount's syscall does. The render suite keeps a copy of its own, since it compiles in another target. **The read-ahead counts are process-wide**, and a stalled thread outlives its handle as an orphan. A class that parks threads releases them in `tearDown` and waits for 0 live and 0 orphaned threads before the next test counts. `AudioFileOpenRulesTests` feeds `VibeMountReadsAhead` a fake `statfs` table and never reads the machine's.

**Test an orchestrator as itself when its nondeterminism has narrow boundaries.** `AudioTrackMetadataLoaderTests` runs the production queues, stage-one barrier, ranking, materialization slots, real coordinator, parse claims, installation, publication and cancellation while replacing only cache reads, file parsing and the coordinator's provider-operation boundary. Do not copy its state machine into a fake or flatten it into disconnected rule tests: that would stop testing the machinery the live scenario relies on. `NowPlayingController` follows the same approach for publication: injected clock and OS sinks, actual dirty checks and artwork construction. `AudioFileConverter` uses held file-operation callbacks and the real `NSUndoManager` for conversion undo/redo; its dormant TagLib functions are fail-loud decoys in `FLACDisposalRulesTests`. Its injected constructor skips the launch-time temp sweep. OS provider state, app-shell routing, remote-command registration and hardware playback settlement remain live tests.

`ArtworkDisplayController` runs its real single-render/latest-request scheduler in `AudioTrackTests` with held renderer completions and a publication sink; the sink keeps views and the Dock out of the suite. Header time formatting lives in `Formatters`, and `TrackDisplayRules` gates label updates. `OpenBurstCoalescerTests` exercises launch priority through the production launch method; `PlaylistFileTests` round-trips the private session with temporary files and isolated defaults, replacing only the write when proving failure cleanup.

`OutputFormatRulesTests` also runs `AudioDeviceManager` with injected enumeration and retry scheduling: real serial refreshes, immutable snapshots, saved-device waiters and main-thread observers, with no HAL registration. `CoreAudioUtil.releaseDeviceObligation:attempt:isAbsent:` is the shared format-restore/exclusive-release retry loop; controlled attempts and real manager snapshots test retained versus retired cleanup obligations. Output rebinding and actual device property I/O remain live tests.

The test target deliberately links an incomplete `AudioTrackMetadata` decoy because the real implementation is ObjC++/TagLib. Its real-parser constructor raises; loader fixtures must use the copy-capable duck fake, and any newly required selector must be added deliberately rather than treating the decoy as production metadata.

## Rendered audio

`make test-audio` generates deterministic fixtures under `build/audio-fixtures`, tests the hardware comparator's corruption detection, then runs **VibeAudioTests**. It is host-less, compiles the production player, FX, decoder and loading machinery into its own derived data (`build/AudioDerivedData`, so `make -j2 test test-audio` runs both suites at once), and reuses `TestFilesystemGuard.m`. `AudioPlayerRenderTests` is a base class with no tests; each topic is a subclass in the same file (`…FidelityTests`, `…TransportTests`, `…SignalTests`, `…PipelineTests`, `…DeviceTests`, `…OutputTests`, `…LinkTests`), and the parallel runner spreads the subclasses across processes, so a new test joins its topic's subclass, and a subclass that grows past the others is the one to split. `…TransportTests` is the largest now, and the next to split. `ARGS=-only-testing:VibeAudioTests/AudioPlayerRenderTransportTests/testGaplessSplitSignalAcrossRenderBlocks` narrows a run; use the actual subclass and method name. `make test-audio-summary` reads `build/AudioTestResults.xcresult`.

`Tests/AudioFixtures.h` is the one home of fixture writers and of the reference conversion (`VibeReferenceResample`), shared by both targets — raw RIFF bytes by default, so a fixture never makes `AudioFileHandle` its own decode oracle, and the handle's writer for a layout or a codec; `AudioPlayerRenderTests`, the base class, is the one home of capture, comparisons and delegate traces. The existing `VibeManualRenderPump` supplies either a frame-driven clock or the app's real timer. Voice ramps, FX sweeps and idle stop use their production algorithms with that clock. File opens and delegate delivery keep their real queues; bounded event waits settle them between render blocks. Before every frame-driven slice the pump decodes the bus inline and after every slice it drains it, so a voice is live before the first slice that could render it and every bus event lands before the next. The test constructor attaches the pump in place of the output unit before any voice exists. It skips HAL observation, and tests assert the actual mode and bus format before playing. No mock renderer, copied transport implementation or UI host is involved.

The oracle fixes one alignment and compares **every remaining source frame in every channel**. With Declick on, only its first 50 ms of startup is excluded from identity comparisons (off, nothing is); a separate constant-signal test measures startup/stop envelopes over all six rates. Lossless WAV matrix references come directly from the fixture bytes, independently checking the handle's decoding. FLAC/ALAC/AIFF references are the original PCM. Lossy formats compare to their decoded PCM, never to the pre-encode source. Independent Apple AAC decodes may differ in floating-point rounding, so AAC allows four float epsilons (below −126 dBFS); other codecs retain exact comparisons. Captures must contain complete channel frames and no unexpected audio after the reference ends. Corruption tests reject dropped/duplicated frames, channel swaps, polarity/gain changes, clipping, silence, NaNs, single-LSB changes, truncation and short matching excerpts.

The core matrix is 44.1/48/88.2/96/176.4/192 kHz × PCM16/PCM24/float32 × mono/stereo. Bit-perfect and regular FX-free playback require exact float samples, and so does a dormant FX chain — never engaged, or every effect released and rested (`testEveryReleasedEffectRestsAndReplaysTheFileExactly`, each key, the boost, the pad, an off inside the sweep) — with the meter installed. **Never loosen that to a tolerance**: a low kill left parked as its flat identity biquad instead of rested differs by about `7e-13`, which only an exact comparison sees. A float32 reference cannot show what float32 dropped, since it carries the same narrowing as the capture, so wider sources are also compared at full width (`CompareWidePCM`, against the fixture's own integers or float64 values as doubles): a 32-bit file on float32's grid plays exactly, and integer32/float64 samples finer than float32's significand arrive rounded once to the nearest float32, every one counted. The corruption test proves a single change one bit below float32's significand fails it. SRC asserts gain within 0.01 dB, duration and an alias ceiling of −90 dBFS; active FX assert their intended frequency response, echo timing/stereo alternation, decay and finite output.

Transport coverage includes start-paused, stop/replay, pause/resume after idle shutdown, seeks, mode/format changes, interrupted fades, a skip storm inside the voice pool, a starved decoder, and repeated operations with bounded voice counts. The pipeline's own edges are covered too: the varispeed is a bit-perfect pass-through at zero pitch (the bus exact, the converter never run, and a track exact from the first frame after the fader returns) and joins and leaves it across repeated toggles without a click, a dip or a skipped frame; every edge is read to the frame off a linear ramp at every rate and in mono (`testPitchEngagesAndDisengagesAtTheExactFrame`); its distortion, false tones and flatness are measured at six fader settings at 48 and 96 kHz (`testPitchQuality`); held off zero, a sawtooth read through a seek, a pause past the idle stop, a splice, a rate change and a ten-minute play shows the bus leading what plays by the kernel's half-width alone (`testPitchedTransportKeepsThePositionHeard`, `testALongPitchedPlayKeepsItsPosition`), and `AudioVarispeedTests` drives the stage host-less in the fast suite; the output's rate moves under the pump (`debugSetOutputRate:`, the same path a device or an iOS route takes) and the playing or paused track is kept at its position; a lossy source at another rate and width is mixed on its own rate, then resampled to the bus's; FX disabled while tails ring processes nothing and passes the file exactly; `audioPathSnapshot` reports every stage; a skip past the end fades the voice like every other edge; a reverb released before a pause keeps the output running past the idle stop until its declared tail rests, and a send held through the pause keeps it no longer than that tail; `outputIdle`, which the iOS session's release reads, answers only at the idle stop, across a 25 s tail, a cancelled stop, a failed or parked open, a refused start and a system stop, and an idle edge a new play overtook finds the output started; a system stop no verdict follows pauses after its second, never inside it, and one a restart follows keeps playing; a reinstalled meter publishes none of the audio before it; a render stuck inside the pipeline past the wait's bound (`debugHoldRenderInside:`, which blocks a render inside after it has read the bus, on the thread `debugRenderOnCallerThread:` drives it from) keeps the meter, the bus, the varispeed hosting and the FX chain alive through a rate change while the rebuilt output's renders are refused as silence (`renderRefusals`), and frees them at the first drain that sees it outside; a meter callback stalled across a remove-and-reinstall (`AudioLevelMeter+Debug.h`'s `debugHoldRender:`) publishes nothing into the new session; a file read stalled inside the decoder (the `AudioFileHandle` read swizzled to block) holds neither the player queue nor a rate change, and the re-voiced track reads its file only once the retired decoder has left it; a hosted effect whose render fails (`AudioFX+Debug.h`'s `debugUninitializeUnitAtIndex:`) fails the slice at the output unit instead of playing, and renders again after a rebuild; and a production player whose output unit cannot be made fails the start with `VibeAudioErrorEngineStartFailed` rather than report Playing, while a unit made late (`createOutputUnitOnQueue`, swizzled to bring a new rate) is followed by the segment before a settlement builds it and by a parked voice before a resume. A stalled old read also leaves a new unrelated song free to play exact PCM, including after the old read returns. A file still downloading is a remote placeholder whose fetch the test writes (`streamingCopyOf:`), played on the decode pool, since the inline fill would block on a waiting read: the whole capture of a stream held twice, silences removed, is the file exactly, with one hold and one resume per stall, no underrun and the output running past its idle stop; a seek, a stop and a skip while a read waits at the edge each interrupt it, the stop and skip letting the coordinator cancel the transfer; a failed transfer ends in the failure path; and a stall pauses in place, after which play fetches afresh and resumes at the held frame, a stop or play submitted right after that resume still winning. A headerless MP3 streams on an estimated length, a constant-rate head's included: the clock follows the audio past a short estimate, a stall past it holds and replays from the position heard, and a cue row beyond it plays from its start to its own end. A link is opened through the real `LinkStore` over `HTTPStub`, which this suite compiles too (`…LinkTests`). It plays exactly as the file, through a held stall, a seek past the download's edge, a seek back, and a connection lost mid-body. A file on a network mount is a forced, scripted read-ahead (`networkCopyOf:`), also played on the decode pool. A throttled one plays exactly as the direct open. Seeks beyond, inside and behind the blocks it holds each land exactly, and the one behind reads a dropped block again. A stalled read holds the voice, then plays on once, exactly, when released. A stall past the deadline pauses in place with `VibeAudioErrorConnectionLost`, and so does a read error past it. Play then replays from there. A brief read error holds and plays on exactly. A seek, a stop and a skip during a stalled read keep the player queue responsive. The open deadline stops an open parked in a read-ahead. A parked prefetch reads ahead and splices exactly. `AudioVoiceBusTests` checks that a seek waits for the same handle's reader, that reusing its old slot gives unrelated audio a free reader, that eight held slots keep a pending start through idle and recover when released, and that a future successor on another queue cannot block unrelated pending starts. The render suite cancels a buffered successor with its read held, re-arms it on another queue while paused, and compares the gapless PCM after the old read returns; releasing the file must not wait for output to resume or the old slot to recycle. It also starts a second voice on a withheld file and requires it on the first's queue once reads are allowed, and withdraws a waiting successor from a voice an earlier successor left a boundary on, which must report it withdrawn. `AudioVoiceBusTests` also polls `filesInUse` across a gapless handoff on the real decode queue and requires the successor listed at every instant. `AudioVoiceBusTests` reads snapshots while a render runs on another thread and while paused voices are started, killed and recycled through one slot, the cases ThreadSanitizer reports without the atomics and the seqlocks, holds a render inside the bus (`debugHoldRender:`, `AudioPlayer+Debug.h`) while a late successor's reopen waits for it — `stopReadingThen:` returns within its bound with the render still held, and a decoder whose reads are allowed gives up on its own, the end restored either way; the render suite's `testARebuildCompletesWhileAVoiceRenderIsStuck` is the player's half, a rate change completing at the new rate with the render still held — counts decoder turns (`decodeTurns`) to show a voice paused at its published end asks for none while a successor queued after it still restarts the decoder; the suite is run under it when the bus's threading changes (`-enableThreadSanitizer YES -enableCodeCoverage NO`, a separate derived-data path), and so is the whole render suite, since a test's own cross-thread flag reads as a race there (`testSeekStopsTheOldVoiceReadingBeforeItsFileIsHandedOn` polls an atomic). `AudioFXChainTests` adds a chain disconnected with tails ringing (no unit renders, the signal exact) and the reverb and delay returns summing through overlapping tails. Gapless tests split a continuous nonperiodic source at awkward frame boundaries and compare the concatenation across 63/256/1024/4096-frame pulls; short successors and canceled/replaced queued successors are also exercised. The bus's conversions are compared with `VibeReferenceResample` (`AudioFixtures.h`): the whole file, read by `AVAudioFile` rather than the bus's handle, through the same resampler off the bus, its tail flushed with silence and cut at the frames fed as the bus does; the whole-file render matches it exactly, and the gapless splits match it frame for frame. Duration and PCM mismatches fail normally. Failures of a PCM comparison attach reference, capture, aligned difference WAVs and event and pipeline state to the result bundle. Metrics/envelope assertions include their measured values in XCTest failures.

The canonical fixture generator's `--render-tests` mode owns the deterministic source corpus; tests only create temporary slices and malformed inputs. Stock macOS encoders cover core formats, CAF and W64 included; MP3/MP2/QTA and Ogg (Vorbis, Opus, and the refused FLAC in Ogg) need ffmpeg and are explicitly skipped if absent — CoreAudio lists an Ogg writer that refuses every input. CI installs ffmpeg so these do run there. The ISO/IEC 11172-4 Layer III compliance stream and its reference decode (`iso-compl.mp3`, `iso-compl.f32`) are ISO's, so the generator fetches them from FFmpeg's FATE mirror, checks their pinned hashes, and leaves them out when that fails; `testDrMP3PassesTheISOComplianceStreamAtFullAccuracy` then skips. Fixture buffers have fixed short durations, render loops are bounded, and the loopback IOProc preallocates a bounded capture rather than allocating or locking on the audio callback.

The pump proves the software path, **not** DAC samples, hardware negotiation, exclusivity or iOS session recovery. `make test-audio-loopback` and `make test-audio-device` opt into the existing `vibe-debug` verifier for those macOS boundaries; see that skill for setup. Hardware is never an ordinary CI prerequisite.

## Rules that are easy to get wrong

**The suite must leave no trace on the developer's machine, and `TestFilesystemGuard.m` is what makes that true.** Being host-less means being **unsandboxed**, so every standard user directory a production path resolves is the developer's real one: `AppTheme`'s artwork store lands in `~/Library/Application Support/<main bundle identifier>/ThemeArt` (for the suite, the XCTest tool's identifier), and because the suite has no bundle identifier of its own, standard defaults would be `~/Library/Preferences/com.apple.dt.xctest.tool.plist` — a domain shared with every other XCTest process on the machine. The guard runs at **image load**, before XCTest builds a case: it makes a per-pid temp root, points `VIBE_THEME_ART_DIR` inside it, and makes `+[NSUserDefaults standardUserDefaults]` answer an in-memory store of the process's own, then removes the root at exit. A process that crashes or is killed never reaches exit, so each one first removes the roots of pids that are gone, and its own, which a dead process whose pid it reused may have left. A test wanting a fresh store of its own allocates the same class, `VibeTestUserDefaults` from `TestFilesystemGuard.h` (`PlaylistFileTests`). **In memory, not a cfprefsd suite, even a per-pid one**: on CI a suite key froze at its first value for seconds while other keys wrote normally. It is deliberately not a `setUp`: a suite-wide guarantee each class opts into is one a new class silently opts out of.

**That per-process isolation is what lets `VibeTests` run in parallel** (the scheme's `parallelizable`): classes spread across runner processes, and without it one process's `AppSettings` writes would reach another's reads. A new cross-process resource — a fixed temp name, a named defaults suite, a real `~/Library` path — breaks that the same way; UUID or per-pid names only.

Two traps follow from it. A test narrowing the artwork path for its own isolation must **restore** the previous value, never `unsetenv` it: unsetting hands every later test the real `~/Library`, so the leak surfaces under whichever class runs next rather than the one that caused it (`AppThemeTests`). And **saving and restoring a setting around a test does not return it to unset** — reading an unset key answers the *registered* default, so writing that value back materializes a key that was never there (`FolderArtWalkTests`), visible to every later class in the same process.

**A bounded wait is a hang guard, a gate or a negative check, and only the last is short.** A wait for something that must happen (an expectation, an asserted semaphore, a poll helper's deadline) uses `VIBE_TEST_HANG_TIMEOUT` from `project.yml`, never a literal: with classes in parallel and `make -j2`, utility-QoS work goes unscheduled for seconds, and 2 s guards failed there. A gate the test releases itself — a fake that blocks on a semaphore until the test signals it, or a pending grace in the code under test that the test settles by cancelling or releasing (`AudioWorkSchedulerTests`) — uses `VIBE_TEST_GATE_TIMEOUT`, which outlasts the guards the test waits on while holding it. A negative check (an inverted expectation, a wait asserted `NotEqual`, a fixed window before asserting nothing arrived) stays short, since every pass runs its full length. A fixed window before asserting something *did* arrive is the flaky shape: poll up to the guard instead. Elapsed-time assertions are none of these, and never read the test thread's own clock, which is late by however long that thread was descheduled: an interval is measured between stamps taken where the code under test runs, in its callbacks into the test's fakes, on the clock its timer uses (`testProductionGatedTimerReopensADatalessScanAfterForegroundRelease`). A timer the code under test arms on its own that the test does not wait for — a retry seconds out — is a boundary to replace like an I/O one, since a slow run is still going when it fires (`testFailedDeviceSwitchReconcilesOutputGraph`'s bind retry).

**A fixture's size on disk says nothing about its length.** The generator writes files whose declared content dwarfs their bytes, so a seek past a 32-bit frame count can be tested: `flac-long.flac` is under a megabyte and 4.3 billion frames (65538 frames of 65535 constant samples). Anything that decodes a fixture to its end, or times a pass over one, reads the header's frame count first and chooses its fixture by that; a full decode of such a file runs for hours.

**Never put test files under `Vibe/`.** Both app targets list whole shared subsystem directories (`- path: Vibe/Audio`, `- path: Vibe/Util`, …), recursed unconditionally — a test file dropped into one is compiled into the shipping binaries of both apps. `/Tests` at the repo root is named by no app target. (`**/*.md` is excluded everywhere, so this file is safe either way.)

**Sources under test are compiled into the test target, not linked from the app.** Adding a test for a new file means adding that file to the `VibeTests` source list in `project.yml`. Keep the list curated, and keep TagLib out of it — nothing here needs it, and the vendored subset would dominate the build.

**Where a test needs an `AudioTrackMetadata`, use a duck-typed fake cast to the property type.** `AudioTrackTests.m` declares `FakeTrackMetadata : NSObject` and installs it through `AudioTrackInternal.h` — `objc_msgSend` does not care about the static type, and `AudioTrack` only ever sends messages to its metadata, never names the class.

**Where the thing under test is a private class method, share it through an `*Internal.h` the implementation file imports too** (`NSURLUtilInternal.h`), rather than re-declaring selectors in the test: a rename then breaks the build instead of the run.

**A temp-directory fixture has two spellings, and both turn up.** `NSTemporaryDirectory()` hands back `/var/folders/…`, `/var` is a symlink to `/private/var`, and a directory walk answers in the resolved form while anything that standardizes a path drops the `/private` prefix again. `URLByResolvingSymlinksInPath` does not settle it — it leaves the temporary directory's prefix as it found it. Use `realpath(3)` on the fixture root at setup and be ready to strip either spelling when comparing (`NSURLUtilTests.m`).
