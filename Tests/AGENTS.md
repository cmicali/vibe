# Unit tests

This directory holds the tests of the three test targets, `VibeTests`, `VibeAudioTests`, and `VibeiOSTests`, and their shared helpers in `Support/`. It also holds two tools that are not test suites, `iOSDriver/` and `BenchComponents/`.

`make test` runs `VibeTests` (always Debug) and the cloud-runner oracle tests (`check-cloud-scenarios`). `make test-audio` runs `VibeAudioTests`, and `make test-ios` runs `VibeiOSTests` (both below). All three are defined in `project.yml`, so editing a source list means re-running `xcodegen generate`.

`iOSDriver/` is **not** a test suite. It is the `vibe-debug` skill's touch driver, a resident XCUITest (`VibeiOSDriver`) started by `drive-ios.sh`, and `VibeTests`' `Tests` source entry excludes it. `BenchComponents/` is the `vibe-perf` skill's benchmark tool, excluded the same way. Its `--waveform` mode is the `vibe-waveform` skill's probe.

**The directories mirror `Vibe/`.** A test lives in the directory of the code it tests: `Audio/` (with `FX/`, `Levels/`, `Metadata/`, and `Waveform/`), `Loading/` (with `Net/` and `iOS/Dropbox/`), `Playlist/`, `WaveformUI/`, `Common/`, `Util/`, `Controls/`, `NowPlaying/`, `Mac/`, and `iOS/`. A subsystem's platform half shares its directory. So `Audio/` holds the device tests, and `Playlist/` holds the drag rules. The FLAC conversion tests are in `Mac/`, beside the other mac shell tests. A test of a debug seam sits beside the tests of the class the seam opens (`AudioFileHandleReadAheadTests`). `Debug/` holds the tests of the debug fakes. **A piece's tests moved with it to vibe-libs and run there.** The file loader's tests, the fake cloud's included, are vibe-libs' `Tests/files/FileLoading`. The tempo and key analyzers' tests are its `Tests/audio/Analysis`. The Dropbox tests are in `Loading/iOS/Dropbox/`, beside the Dropbox code. `SmokeTests.m` stays at the root, because it tests the harness itself. **WaveformCore's tests live in its package** (`Packages/WaveformCore/Tests`), so `swift test` runs them there. `VibeTests` compiles the same files.

## Helpers

`Support/` holds the shared helpers. None of them runs a test.

- `AudioFixtures.h`: the fixture writers and the reference conversion (`VibeReferenceResample`). Both targets use it.
- `DrawnViewTestSupport.h`: renders a view or a layer tree into a 1x bitmap and reads a pixel by view coordinates. It also makes the deferred window that the view tests attach to and that `MainPlayerControllerTests` takes its undo manager from.
- `DropboxStubProtocol.h` and `.m`: the Dropbox tests' `NSURLProtocol`. One handler the test installs answers every request.
- `HTTPStub.h` and `.m`: a scripted HTTP host per instance, over the debug fake's serving engine. Both targets compile it.
- `LinkStoreTestCase.h` and `.m`: the base class of each link host's store tests.
- `MetadataLoaderTestFakes.h` and `.m`: the metadata loader tests' fakes, and the suite's `AudioTrackMetadata` decoy.
- `ShellTestFakes.h` and `.m`: the mac shell's duck-typed player and metadata scan, the window's occlusion answer, and the partial `MainMenuBuilder` decoy.
- `TestFilesystemGuard.h` and `.m`: the per-process temp root (`VibeTestProcessRoot`) and in-memory defaults, installed at image load. All three targets compile it. Its header also holds the one run-loop wait: `VibeSpinUntil` polls up to the hang guard, and `VibeSpinFor` spins a fixed window. Each harness calls the first `eventually:`.
- `FakeTrackMetadata.h` and `.m`: the duck-typed `AudioTrackMetadata` that `VibeTests` and `VibeiOSTests` share.
- `VibeReadAheadScript.h` and `.m`: forces the network-mount rule and scripts each read. Both targets compile it.
- `WaveformTestSupport.h`: waveforms built bin by bin, for the renderer and view tests. ObjC++ only.

## What belongs here

Deterministic host-less logic and machinery: code whose outcome its inputs or narrow injected I/O boundaries control. That covers math, archive encode and decode, formatting, precedence rules, cache keys, coordinator accounting, queue and retry orchestration, and local temp-file wrappers. The suite is **host-less** (no `TEST_HOST`). It needs no window server, audio hardware, permissions or Vibe instance, and it does not inherit the app's sandbox, so it can read fixtures from the repo.

Anything that needs the app running belongs in the `vibe-debug` skill's command channel: shell transport routing, menus, drag and drop, layout, on-screen compositing, Now Playing, device switching. A single view's drawing does not need it (below). Player transport and FX have the device-free audio suite below.

**Where rendering is the whole class, extract the arithmetic into a seam.** Decisions that need no rendering live in header-only `*Rules.h` and `*Math.h` files that the shipping class **calls** rather than restates: `FadeMath.h`, `AudioFXMath.h`, `TransportMath.h`, `NowPlayingRules.h`, `PlayerScreenRules.h`. `AudioVoiceBusTests` tests the voice bus host-less: the tests own the output buffers and call `VibeVoiceBusRender` with inline decoding, so every frame is compared against its file. `AudioVoiceBusPoolTests` covers starvation, kills and the voice pool. Their harness is `AudioVoiceBusTestCase`. `AudioFXChainTests` hosts the FX chain alone and calls `VibeFXChainRender` through the debug pump's frame-driven clock. Reach for these before deciding a class cannot be tested.

**The boundary is uncontrolled I/O.**

- `AudioWaveformLoaderTests` writes a WAV through `AudioFixtures.h` and reads it back through the real loader. It streams one into a part file behind a `CloudFileAvailability`, and runs the real `AudioWaveformCache` over a store in its temp directory (`initWithRootPath:`). `AudioWaveformObserverTests` drives the same cache with an observer of its own, which records what each sink saw and can hold a decode on its first block.
- The Dropbox tests drive the real `DropboxClient` and `DropboxMirror` over `DropboxStubProtocol` and a temp root. `DropboxMirrorTestCase` is their harness and runs no tests. `DropboxMirrorTests` covers listing, search, ranged reads and the account. `DropboxMirrorFetchTests` covers the fetch and resumed downloads. `DropboxMirrorStreamingTests` covers streaming, the tail window and the row's loading bar. Their seam is `DropboxClientInternal.h`: `adoptRefreshToken:accountID:`, plus `useSessionConfiguration:` and `retryDelayScale` from `HTTPTransferClientInternal.h`. `retryDelayScale` makes a scripted drop or 429 wait milliseconds instead of seconds. The debug channel's `VibeFakeDropbox` uses the same seam.
- `HTTPTransferClientTests`, `RemotePlaceholderStoreTests` and `LinkStoreTests` drive their classes over `HTTPStub` and a temp root. `HTTPStub` has its own host per instance. It scripts the answers of the debug fake's serving engine, `VibeFakeHTTPProtocol` (`Vibe/Debug/AGENTS.md`). So the Range rule and body delivery are the debug channel's own. `LinkStoreTestCase` is a harness that runs no tests. Each link host's store tests subclass it in that host's rules file (`DropboxLinkStoreTests`, `GoogleDriveLinkStoreTests`, `ICloudLinkStoreTests`). `answerHost:` lets one stub answer a public name, so a test sees that nothing was sent there. `VibeFakeHTTPTests` drives the debug fake through the plain client and through `LinkStore`.
- The link decisions need no network: `HTTPTransferRulesTests`, `LinkRulesTests`, `LinkDropRulesTests`, and each host's `*LinkRulesTests`. `FileSearchRulesTests` covers the iOS search's `FileSearchRules.h` and `FolderSessionRules.h` from this macOS suite. `BrowserRulesTests` covers the Files tab's `BrowserRules.h`. `PlayerScreenRulesTests` covers `PlayerScreenRules.h`. `VibeWidgetStateTests` covers the widget's publish decision in `VibeWidgetState.h`.
- `DropboxSearchTests` drives the search screen's Dropbox section over the same harness, with the mirror passed in (`initWithMirror:`).

**A network mount is forced, never found.** `AudioFileHandleReadAheadTests` reads ahead on files in its own temp directory. It shares `AudioFileHandleStreamingTestCase` with `AudioFileHandleStreamingTests`. `AudioFileHandle+Debug.h` forces the mount rule for those URLs, and its before-read hook scripts each `pread`. `VibeReadAheadScript` (`VibeReadAheadScript.h`) installs both and is the script's shape. It counts reads by file and offset. It can throttle them, stall them from an offset until released, fail them with an errno once or always, or read nothing once at an offset, as a reconnecting share can. A stall can hold one file's reads only, and can let them through one at a time. A failure can be held after it is signalled until the test releases it. A stalled read holds its thread as a dead mount's syscall does. Both test targets compile it. **The read-ahead counts are process-wide**, and a stalled thread outlives its handle as an orphan. A class that parks threads releases them in `tearDown` (`releaseEverything`) and waits for `threadsGone` before the next test counts. vibe-libs' `NetworkReadAheadRulesTests` feeds `VibeMountReadsAhead` a fake `statfs` table and never reads the machine's.

**Test an orchestrator as itself when its nondeterminism has narrow boundaries.** The metadata loader tests run the production queues, barrier, ranking, materialization slots, real coordinator, parse claims, installation, publication and cancellation. They replace only cache reads, file parsing and the coordinator's provider-operation boundary. Their harness is `AudioTrackMetadataLoaderTestCase`, and each topic is a subclass: `AudioTrackMetadataLoaderTests` (stage one, the cache and priority), `…SharedFileTests` (rows that share one file) and `…RetryTests` (retries, the foreground yield, admission, cancellation, and a parse of another version). Do not copy the loader's state machine into a fake or flatten it into rule tests. Other examples of the same approach:

- `AudioFileMaterializationCoordinator`: a gated dataless probe, hand-completed provider operations, and a clock the test sets. Its tests are vibe-libs' (`files/FileLoading/AGENTS.md`). `AudioFileHandleOpenTests` stays here: it checks that the coordinator delivers Vibe's real handle, through the player's opener.
- `NowPlayingController` (`NowPlayingRulesTests`): an injected clock and OS sinks, with the real dirty checks and artwork construction.
- `AudioFileConverter`: held file-operation callbacks and the real `NSUndoManager` for undo and redo. Its dormant TagLib functions are fail-loud decoys in `FLACDisposalRulesTests`. Its injected constructor skips the launch-time temp sweep.
- `ArtworkDisplayController` (`AudioTrackTests`): the real single-render, latest-request scheduler with held renderer completions and a publication sink that keeps views and the Dock out.
- `OpenBurstCoalescerTests` runs launch priority through the production launch method. `PlaylistFileSessionTests` round-trips the private session with temp files and isolated defaults.
- `AudioDeviceManager`: injected enumeration and retry scheduling, with no HAL registration. Its tests are vibe-libs' (`audio/OutputDevices/AGENTS.md`), with the device and session rules' tests. `AudioOutputUnitTests` stays here, since the output unit is the player's.
- `MainPlayerControllerTests` builds the mac shell through its injected constructor, with a duck-typed player and metadata scan, a held deferral timer and the real `PlaylistController`. The removal funnel, every successor re-park, the deferred metadata sweep, the reorder follow-up and the equalizer demand count run as shipped.
- `PlaylistControllerTests` makes the data source calls AppKit makes for a drag, over a windowless `PlaylistTableView`. It covers the reorder proof and the dragged rows' identity resolution.
- `FolderSessionTests` runs the iOS `FolderSession` whole: the prologue, both work queues, the walk, real bookmarks and the landing, over folders in a temp root. A landing reaches main only when the test spins it, so two requests made in one turn race as two taps do. A negative check drains the session's two queues and then runs one turn of main, so it needs no fixed window.
- `LocationStoreTests`, `FavoritesStoreTests` and `RecentsStoreTests` round-trip each iOS store through the process's in-memory defaults. A store of its own (`initPrivate`) reads what a relaunch reads.
- Their harness is `IOSShellTestCase`, which `FileSearchRulesTests` also uses. The shell reaches `DropboxMirror.shared`, so in this process it answers a store under the per-pid root, with no account and no network. The guard does the same for `LinkStore.shared` in every class. The stores' own singletons are emptied before each test. `VibeWidgetStateTests` covers the snapshot's playhead arithmetic and its publish decision, but never its app group container, which on the mac is a real directory under `~/Library`.

`PlaybackController` is in neither target. Its header imports UIKit, and it owns an `AVAudioSession` controller and the iOS recovery category, which the mac cannot compile. Its decisions are tested as rules instead (`PlayerScreenRules.h`, `FolderSessionRules.h`).
- `EqualizerIndicatorViewTests` runs the playing-row marker in a deferred window with a recording `EqualizerLevelSource`. Every gate, a source swap, a reentrant restart and deallocation must leave one balanced consumer per running poller. `LoadingIndicatorTests` covers the loading control's layers, pulse, sweep and palette, and its row view.
- **A drawn view renders into a bitmap with no window server** (`DrawnViewTestSupport.h`). The tests assert facts about the pixels. They never compare against a stored image, which breaks on every OS change. `WaveformViewTests` checks the played side, the playhead line and the theme's colors through the real view. `PitchFaderViewTests`, `VolumeControlViewTests`, and `ArtworkImageViewTests` cover the mac controls that stay here. The drawn-control, symbol-button, and link-label tests moved with their controls to vibe-libs' `ui/Controls`. The settings window's own tests are in vibe-libs' `ui/SettingsWindow`. The shortcut encoding's, the keyboard layout's, and the Keyboard Shortcuts pane's are in vibe-libs' `ui/Shortcuts`. `MenuShortcutRulesTests` stays here, over Vibe's command table. vibe-libs keeps one copy of `DrawnViewTestSupport.h` for both, in its own `Tests/Support`. A dragging session and a key window need a window server, so they stay with `vibe-debug`. NSApp is nil here, so a sent action is not asserted.

OS provider state, shell routing, remote-command registration, output rebinding, device property I/O and hardware settlement remain live tests.

**The suite links an incomplete `AudioTrackMetadata` decoy** (`Support/MetadataLoaderTestFakes.m`), because the real one is ObjC++ and TagLib. The real parse is tested in `VibeAudioTests` (below). Its parser constructor raises. Loader fixtures use the copy-capable duck fake, and a newly required selector is added deliberately. `ShellTestFakes.m` holds the shell's one decoy. `MainMenuBuilder` answers only the row menu's items. The suite compiles `MainPlayerController.m`, `+Playlist`, `+Transport`, `+Settings` and `+NowPlaying`. It leaves out `+Construction`, the app's construction road, so the suite needs no decoy for the classes that road builds. A tested path that reaches another category fails loudly, except `+Window`'s `isWindowVisible`, which the fakes answer.

## Rendered audio

`make test-audio` generates deterministic fixtures under `build/audio-fixtures`, self-tests the PCM comparator (`build/verify-bit-perfect`, compiled from `scripts/test/verify-bit-perfect.swift`), then runs **VibeAudioTests**. It is host-less and compiles the production player, FX, decoder and loading machinery into its own derived data (`build/AudioDerivedData`), so `make -j3 test test-audio` runs both suites at once. Under `make -j`, `audio-test-bundle` builds the bundle and `audio-fixtures` makes the fixtures at the same time. The tests then run without a rebuild. It reuses `TestFilesystemGuard.m`. `make test-audio-summary` reads `build/AudioTestResults.xcresult`. CI caches the fixtures and the comparator under a key made from both scripts and the runner image. A change to either script makes new ones.

The suite lives in `AudioRender/`. `AudioPlayerRenderTests` is a base class with no tests, in `AudioPlayerRenderTestCase.h` and `.m`. Each topic is a subclass in its own file of the same name: `AudioPlayerRenderFidelityTests`, `…EdgesTests`, `…StreamTests`, `…ReadAheadTests`, `…EstimatedTests`, `…SignalTests`, `…PipelineTests`, `…DeviceTests`, `…OutputTests`, `…PitchTests` and `…LinkTests`. The parallel runner spreads the subclasses across processes. The slowest subclass sets the suite's wall time. A new test joins its topic's subclass. A subclass that outgrows the others is the one to split. `ARGS=-only-testing:VibeAudioTests/AudioPlayerRenderEdgesTests/testGaplessSplitSignalAcrossRenderBlocks` narrows a run.

**The tag parse is tested here too, since this target compiles TagLib.** The two classes are in `Audio/Metadata/`, and `VibeTests` excludes them by name. They write their files with `AudioTrackMetadataTagFixtures.h`: audio from `AudioFixtures.h` or an Apple encoder, then tags from TagLib's own writers. Ogg starts from the generated fixtures, so its cases skip without ffmpeg.

- `AudioTrackMetadataTagTests` runs `metadataWithURL:displayArtData:` and the art read over each format: ID3v2.3, ID3v2.4, ID3v1 and APE on MP3, M4A, FLAC with a picture and with a CUESHEET block, Vorbis, Opus, WAV with ID3 or RIFF INFO, AIFF, CAF and W64. It checks tags, tempo and key against analysis, and codec facts. It checks art that will not decode, art whose header claims a huge image, and `TagLibAudioFile`'s detection. It reads a remote placeholder's tags and art through its backend's read. The class writes each tagged file once and copies it into each test's directory, so a test may change its copy.
- `AudioTrackMetadataFuzzTests` mutates those files with a fixed seed: truncations, flipped bytes, forged sizes, duplicated bytes and a FLAC picture longer than its file. Each mutant must parse or fail within a bound and throw nothing. The original must parse the same after a fixture's mutants. `TEST_RUNNER_VIBE_FUZZ_ROUNDS` raises the rounds, and `TEST_RUNNER_VIBE_FUZZ_SEED` changes the seed. Run a raised count under `-enableAddressSanitizer YES -enableUndefinedBehaviorSanitizer YES` after a change to the parse.

`AudioFileHandleFuzzTests.m` renders nothing, and it lives here because the suite's fixtures and decoders do. It feeds seeded mutants of every fixture through `AudioFileHandle`. `AudioFileHandleFuzzTestCase` is its base class with no tests. Each decoder family is a subclass: `AudioFileHandleFuzzDrWAVTests`, `…DrFLACTests`, `…MPEGTests` and `…CoreAudioTests`. One source's mutants decode across the cores. The budgets at the top of the file keep each class under 30 seconds at the default count. `TEST_RUNNER_VIBE_FUZZ_ITERATIONS` multiplies the count. `TEST_RUNNER_VIBE_FUZZ_SEED` re-runs one base seed. `TEST_RUNNER_VIBE_FUZZ_EXPORT` names a folder, and every mutant is also written there. Another build can then decode the same files (the `vibe-audio-quality` skill).

`AudioQualityCorpusTests.m` runs a downloaded public corpus through the handle. Only the `vibe-audio-quality` skill names one. Otherwise it skips, and that skip is on the allowed list.

`AudioFixtures.h` is the one home of fixture writers and of the reference conversion (`VibeReferenceResample`), shared by both targets. Raw WAV fixtures use independent RIFF bytes. `VibeWriteFixture` uses `AudioFileHandle` for other containers and channel layouts. Those fixtures need an independent PCM reference. The base class is the one home of capture, comparisons and delegate traces. The test constructor attaches `VibeManualRenderPump` in place of the output unit before any voice exists and skips HAL observation. The pump supplies a frame-driven clock or the app's real timer, and voice ramps, FX sweeps and idle stop run their production algorithms on it. Before every frame-driven slice the pump decodes the bus inline, and after every slice it drains it, so a voice is live before the first slice that could render it. File opens and delegate delivery keep their real queues, and bounded event waits settle them between render blocks. No mock renderer, copied transport or UI host is involved.

**The oracle compares every source frame in every channel** after one alignment. With Declick on, only its first 50 ms of startup is excluded. Lossless WAV references come from the fixture bytes, FLAC, ALAC and AIFF references are the original PCM, and lossy formats compare to their decoded PCM. AAC allows four float epsilons (below −126 dBFS), since independent Apple decodes may round differently; every other codec is exact. Captures must hold complete frames and no audio after the reference ends. The corruption tests reject dropped or duplicated frames, channel swaps, polarity or gain changes, clipping, silence, NaNs, single-LSB changes, truncation and short matching excerpts.

**Bit-perfect and FX-free playback require exact float samples, and so does a dormant FX chain** with the meter installed (`testEveryReleasedEffectRestsAndReplaysTheFileExactly`). **Never loosen that to a tolerance.** A filter left active at its flat setting can still change samples through rounding. Only an exact comparison catches every such change. A float32 reference cannot show what float32 dropped, so wider sources are also compared at full width (`VibeCompareWidePCM`). SRC asserts gain within 0.01 dB, duration and an alias ceiling of −90 dBFS. Active FX assert their frequency response, echo timing, decay and finite output.

**Coverage spans** transport (start paused, stop and replay, idle shutdown, seeks, mode and format changes, interrupted fades, skip storms, a starved decoder), the varispeed, output rate changes, the idle stop and `outputIdle`, the meter's reinstall, stuck renders and stalled reads, a failed or late output unit, gapless splits at awkward boundaries, and conversions against `VibeReferenceResample`. Each test names its case. Two techniques recur:

- **A file still downloading** is a remote placeholder whose fetch the test writes (`streamingCopyOf:`, `…StreamTests`). **A file on a network mount** is a forced, scripted read-ahead (`networkCopyOf:`, `…ReadAheadTests`). Both play on the decode pool, since the inline fill would block on a waiting read. **A link** plays through the real `LinkStore` over `HTTPStub` (`…LinkTests`).
- **Threading changes run under ThreadSanitizer.** Run `AudioVoiceBusTests`, `AudioVoiceBusPoolTests` and the whole render suite with `-enableThreadSanitizer YES -enableCodeCoverage NO` and a separate derived-data path. A test's own cross-thread flag must be atomic, or it reads as a race there. **TRAP: so must a swizzle's saved original IMP when the swizzled method can run while the swizzle installs.** Store it from `method_getImplementation` before `method_setImplementation`, never from that call's return (`…EdgesTests`, `…OutputTests`).

A failed PCM comparison attaches the reference, the capture, aligned difference WAVs and the event and pipeline state to the result bundle. Metric assertions include their measured values.

The fixture generator (`scripts/test/generate-test-audio.sh`) owns the source corpus in its `--render-tests` mode. Tests only create temporary slices and malformed inputs. Stock macOS encoders cover the core formats, CAF and W64 included. MP3, MP2, QTA and Ogg need ffmpeg and are skipped without it. The 5.1 Vorbis file also needs oggenc (`brew install vorbis-tools`). CI installs both. No unit test reads the gitignored `Assets/test_audio_files` corpus. A unit test writes its own fixtures through `AudioFixtures.h` into the per-process temp root. The render suite instead requires its generated core fixtures. The ISO/IEC 11172-4 Layer III compliance stream and its reference decode are ISO's, so the generator fetches them from FFmpeg's FATE mirror and checks pinned hashes. When that fails, `testDrMP3PassesTheISOComplianceStreamAtFullAccuracy` skips.

**A skip is gated.** `make test-summary`, `make test-audio-summary` and `make test-ios-summary` fail on any skipped test that `scripts/checks/skip-allowlist` does not name. A new deliberate skip is named there in the same change.

The pump proves the software path, **not** DAC samples, hardware negotiation, exclusivity or iOS session recovery. `make test-audio-loopback` and `make test-audio-device` run the same verifier against a real device for those macOS boundaries. Each needs a Debug app running first (`vibe-debug`). Hardware is never a CI prerequisite.

## The iOS shell on a simulator

`make test-ios` runs **VibeiOSTests** on an iOS simulator. `IOS_TEST_DEVICE` names it, and the default is `iPhone 17`. CI runs it nightly and on manual runs, and reads `make test-ios-summary` after it. A simulator's first boot and the tests' launch cost a runner four to eight minutes. Pull requests and pushes skip it. Run it yourself when a change touches the iOS shell. The suite lives in `iOSSim/`, which `VibeTests` excludes. It is one directory, like `AudioRender/`, because it is one target's suite. Its classes are named for the code they test.

**It is hosted, unlike the other two.** `TEST_HOST` is the Debug `VibeiOS` app. The card, the root, and the settings screens reach `PlaybackController`, and through it the whole engine. Compiling them in would repeat the app's source list. So the bundle links against the app (`BUNDLE_LOADER`) and compiles only its tests and `TestFilesystemGuard.m`. The guard is in before the app registers its defaults, so the host's settings are the in-memory store too. `HostSmokeTests` checks that the registered defaults landed there. The cost is the app's launch, a few seconds per run. The host's own scene and its one `AudioPlayer` stay up underneath and are never driven. The debug channel is not used.

**No second player.** `FakePlayback` (`IOSSimTestCase.h`) is a duck-typed `PlaybackController`. The screens read its properties. A test sets `screenState` and sends a `PlaybackObserver` event (`notify:`). Any other selector `PlaybackController` declares is recorded in `calls` and answers zero. Tracks carry the duck-typed `FakeTrackMetadata` from `Support/`, which `VibeTests` uses too. `IOSSimTestCase` gives each test a window of its own on the host's scene. It puts back every setting a test wrote.

**What belongs here is what needs UIKit**: view and controller lifecycles, cells, layers, trait changes, gestures driven through their handlers, and table data sources. Assert state, not pixels. The scrubber's bitmaps are read back from the layer tree and checked for coverage and tint, never compared. A decision that needs no view belongs in a `*Rules.h` seam and `VibeTests`. Taps, drags, and layout on a running app belong to the touch driver (`vibe-debug`).

## Rules that are easy to get wrong

**The suite must leave no trace on the developer's machine.** `TestFilesystemGuard.m` isolates the theme artwork path and standard defaults. Host-less means unsandboxed, so every standard user directory a production path resolves is the developer's real one. `AppTheme`'s artwork store would land in `~/Library/Application Support/<main bundle identifier>/ThemeArt`, where the main bundle is the XCTest tool. Standard defaults would be the XCTest tool's domain, shared with every other test process on the machine. The guard runs at **image load**, before XCTest builds a case. It makes a per-pid temp root, points `VIBE_THEME_ART_DIR` inside it, and makes `+[NSUserDefaults standardUserDefaults]` answer an in-memory store of the process's own. In the two host-less targets it also makes `LinkStore.shared` a store under that root, since the real one resolves the XCTest tool's Application Support. It removes the root at exit. A crashed or killed process never reaches exit, so each process first removes the roots of dead pids, and its own pid's root, which a reused pid may have left. A test wanting a fresh store allocates `VibeTestUserDefaults` (`TestFilesystemGuard.h`). **TRAP: keep tested defaults in memory.** cfprefsd caching can make immediate read-after-write assertions depend on another process. It is not a `setUp`, because a guarantee each class opts into is one a new class silently opts out of.

**That per-process isolation is what lets both suites run in parallel** (the schemes' `parallelizable`). Classes spread across runner processes, and one process's `AppSettings` writes must not reach another's reads. A new cross-process resource (a fixed temp name, a named defaults suite, a real `~/Library` path) breaks that. Use UUID or per-pid names only. **TRAP: the in-memory store keeps what XCTest registered before the bundle loaded.** XCTest's IDE connection timeout is there. Without it a parallel worker can exit before its first test.

**TRAP: a test narrowing the artwork path must restore the previous value, never `unsetenv` it** (`AppThemeTestCase`). Unset hands every later test the real `~/Library`, and the leak surfaces under whichever class runs next. **Saving and restoring a setting around a test does not return it to unset.** Reading an unset key answers the registered default, so writing it back stores a key that was never there.

**A bounded wait is a hang guard, a gate or a negative check, and only the last is short.**

- A wait for something that must happen (an expectation, an asserted semaphore, a poll's deadline) uses `VIBE_TEST_HANG_TIMEOUT` from `project.yml`, never a literal. Under parallel classes and `make -j3`, utility-QoS work goes unscheduled for seconds.
- A gate the test releases itself (a fake blocked on a semaphore, or a pending grace the test settles, as in vibe-libs' `AudioWorkSchedulerTests`) uses `VIBE_TEST_GATE_TIMEOUT`, which outlasts the guards the test waits on while holding it.
- Replace unrelated production timers at their boundary. Extend an exposed duration past the guard when the test only needs the timer out of the way (`restoreDeadline`, `streamedTagWait`, `AudioLoadingConfiguration`). Inject a `VibeScheduler` when the test controls delivery order (`OpenBurstCoalescer`, `OpenRequestCoordinator`, metadata retries). A test of the timer itself keeps the shipping value.
- A negative check (an inverted expectation, a fixed window before asserting nothing arrived) stays short, since every pass runs its full length. The window is `kVibeTestNegativeWindow`. Where the test can drain the queues that would deliver, it drains them instead.
- A fixed window before asserting something did arrive is the flaky shape. Poll up to the guard instead.
- An elapsed-time assertion never reads the test thread's clock, which is late by however long that thread was descheduled. Measure between stamps taken where the code under test runs, on the clock its timer uses (`testProductionGatedTimerReopensADatalessScanAfterForegroundRelease`).

**A fixture's size on disk says nothing about its length.** The generator writes files whose declared content dwarfs their bytes, so a seek past a 32-bit frame count can be tested. `flac-long.flac` is under a megabyte and 4.3 billion frames. Anything that decodes a fixture to its end, or times a pass over one, reads the header's frame count first. A full decode of such a file runs for hours.

**Never put test files under `Vibe/`.** Both app targets recurse whole shared subsystem directories, so a test file there is compiled into both shipping apps. `Tests/` is named by no app target.

**Sources under test are compiled into the test target, not linked from the app.** A test for a new file adds that file to a source list in `project.yml`. A file both test targets compile goes in the `hostless-test-sources` template. A file only one target compiles goes in that target's own list. Keep the lists curated. TagLib and the real `AudioTrackMetadata` are compiled only into `VibeAudioTests`. Keep them out of `VibeTests` and the template.

**Where a test needs an `AudioTrackMetadata`, use a duck-typed fake cast to the property type.** `FakeTrackMetadata` (`Support/`) is that fake, installed through the row's `installMetadataIfUnresolved:`. `AudioTrack` only sends messages to its metadata and never names the class.

**Share a private method under test through an `*Internal.h` the implementation imports too** (`FolderWalkInternal.h`), never by re-declaring selectors in the test. A rename then breaks the build instead of the run.

**A temp-directory fixture has two spellings, and both turn up.** `NSTemporaryDirectory()` returns `/var/folders/…`, and `/var` is a symlink to `/private/var`. A directory walk answers in the resolved form, while standardizing a path drops the `/private` prefix again. `URLByResolvingSymlinksInPath` leaves the temp directory's prefix as it found it. Use `realpath(3)` on the fixture root at setup, and be ready to strip either spelling when comparing (`Playlist/FolderWalkTests.m`).
