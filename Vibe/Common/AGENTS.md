# Common

**What every other directory is written in terms of, and nothing else. If you can name the feature it belongs to, it belongs there instead.** The featureless helpers are `Vibe/Util/`. **Nothing in `Common/` may import from a feature directory.** The one class importing from `Util/` is `Mac/Theme/AppTheme`, for two featureless categories (`NSData.sha1Hex`, `NSAppearance.isDark`). It lives under `Common/Mac/` because it is macOS-only. `Mac/AGENTS.md` owns the theme store, and `Mac/Theme/AGENTS.md` the record.

## The settings store

`AppSettings` is every persisted preference, as properties over `NSUserDefaults`. `AppStats` is every persisted counter. **Every reader imports `AppSettings.h` explicitly and uses `sharedInstance`**, so a file's import list exposes the dependency. That is why `Vibe-Prefix.pch` carries only macros (logging, the realtime-effects brackets, the debug-only signposts, `VibeNotLocalized`) and `HelperMacros.h`, and no feature API. A feature API there would recompile the world and hide a dependency from the file that has it.

The macOS half is two categories. `(Mac)` in `Mac/AppSettings+Mac` is every mac-only preference. `(Themes)` in `Mac/Theme/AppSettings+Themes` is the theme store. A mac reader imports `AppSettings+Mac.h` explicitly beside `AppSettings.h`, and that header brings the theme store's. `AppSettingsInternal.h` is the seam between the halves (`Mac/AGENTS.md`). The value ladders a stored setting is snapped to on read are `SettingsRules.h`, so a rule about a setting is testable without a defaults store.

**The store never applies effects.** A writer that needs an immediate follow-up requests a named `VibeSettingsLiveEffect` from `MainPlayerController+Settings`. That is a central, synchronous mapping. It calls the behavior owned by the affected object, and never writes a setting or posts a notification. The Settings window is `Vibe/Mac/Settings/`. iOS keeps the rule with two spellings (`iOS/Settings/AGENTS.md`). A display setting's writer posts `VibeNotifyDisplaySettingsChanged()` for the card. A track-transition setting's writer calls `PlaybackController.applyTrackTransitionSettings`.

The one in-memory value is `windowAppearancePreviewStyle`. The Settings window's light/dark preview toggle holds it while its pane is open (`Mac/Settings/Themes/AGENTS.md`). `windowAppearance` answers it, and `setWindowAppearanceStyle:` clears it. It lives here because that accessor already holds the style-to-appearance ladder, so every consumer gets the preview.

## The platform split

**Adding a property means choosing a side.** The header it sits in answers "does the iOS app honor this?". Most settings configure something only macOS has, so they go in `Mac/AppSettings+Mac`. `AppSettings.h` holds only what iOS needs too.

- **The iOS-only keys** sit in its `#if !TARGET_OS_OSX` block. They are the waveform's loose keys: `waveformStyle`, `waveformTheme` with its custom played and unplayed colors, `waveformBandTheme` with its custom bands, `waveformPlayheadLine` and `waveformCentered`. **Each is stored twice, once for the card and once for the widget**, and every accessor but the style's takes `widget:`. The widget's key is the card's with `Settings.waveform` spelled `Settings.widgetWaveform` (`WaveformKey`). The widget's copy counts only while `widgetWaveformStyle` is non-nil. Under Match app, a nil style stored as an empty string, a widget read answers the card's, and a widget write still lands in the widget's copy. `VibeDisplaySettingsDidChangeNotification` sits in the block too. `waveformPlayheadLine` is nil until chosen and deliberately unregistered, since its default is the style's (`WaveformUI/AGENTS.md`). On macOS `currentTheme`'s fields are the store of record, so these keys are compiled out there. A mac caller fails to build instead of reading the registered default forever.
- **The player display switches** `showRemainingTime`, `showFileInfo` and `showShuffleRepeat` are shared properties over keys that differ by platform. Each reads the key its platform shipped (the `#if TARGET_OS_OSX` pair in `AppSettingsInternal.h`). Only iOS reads `showShuffleRepeat`.
- **The genuinely shared settings** are the ones both shells enforce: `folderOpenSort`, `pauseAtTrackEnd`, `crossfadeMilliseconds`, `repeatMode`, `shuffleEnabled`, `audioFXEnabled` and `analyzeBPM` (root `AGENTS.md`). The crossfade slider's range and step sit beside its getter. `effectiveCrossfadeMilliseconds`, which bit-perfect output holds down, is the mac's. Normalize and Gain are the mac's too. They are plain settings rather than `AppTheme` fields because they match a library's mastering level, not a look. The iOS scrubber draws the normalized mapping with no knob.
- **`sharedInstance`** is shared. The other store-wide entry points are the mac's: `applicationDidFinishLaunching`, `allSettingsAtDefaults`, `resetToDefaults` and `factoryReset`. iOS has no reset and nothing to do at launch. Stored custom themes are content. A normal reset keeps them. `factoryReset` removes them, and also clears `welcomeTrackLoaded`, the shared first-launch state no other reset touches.

**`AppStats` has the same shape.** Both shells feed it and both About screens read it. Its `#if TARGET_OS_OSX` blocks keep a running listening clock true while the process goes quiet. The mac brackets the clock around system sleep, since `systemUptime` is not frozen by sleep on Apple Silicon. Without that, a night asleep would count as listening. iOS needs no bracket, since nothing silences a running audio session without pausing the player. It folds and restarts the clock at every background and terminate notification instead, since a backgrounded app is killed with no warning. Main thread only.

## There is no settings cache

Reads go straight to `NSUserDefaults`. Each is one CFPreferences lookup, cheap enough even for `uiUpdateHzCap` on every live-resize frame. The exceptions are the mac theme store's (`Mac/AGENTS.md`). `storedUserThemes` is memoized, and `currentTheme` materializes once. Each is refreshed by its own writer, and no CLI-side verb writes those keys.

**TRAP: `NSUserDefaultsDidChangeNotification` does not fire for a write from another process.** A plain `defaults write` is one, and so are the debug channel's CLI-side verbs (`set_analysis`). A cache invalidated on the notification reports the old value for good. A cache over a stored key must invalidate some other way. `FolderArtResolver` caches `useFolderArt` on the cell-draw path, so a write that skips `VibeSettingsLiveEffectFolderArt` is never observed (`Audio/Metadata/Artwork/FolderArt/AGENTS.md`).

**TRAP: a stored key never follows a rename of its macro.** Changing the string resets every user's setting. `SETTING_FOLDER_ART` keeps `@"Audio.folderArtwork"`. The mac keys are listed at the top of `Mac/AppSettings+Mac.m` and `Mac/Theme/AppSettings+Themes.m`. The shared keys, and the mac keys both of those files read, are in `AppSettingsInternal.h`.

## Single homes

- **`VibeStrings.h`**: every user-facing string, declared here and nowhere else. Call sites use `STR_*` (root `AGENTS.md`, the `vibe-strings` skill, `make strings` after). **TRAP: the file must be named `VibeStrings.h`, not `Strings.h`.** On a case-insensitive filesystem `Strings.h` shadows `<strings.h>` in explicit-modules dependency scanning. Its Foundation import then closes a Foundation → CoreServices → Foundation cycle that fails every module build. **TRAP: its Foundation import sits under `#ifndef VIBE_STRINGS_EXTRACTION`**, because `extract-strings.sh` runs it through `clang -E` and needs `NSLocalizedStringWithDefaultValue` unexpanded.
- **`PlayableExtensions`**: every audio extension the app plays. `ordered` is for the playlist resolver's fallback walk. It lists lossless before lossy, and the order decides which replacement a folder holding several yields. `lookup` is the open funnel's membership test. It is stateless and Foundation-only, so it sits below both readers. `FolderWalk` imports `PlaylistFile`, so `PlaylistFile` cannot import `FolderWalk` back. **It must cover every spelling `CFBundleDocumentTypes` admits, conformance included.** A claimed type takes in every type conforming to it: `public.mpeg-4-audio` brings the `m4r` ringtone, and `public.aac-audio` brings `adts`. A missing spelling means Finder offers Vibe a file the filter then silently discards.
- **`DocumentTypes`**: the `CFBundleDocumentTypes` declarations read back as `UTType`s. `declaredTypes` includes the folder, and `declaredFileTypes` is the files alone. `defaultHandlerTypes` is only the Default-rank ones the app asks to be the default for: the audio, CUE and M3U. The ⌘O filter and what the app is registered for therefore cannot drift. The Launch Services side is `DefaultAppRegistration` (`Mac/Settings/`), which keeps this class AppKit-free.
- **`VibeProductURLs`**: the three web addresses, spelled once. An address is an identifier and is never localized. What a row is called is a `settings.about.*` string.

## Platform aliases and the two free-function headers

`PlatformTypes.h` defines `VibeImage` and `VibeColor` (`NSImage`/`NSColor` on macOS, `UIImage`/`UIColor` elsewhere). A model header can then carry an image without importing AppKit or UIKit. **Do not add aliases for their own sake.**

`PlatformImage.h` and `PlatformColor.h` are the two homes of free functions over a foreign class (root `AGENTS.md`, Vocabulary). The class involved differs per target, so there is no single one to hang a category on.
- `VibeDecodedImageWithData(data, maxPixelSize)` is the bounded ImageIO decode that never materializes the full-size bitmap. It takes 10–100ms, so it belongs off the main thread.
- `VibeDominantColorOfImage` is the weighted hue histogram behind the mac window tint and the `album_art` waveform theme. It samples a fixed 32×32 downsample, so its cost does not depend on image size. **It works in CoreGraphics terms rather than either platform's bitmap type.** `NSBitmapImageRep` and `UIImage`'s backing store agree on nothing. A `CGBitmapContext` we create has a layout the pixel loop can rely on, so one implementation serves both. `NSImage (Util)`'s `dominantColor` and `UIImage+DominantColor` forward to it.
- `PlatformColor.h` carries the `#RRGGBB[AA]` persisted form of a stored color (opaque stays six digits) and the linear blend. It has `extern "C"` guards because the `.mm` renderers include it.
