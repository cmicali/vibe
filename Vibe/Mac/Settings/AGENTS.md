# Settings window (macOS)

Vibe > Settings… (⌘,) is `SettingsWindowController`: an `NSSplitViewController` whose source-list sidebar (`SettingsSidebarController`) drives a tab-less `NSTabViewController` of panes, in the System Settings shape. The store is `AppSettings` (`Vibe/Common/`), and this directory is only the window. `DefaultAppRegistration` lives here as the Launch Services half of `Common/DocumentTypes`. The Themes pane (the theme list and editor) is `Themes/`, with its own `AGENTS.md`.

**A write that must change the running app has one path**: store the value, then request the exact `VibeSettingsLiveEffect` from `MainPlayerController+Settings`. The mapping runs synchronously on main and applies stored state. An effect can close the pitch panel and save its geometry. A setting read at the next gesture requests nothing. The pane notes below name the effect each row must request. **A missing request silently breaks the setting.**

## Window and chrome

- **The split controller must stay the window's `contentViewController`.** The sidebar's tracking separator resolves through it. Hosting its view bare brings back macOS 26's titlebar scroll pocket as a window-wide band. The split items' `titlebarSeparatorStyle = None` governs that band. A `contentViewController` assigned after init does not bind the title, so `SettingsSplitViewController.setTitle:` pushes it.
- **The window title is the title-propagation chain, never set directly.** Each pane's `title` names its sidebar row and the window. `didSelectTabViewItem:` pushes it onto the split controller. The first pane's title is seeded at init, because the initial selection comes before the split controller.
- **The toolbar is icon-only** (`displayMode`). With labels allowed, a unified toolbar reserves a label row whether or not one is drawn. Labels stay set for accessibility.
- **Sidebar rows are built from the tab items**, so order, labels and symbols cannot drift. Selection syncs both ways through `didSelectTabViewItem:`, which owns only the selection, the sidebar and the title. Groups are spacer rows before the panes `SidebarGroupStarts` names. The sidebar keeps its own row list (`reloadRows`), so a row index is never a tab index. The order is General, Themes, Appearance | Playback, Audio Output, Files | Keyboard Shortcuts | Advanced, About.
- Each tab item has a **stable, unlocalized identifier** (`general`, `themes`, `appearance`, `playback`, `audio`, `files`, `shortcuts`, `advanced`, `about`), which `settings_open` selects by. Sidebar labels reuse menu strings where the word is the same. The rest are `settings.*` keys.
- **Rows are `SettingsAccentRowView`s, whose `isEmphasized` override answers YES**, so the accent stays while the window is unfocused. Setting `emphasized` in `rowViewForRow:` is overwritten on every key-window change. **TRAP: never `reloadData` inside the sidebar's selection callback.** It resets the selection to row zero and reenters. The icon re-tint rides `SettingsSidebarCellView.setBackgroundStyle:` instead.
- **Search** is the sidebar's field. Typing narrows the rows to the panes whose `matchesSearch:` answers: the pane's title, or a row's title, caption or section header, ignoring case and diacritics. Every pane marks its matching rows (`setSearchHighlight:`). A pane walks its view tree for rows once, since rows never change after `loadView`, only their visibility. It answers each query once for the filter, the marks and the reveal. A pane off screen keeps the query and marks its rows when it appears. A pane on screen reveals its first hit, scrolling only when that hit changes. The Themes pane opens its editor for a hit only the editor holds. **TRAP: the reload and reselection post selection changes**, which are ignored under `_reloadingRows`. Treated as the user's, one would switch panes under the search being typed. A pane whose sections hide for a reason other than a page swap excludes their rows (`isRowSearchable:`).
- **Back and Forward are System Settings' history** (`updateNavigation`). Every pane switch or editor page swap pushes the location it left, a pane identifier or `themes/editor`, and clears Forward. The pill walks the history under `_restoringLocation`. That flag also keeps the switch's own refreshes from recording a half-applied state. `goToLocation:` sets the page before selecting the pane. **A pane picked in the sidebar opens at its top** (`paneWillBecomeSelected:`). Themes opens at its list, so only Back and Forward reopen the editor where it was left.
- `AppDelegate` creates the window lazily and keeps it alive. File > Close is nil-targeted, so this controller's `closeFile:` catches ⌘W ahead of the player's.
- Pane switches are immediate (`transitionOptions` is `None`). The default crossfade composites two section headers and reads as a flash.

## Pane scaffolding

Panes subclass `SettingsPaneViewController` and build on shared scaffolding. Each pane is its own class, named after the pane.

- A pane is a stack of `SettingsSectionView`s of `SettingsRowView`s (`SettingsFormViews.h`): cards of hairline-separated rows, with the title and optional caption leading and the controls trailing. Every flat surface is a `SettingsFillView`, a layer fill re-resolved on an appearance flip.
- `switchWithAction:` makes a `VibeSwitch`, never an `NSSwitch` (`Mac/Controls/AGENTS.md`). `popUpButtonWithWidth:action:` makes a `VibeInlinePopUpButton`, the System Settings inline style, where the width is a cap rather than a size.
- Every list uses `SettingsRowView.listTableWithColumnIdentifiers:delegate:` and `listCellWithIdentifier:inTableView:imagePosition:`. A list inside a card is `SettingsRowView.rowWithTableView:rowCount:`. Its scroller is legacy style, so a list with more rows than fit shows the bar without a scroll, and still hides it while every row fits. `listRowViewForRow:` supplies the shared palette: alternating backgrounds and a neutral selection fill, with no row separators. The palette is measured in Display P3 from the system's Sound settings. It does not follow the main window's theme.
- Disabled controls go through `SettingsRowView.setControl:enabled:` (one control) or `setControlsInView:enabled:` (a row or a section). A disabled control fades to 50% alpha. A row whose controls are all disabled dims its title, caption and readouts the same way. Separators do not dim.

**The debug walker keys off these classes.** A row's title labels the controls beside it, and a section header labels the untitled rows under it. A pane built from anything else loses `settings_click`'s by-name addressing. Row titles drop a trailing colon at display time (`NSString+FormLabel`).

**TRAP: a content row must never carry a required width, fixed or capped.** `rowWithContentView:` pins its content leading to trailing. The pin climbs to the window's content view, which follows the frame only at `NSLayoutPriorityWindowSizeStayPut`. The content then stops short of a widened window, on every pane. A wrapping explainer follows its frame in `viewDidLayout` instead, with compression resistance below the fitting priority.

## Pane sizing

**Every pane shares one size, the largest pane's, and it is the window's FLOOR, not its size.** `naturalPaneSize` takes its **width from the pane view and its height from the section stack**. It is floored at `kSettingsPaneWidth` × `kSettingsPaneMinHeight` and capped at `kSettingsPaneMaxHeight`. `applySharedSizeToPanes:` writes the maximum into each pane's `sharedPaneSize`. The tab controller turns the selected pane's into `contentMinSize`, which only grows the window. The floor is recomputed, not a high-water mark, so a row reveal raises it and hiding the row lowers it. The window keeps any larger size the user gave it.

- **TRAP: the width has to be the pane's.** A page swapped in beside the stack, the theme editor, keeps its required width while hidden. A floor from the stack alone would let the window sit narrower than the pane, clipping every trailing control on every pane. The height stays the stack's, because a swapped-in page scrolls.
- **TRAP: `loadView` runs before `resolveLayoutStateFromSettings`, so a row that hides itself is first measured visible.** `settleSharedSizeForPanes:` runs at window creation. It loads every pane and resolves its layout state before taking the maximum, and it starts no refresh work in a hidden pane. `paneContentDidChange` re-derives the shared size after each refresh or row toggle of the selected pane.
- Each pane scrolls a flipped `SettingsStackView` in a scroll view pinned below the safe-area top. **Every scroll view in this window sets `autohidesScrollers`.** AppKit's default draws a bar down a pane, the sidebar or a list with nothing to scroll.

**Each pane measurement takes two Auto Layout solves.** Remeasurement has three gates. `settings.shown-refresh-*` in `Tests/BenchComponents/` measures their cost.

1. A hidden window does nothing. `showWindow:` settles every pane on the way from hidden to shown.
2. **A pane remeasures only when its layout signature moved** (`layoutSignature`: which rows show, and the text of their titles, captions and controls, lists excepted). Every regained key and closed menu refreshes the pane, so this gate is what keeps those cheap. The first open measures every pane, and a reopen measures none that did not change.
3. A pane whose signature moved measures **itself first**. It stops there when its own natural size did not move, since the shared size is a maximum.

**TRAP: a status line that changes during playback must never reach the solve.** Without the gates, every audio event re-solves every pane inside a resize animation on main, for the rest of the process after one visit to Settings. That freezes transport and drag-seeking. Before any of it, `setCaption:` answers whether the row's *height* changed, measured on that one label at its wrapping width. A caption with unchanged height needs no pane measurement. The cost of the gates: a pane whose rows changed while it was not selected can leave the floor stale until it is selected again or the window reopens.

The selected pane calls `refreshFromSettings` on appearance, on regaining key, and after menu tracking ends. The queued menu refresh re-checks visibility, since the menu action may have been File > Close. `SettingsWindowController.refreshSelectedPane` also refreshes it after a settled device switch changes bit-perfect mode, because menu tracking can end before the bind settles. The debug channel uses the same entry. The sizing pass never calls `refreshFromSettings`. Files probes its common folders once per appearance, since a probe can hold a worker on a provider root. Advanced measures its caches once per appearance.

**A drag's live work is paced** (`applyLiveEffectsDuringDrag:`). A continuous slider or color well writes its value on every tick. Its live effects and the Themes pane's waveform preview (`didApplyDragEffects:`) land at most every 1/30 s, always with the last value. Discrete changes apply at once.

**Hidden panes start no periodic refresh work.** Work already submitted can still finish after a pane hides. Nothing exists until Settings is first opened. After that the controller and every pane outlive the window, so everything that reaches a pane from outside is gated on the pane being visible. `audioPane` answers nil otherwise, and the player's report, device callbacks and the Output menu's refreshes all go through it. The Audio Output pane's device observer and the Files pane's grant observer are registered per appearance. The appearance KVO returns early unless the Themes pane is shown. A hidden pane catches up in `viewWillAppear`. Every refresh does nothing on unchanged values: `setCaption:`, `setRowTitle:`, `setControl:enabled:` and the popup selects return before touching a view. A visible pane's own size change remeasures only itself and reuses its siblings' last measurements (`applySharedSizeToPanes:measure:`).

## TRAP: the fitting-size snap, and the one resize path

AppKit resizes a `contentViewController` window to its fitting size after every layout pass. No constraint arrangement survives that and stays resizable. Equalities collapse the user's resize range, and minimums lose the fight. On macOS 26.5 a child's nonzero `preferredContentSize` becomes priority-501 equalities that pin the window. So the panes carry no size constraints, and the snap is refused at its funnel. **`SettingsWindow` overrides `setFrame:display:`** and drops any size change that is not the user's live resize, a call inside `resizeUnlocked:`, or setup before the window is visible. `resizeUnlocked:` is block-scoped and synchronous. A time-boxed unlock would let the snap back in, and an animator's later frames would arrive locked out. Every programmatic resize goes through `SettingsWindowController.applyWindowFrame:`. The floor lives only in `contentMinSize`. Zoom is refused.

- **The pane's root view follows the tab view by autoresizing mask, never by host constraints.** The tab controller pins only the pane selected before the window existed. Later selections set a frame and add nothing, so a pane without the mask collapses when selected second. `settings_open`'s `paneFillsTabView` checks it.
- **A real shared-size change is `paneContentDidChange`'s alone.** It runs one `NSAnimationContext` at `kWindowResizeAnimationDuration` with implicit animation. The remeasurement, the pane layout and a synchronous `setFrame:` through `applyContentSize:` all run inside it. The target frame comes from the engine's own numbers, since anything else is re-snapped by the next flush. **TRAP: the section stack must stay layer-backed.** Implicit animation moves only layer-backed views, and plain section headers would jump.
- **Both the tab and split controllers swallow `setPreferredContentSize:`**, since AppKit resizes the window at once on it. A pane's size change reaches the window only through `SettingsPaneSizeHost`. The tab controller answers it by resetting `contentMinSize` and growing the window where needed.

## Panes

**General.**

- The cards are Behavior, Window placement and, in the direct download only, Updates. Reopen last playlist at launch requests `ReopenLastPlaylist`. Always on top requests `AlwaysOnTop`, which also sets the About, Settings and Open URL windows' levels. Lock window position requests `WindowLock`, shared with Window > Lock Window Position. Waveform drag and Artwork drag request nothing, since each view reads its setting per gesture.
- **Automatically check for updates** is a switch over `AppDelegate.updateCheckInterval`: on writes the first preset, daily, unless a longer interval is already stored, and off writes 0. It is not an `AppSettings` key (`Mac/App/AGENTS.md`, Updates). **Check for updates now** sends `checkForUpdates:` to the updater controller, as the app menu's item does. In a Debug build launched without `--update-feed` the updater is created but never started. It still stores the interval, and Check Now does nothing, so both rows stay live to test (`Mac/App/AGENTS.md`, Updates). **Include beta versions** (`AppSettings.receiveBetaUpdates`) is on by default in a beta build and off in a stable one. The updater reads it at each check, so it requests no live effect. It stays enabled with the automatic check off, since Check Now still honors it.
- **Default music player** sits in Behavior. Its row shows a Set … as Default button until the app holds every type, then a checkmarked label in its place: a done state drawn as a disabled button read as unavailable. The swap lands after the async check, so it calls `paneContentDidChange` itself. `DefaultAppRegistration` claims only the **Default-rank** declarations (`DocumentTypes.defaultHandlerTypes`, in `project.yml`'s order, common formats first), then CUE sheets and M3U playlists. It also claims the type each of their extensions resolves to, never a video one (`.mp4` is a movie), since the Finder opens by that type. `.cue` often resolves to another app's type. It asks **one type at a time** and skips types already Vibe's, because each request raises its own Use/Keep panel. **TRAP: a refusal ends only its own type.** Ending the walk at a refusal would silently leave every later format unclaimed when the user keeps Books for one. Only when the system refused every request without the user declining one does the pane show its own alert, pointing to the Finder's Get Info > Change All. The "is default" check reads the same claimed set. **Alternate-rank types are never claimed, on purpose**: folders (Vibe must never become the default folder handler) and audiobooks (`.m4b` belongs to Books).

**Appearance** is `SettingsAppearanceViewController`. **It holds what the window shows, which is app-wide and never a theme field** (`AppTheme.h`), so a theme switch cannot hide a readout or a column.

- Window: Window appearance (`windowAppearanceStyle`, `WindowAppearance`), Dock icon (`AppIcon`) and Show window controls (`TrafficLights`). **A single-mode theme pins the window dark** (`AppTheme.requiredWindowAppearance`), so the popup disables, shows Dark so it agrees with the window, and its caption names the theme.
- Volume: **Show volume slider** (`AppSettings.volumeControl`, default off) puts a volume slider in the player window (`MainWindow/LAYOUT.md`). Location (`volumeLocation`), Show (`volumeVisibility`) and Show labels (`showVolumeLabels`) follow it. One action (`volumeSettingChanged:`) writes only its sender's setting and requests `Volume`. `Volume` pushes `effectiveVolume`: the slider's position while the control is on, 1 otherwise. Off bypasses volume scaling and keeps the slider position for next time. **It stays usable under bit-perfect output.** Below full, the player's report says so (VolumeScaled), and the open lock and the Bit-perfect caption show the percentage.
- Waveform: Normalize and Gain (`waveformNormalize`, `waveformGainDB`, `WaveformLevels`). These are common settings, not theme fields. A style without levels (Progress) disables both and says why under the description. The Themes pane's previews are keyed by the levels, so they redraw when it next appears.
- Track information: the time labels and the Time display popup, status icons, file info, BPM, key, key notation and Camelot key colors. One action (`trackInfoChanged:`) writes only its sender's setting and requests `TrackDisplay`. Show file info governs the whole BPM and key line, so it disables BPM and key. Show key disables notation and colors. **A row disabled this way says why in a caption** ("Requires Show file info"), the Audio Output pane's pattern, and the action remeasures the pane when a caption comes or goes. Time display follows Show time labels. A click on the time label writes the same setting.
- Playlist: the number, artwork and duration columns, requesting `PlaylistAppearance`.

**Audio Output** (identifier `audio`).

- **The Output list** has a fixed-width glyph column, then Name and Type. The type label and symbol share one transport mapping. System Output (device ID -1) comes first, then the manager's device snapshot. Selecting a row calls `OutputDevicesMenuController.selectOutputDevice:`, the funnel the Output menu uses too (`Mac/Menu/AGENTS.md`). The selected row follows the requested device ID, never its position. Every row stays selectable whatever the mode. Device and system-default notifications reload the snapshot, and the reload's reselection is guarded so it cannot request a device. **TRAP: building the pane tiles the table before its first refresh, and AppKit, denied an empty selection, selects row 0 itself.** Read as a request, that would switch the output to System Output and persist it on the pane's first showing. So the pane's `loadView` holds `_refreshingOutputList` for its whole construction.
- **Bit-perfect output** (`AppSettings.bitPerfectOutput`), first in the Device section. **The switch is the selected device's own.** It and Exclusive output are remembered per device UID, so selecting another row shows that device's modes. Off deletes the device's stored mode rather than storing NO, and an unplugged device keeps its entry. **TRAP: until the bind settles, mode writes still name the old saved UID**, so both mode switches stay disabled while any selection is pending. The switch writes the setting, then requests `BitPerfectApply` (`BitPerfect | FXControls | Crossfade`). The FX and crossfade branches read the derived `audioFXAllowed` and `effectiveCrossfadeMilliseconds`, so they withdraw the FX and drop the crossfade.
  - **Turning it on needs a device with a persistent UID that the mode can drive** (`VibeBitPerfectDeviceEligible`, `Audio/Mac/Devices/OutputFormatRules.h`). Bluetooth and other transports off the allowlist need Advanced's override. Turning it off is always allowed, even when the saved device is absent at launch.
  - **The caption is two lines**: what the mode does, then why it cannot be used, or, when on, the player's report (`setCaption:detail:`). The section header names the selected device. **The two ineligible cases get two reasons, because they need different remedies.** System Output (-1) names no device at all, and its own device may well be wired, so the caption says that row cannot be used. A concrete device off the allowlist is told to choose a wired device. When on, the caption is `bitPerfectStatusText`, the same sentence the header's open lock shows.
  - The rows refresh from the player's settled device callback, the pane's device observation, and the report, through `refreshBitPerfectRows`, which `MainPlayerController` calls from `audioPlayerDidChangeBitPerfectReport:`. The pane has no playback observation of its own. All of it reaches the pane only while it is on screen. The device observer is registered in `viewDidAppear` and removed in `viewWillDisappear`.
  - **Verification trap: the debug channel refreshes the selected pane after every verb**, reads included. A scripted check of this caption must screenshot as the first command after the change settles, or the dispatcher's refresh masks a missing production one.
- **Exclusive output** (`AppSettings.exclusiveOutput`, default off) asks for exclusive device use while playing. It enables only with bit-perfect output on and an eligible device whose hog property is writable (`CoreAudioUtil.supportsHogModeForDeviceID:`). The current system output device is eligible like any other, and taking it moves the system default elsewhere (`Audio/Mac/Devices/AGENTS.md`). The caption tells unsupported exclusive access apart from the other unmet conditions. The choice is per device and survives turning bit-perfect output off. It requests only `BitPerfect`, which sends both preferences together.
- **Declick** (`AppSettings.declick`, default on, one choice for every device and mode) sits in the Output card under the list, ahead of the selected device's own card, since it is not per device. It decides whether a transport edge ramps over the 10 ms declick or cuts (`Audio/AGENTS.md`). It requests only `Declick`, which rebuilds nothing. The volume slider's switch is on the Appearance pane, since it is something the window shows.

**Playback.**

- On track end requests `EndOfTrack`. **TRAP: without it, a mid-track switch to Pause leaves the armed gapless successor, which advances anyway.** The effect re-parks or drops the successor handle.
- Pitch range (a segmented control whose segment tags are the range) and crossfade request their own effects. Skip steps are read at the next skip.
- Audio effects requests `FXControls`. Off clears all five effects and hides the FX menu and keys. Both directions apply the audio route live through the same rebuild as bit-perfect. The first enable hosts the FX units. Bit-perfect output disables the FX switch and the crossfade slider with a second caption line.
- Detect BPM and Detect key request `TrackAnalysis`. Their captions are the iOS footers' sentences. A widened ask reloads the track on screen, whose cached waveform misses for an analysis it was decoded without (`Audio/Waveform/AGENTS.md`).

**Keyboard Shortcuts** (identifier `shortcuts`) lists every remappable command (`Mac/Menu/ShortcutRules.h`) under its menu's title, in the menu's order and with the menu's item titles. It rebuilds from `NSApp.mainMenu` on each refresh. Play, Convert to FLAC and the six skips take stable labels, because validation retitles them. A skip reads in its bars form whatever the track's tempo. A submenu item reads "Width: Small" or "Skip Back: 4 Bars".

- Clicking a command's shortcut, Record Shortcut, or a double-click starts recording. Record Shortcut and Clear act on the selected row, and Reset All on the whole list.
- **Every write goes through `MainPlayerController.assignShortcut:toCommand:loser:` or `resetShortcuts`**, the path the `set_shortcut` debug verb shares. It refuses a reserved or unnameable key, stores through `VibeShortcutOverridesByAssigning`, then requests `Shortcuts`. A conflict reassigns rather than refuses, and the caption names the command that lost the key.
- **Every write is undoable.** The pane keeps its own `NSUndoManager` (`paneUndoManager`), which Edit > Undo reaches while the pane is selected. Each entry restores the whole override set through `MainPlayerController.setShortcutOverrides:`, so a reassignment's loser returns with it.
- **Recording is a state of the pane, not a control.** A local monitor swallows every key in the Settings window until the captured key is released. So a recorded ⌘W or bare skip key never reaches a menu key equivalent, and its repeats are swallowed too. Resigning key or opening a menu cancels it, since the release would never arrive. **TRAP: the list's reload and reselection post selection changes**, ignored under `_reloadingList`. Treated as the user's, a refresh on regaining key would cancel the recording it ran under.

**Files.**

- **When opening a folder** (`folderOpenSort`) requests nothing. The order governs the *next* open, and re-sorting the playlist on screen would discard one built by hand. Both shells read it at open time (`Playlist/AGENTS.md`).
- **Album art** (`useFolderArt`, identifiers `file_only` and `file_then_folder`). **TRAP: the pane must request `FolderArt` after writing it.** The resolver caches the setting, and that effect is its only re-read (`Audio/Metadata/Artwork/FolderArt/AGENTS.md`).
- **Granted folders** lists `FolderAccessManager`'s grants (`Mac/App/AGENTS.md`). Every folder the user opens, drops or adds is an app-scoped security bookmark reopened at launch. A row carries its `VibeGrantedFolderState`, and an unavailable one is dimmed and suffixed. The list multi-selects, so Remove Access takes a batch, and Edit > Select All reaches it. The store is the manager's own `VibeGrantedFolders` key, bookmark data rather than `AppSettings`.
  - **TRAP: never stat a row, and ask about a drag once.** `viewForTableColumn:` runs on main per reload, and drag validation per mouse move. A dead mount blocks a stat for an automounter timeout. State comes from the manager's resolve, and the icon is the generic folder icon. Folder-ness is asked of the **pasteboard** (`public.folder`, which also refuses a package). The pasteboard answers with a `getattrlist` per URL each time it is asked. Validation asks it once per drag, through the pane base's `pasteboardOfDrag:canReadURLsWithOptions:`. A folder deleted while the app runs reads active until the next launch.
  - **TRAP: a Finder drag delivers file-reference URLs.** A grant is stored against a path, so the drop pins each to its current path (`MainWindow/AGENTS.md`).
  - **Add Common Folder** offers the real home (`FolderAccessManager.realHomeDirectory`, `Mac/App/AGENTS.md`), Documents, iCloud Drive or Dropbox in an open panel with nothing selected, since the sandbox grants nothing unpicked. Each item carries its own disabled reason, "Not found" or "Already accessible". The not-found probes run off main, generation-guarded, because two candidates are provider roots where a stat blocks. An unavailable row does not count as "Already accessible", since it is the folder worth offering again.
  - A playlist file whose entries are unreadable raises the folder grant panel (`requestAccessForPlaylistFolder:`). It is the same picker and bookmark as Add Folder (`Mac/App/AGENTS.md`, Sandbox grants).
- **FLAC conversion**, off by default. Convert menu requests `ConvertMenu`, which hides the Convert menu in place (`Mac/Menu/AGENTS.md`) and disables the destination and Trash rows.

**Advanced.** The sections are Build, Engine, Maintenance and the Audio readout.

- **Build** reads from the bundle, not the catalog. **Debug info > Save…** writes `DebugInfo`'s report (`Mac/App/AGENTS.md`) wherever the user picks in a save panel, the sandbox's user-selected grant as Save Playlist uses, and reveals it in Finder. The button stays disabled until the write finishes.
- **Engine.** Playhead refresh cap requests `UIUpdateRate`. **Allow bit-perfect on any device** (`AppSettings.allowBitPerfectOnAnyDevice`, default off) bypasses the transport allowlist for every concrete device, Bluetooth included, through `BitPerfectApply`. It keeps the device-specific mode choices, and turning it off reapplies normal eligibility at once. System Output still has no device UID.
- **Cache size** sums both stores and is generation-guarded against a stale reply landing after Clear Cache. It is measured once per appearance and after Clear Cache, never on the key and menu refreshes. Each measurement walks both stores stat by stat and holds the waveform cache's queue, which the next track's waveform waits on.
- **Restore Defaults…** asks first, in a sheet with an "Also delete custom themes" checkbox: off runs `AppSettings.resetToDefaults`, which keeps custom themes, and on runs `factoryReset`, which deletes them. Nothing here is undoable. In the direct download both also clear Sparkle's two check settings, then tell it to reschedule its checks. Both reset the store, request `All`, select System Output through `OutputDevicesMenuController`, restore the window shape and reload every pane. The button enables while a setting differs from its default (`VibeSettingsAreAtDefaults`, `SettingsRules.h`), while custom themes remain, or while the welcome track is spent (`welcomeTrackSpent`, which only the factory reset clears).
  - **TRAP: reset clears the saved device UID while the player keeps the old binding**, so the mode switches would write to nothing. The reset selects System Output through `selectOutputDevice:`, which keeps the switches disabled until the change settles. A refused bind reannounces the kept device, restoring its saved UID before the controls re-enable.
  - **TRAP: reset clears the two window-shape settings, and no live effect applies them.** The reset must call `MainPlayerController.resetWindowToDefaultShape` after `All`, or the window keeps a shape the store disagrees with until the next launch.
- **Audio** lists the render chain stage by stage from `AudioPlayer.audioPathSnapshot`: source file, decoder, mixing bus, pitch, effects, level meter, output unit, output device. Each row reads across in one shape (name · rate · depth · channels · status · latency), with each column only where the stage has one. A stage the signal bypasses reads a bare Off. A connected effects stage with nothing active reads "On, nothing active". The device row shows its bit-perfect or exclusive standing as BP and Hog. It refreshes once a second off main while the pane is on screen, and on every pane refresh. **TRAP: never take the snapshot on main.** It waits on the player queue, which a device rebind or an unresponsive device holds for seconds. **It is a debug readout, so a Release build hides it** until the Version row is clicked seven times in quick succession (`kVibeAudioPathRevealClicks`, `SettingsRules.h`), for the session. While it is hidden no snapshot is taken and no timer runs. The readouts are single-line and truncate, so a change never reaches a pane solve. The debug channel's `dump_audio_path` and the debug report read the same model.

**About.** The identity block sits outside any card (`loadPaneWithSections:` stacks a plain view where a section would go). The icon opens the About window through the nil-targeted `showAboutWindow:` (`Mac/About/AGENTS.md`). The copyright is the About window's alone.

**Preset settings are normalized on read** by `AppSettings` (`SettingsRules.h`). The pane and the player read the same value.

## Driving this window from the debug channel

**Never with `click`, `drag` or the `key*` verbs**, which post into the main player window's event stream. `settings_open`, `dump_settings_ui`, `settings_click`, `settings_reveal`, `settings_menu`, `settings_resize` and `settings_close` address it structurally: a pane by identifier, a control by the name its row shows. The `vibe-debug` skill documents them. Rerun `dump_settings_ui` after changing a pane's layout. A control kind the walker does not model, or a name two controls share, shows up there first.
