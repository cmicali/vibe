# Appearance pane: the theme list and editor

Two pages in one pane. The list page, the page swap, import, export and the drop target are in the class file; the editor page is `+Editor.m`, with `SettingsAppearanceViewControllerInternal.h` carrying its outlets and the list-side methods it calls. Scaffolding and sizing are `../CLAUDE.md`; the theme record and its sanitization gate are `Common/Mac/Theme/CLAUDE.md`, the theme store `Common/Mac/CLAUDE.md`.

## The list page

A Window card (the **Appearance** popup — Auto/Light/Dark, the window's own setting — and Show traffic lights), a Waveform card (Style, Normalize, Gain — captionless, so the pane keeps the design width) and the theme list.

- **Style is a THEME field surfaced outside the editor**: the same slot as the editor's Waveform style row, built by one helper, each edit re-selecting the other, written through the working-record funnel — so over a built-in it lands in the divergence key, the Show File Info behavior. **Normalize and Gain are common settings**, not theme fields, sharing `VibeSettingsLiveEffectWaveformLevels`.
- **Selection IS activation.** Clicking a theme row applies it (`applyThemeWithIdentifier:` + `ThemeApply`), the same as View > Theme; the selected row is the active theme, highlighted with the shared settings list selection fill, including while unfocused, no checkmark. **A header is an ordinary row the delegate refuses to select, not an AppKit group row** — that style adds a gap and its own height to a ten-row budget — so row-to-theme is arithmetic over the built-in count (`identifierForRow:`, nil for a header). The reselect after each reload scrolls, or an imported theme lands selected past the fold.
- Add ▾ (New Theme, Duplicate, Import…), Remove (user themes only, no confirmation — a sheet would block `settings_click`), Edit… and Export…. Edit… and a row double-click push the editor for the active theme.
- **TRAP: the list's programmatic reload guards reentrancy** (`_refreshingThemeList`). `reloadData` and the reselect both post selection-changed, and treating those as activations recursed refresh into a stack overflow.
- **Import and the drop are one funnel** (`importThemesFromURLs:`). The drop validates against the pasteboard's content types, JSON or ZIP, never the file system, and retargets onto the whole list since an import always lands in the user group. Files are read mapped, so the size gate refuses a huge pick without loading it; each passes the same sanitize gate as `import_theme`; the last one is activated once, after the whole list; failures are named in one alert. Export decides ZIP-or-JSON from the record's artwork references (`AppTheme+Archive`), reads images only after the panel confirms, falls back to plain JSON when an image vanished, and reports a failed write with the system's error.

## The titlebar controls

- **The light/dark preview toggle** (both pages) writes `AppSettings.windowAppearancePreviewStyle`, the transient override, never the stored style: the list page's Appearance popup keeps showing the stored choice, and the two disagreeing is the feature. `viewDidDisappear` drops the preview, so leaving the pane and closing the window are one revert; writing the stored style clears the preview. Under a single-mode theme the preview is outranked by the pinned dark appearance. The item is inserted while the pane is selected and removed otherwise, never hidden: `NSToolbarItem.hidden` needs macOS 15, and the delegate vends non-inserted copies during enumeration.
- **Navigation is the toolbar's `navigational` pill.** The editor retitles the window `Theme: <name>` through the pane-title chain (`applyEditorTitle`, the Name field's live text while editing). Back pops; Forward, armed by a pop, re-opens; both disable outside this pane (`updateThemeNavigation`).
- **The dice control** rolls settings or colors (`AppTheme`'s two dice, `Common/Mac/Theme/CLAUDE.md`) as a whole-theme `ThemeApply`, on the editor page over a user theme only (`canRandomize`). **The arrow undoes the last edit**, the Name rename included: the stack lives in `AppSettings.currentThemeDidChange` (`Common/Mac/CLAUDE.md`), which also re-runs `updateThemeNavigation`, so the arrow enables on the first edit. Edit > Undo does not reach it; that item targets the playlist undo.
- The toolbar sits outside the pane, beyond the walker: `settings_click Back|Forward`, `preview light|dark`, `randomize settings|colors` and `undo` are reserved names routed through the pane's model, and `dump_settings_ui`'s `toolbar` reports each segment's enabled flag.

## The editor page

Swapped in as a **sibling of the section stack**, and **scrolling inside whatever size the panes settled at**: `naturalPaneSize` measures only the base stack, so twenty editor rows cannot grow every pane, and the page swap is size-neutral. Every row action is one helper — write the `currentTheme` field, `currentThemeDidChange`, request the row's effect.

- **TRAP: the document view is a FLIPPED stack** (`SettingsEditorStackView`). Unflipped, the document's top is its maxY while the clip view keeps its bounds origin, so every relayout stranded the page further under the toolbar. The scroll view keeps `automaticallyAdjustsContentInsets = NO`.
- **A built-in's page is read-only**: every control disables (the walker reports it and `settings_click` refuses), the Name row hides, and the first card carries a caption plus **Duplicate**. The Name and built-in rows swap visibility, so the second carries no top hairline.
- **Renaming is the Name field** (end-editing → `renameUserThemeWithIdentifier:`), not inline in the list, which would collide with double-click-to-open. The name may come back deduped, so the pane re-reads.
- **The fonts rows drive the system font panel** onto a slot ivar. **TRAP: Select… parks first responder on the pane's view first — a focused field editor is an `NSTextView`, which implements `changeFont:` and would eat the panel's sends.** The panel closes on Back, on leaving the pane and when a read-only page takes over; it cannot be driven from the channel — `import_theme` and `set_theme` are the scripted path.
- **The editor's Appearance popup is the theme's `mode`** (Light & Dark Modes / Single Mode), the theme's colors, not the window's appearance. Under Single Mode `resolveLayoutStateFromSettings` collapses every Dark/Light well pair to the dark-keyed well, the single slot `AppTheme` reads and writes from either side; the light halves lie dormant, so flipping modes round-trips. Mode edits ride `ThemeApply`, which carries `WindowAppearance`, because a single-mode theme pins the window dark.
- Every color well is bound to its pair once (`wellForDark:base:effect:`), so one action, one refresh loop and one dark-first seed walk (`seedWellsIn:`) serve all of them; dark-first is what lets single mode's slot take the dark default. The five popups that reveal color rows are one helper (`chooseFromPopUp:revealing:wells:effect:write:`). Revealed wells are **seeded from their displayed fallbacks**, so the window matches the wells at once; alpha is part of every choice. The playlist's background rows mirror the window's popup and tint.
- **Everything below Show file info disables as a group** (`SetDescendantControlsEnabled(_infoSection, …)`); Key notation and Color keys additionally require Show key. **Both key choices govern every key shown, tagged ones included**, since a tag is parsed to a `VibeMusicalKey` on read.
- The corner-radius slider (`VibeDetentSlider`) has a magnetic detent at `kVibeThemeCornerRadiusDefault` and is enabled only under Custom corner radius: with the switch off the window draws the standard radius whatever the slider holds (`AppTheme.resolvedWindowCornerRadius`).
- **An image field is a preview, not a popup**: one image button per slot, keyed by field on the button's `identifier` (`imageClusterForKey:`), showing `previewImageForKey:`'s resolved image. A click opens the JPEG/PNG panel into `storeCustomImageData:`; hover reveals a clear badge **only while the slot holds a custom image** on an editable page, and clicking it writes the slot back to `""`. The hover rides tracking areas (`ActiveInActiveApp`, so it works while the color panel is key); posted debug events cannot fire them, so a scripted clear needs a real hover through `input.swift` before `settings_click "Clear custom image"`. Each slot's edit requests its own effect (`VibeThemeImageEditEffect`).
- **A transport button is a glyph popup with a color pair, or a picture** (`buttonRowsForImageKey:`). The popup lists `SettingsRules.h`'s curated SF Symbols by symbol name — an identifier, deliberately not thirty display names — and ends in Custom image…; a JSON-authored glyph the menu lacks shows through a transient item. The color row and the image row swap on whether the button holds an image. **A button's Dark and Light wells are the colors over dark and light ARTWORK**, not appearance (`MainWindow/APPEARANCE.md`), so they and the image pairs stay two-sided under Single Mode (`artKeyedColorPairForBase:`, `artKeyedImagePairForDarkKey:lightKey:`). **A glyph pick retires the button's image**, since the image wins while set, and a play pick writes the pause glyph (`VibePauseGlyphForPlayGlyph`); `AppTheme.setGlyph:forButtonImageKey:` owns that mutation. Play has an image row per state; an unset side draws the other's. Every button edit and the Button gradient switch request `TransportButtons`; the Dock icon popup and the App icon preview request `AppIcon`.
- In the channel the theme table is addressed by index (`settings_click '#2' <row>`), because the card's header labels every control in it; **header rows take indices of their own**, so read the row off `rows` rather than counting themes. Assert activation through `dump_state.settings.activeTheme`.
