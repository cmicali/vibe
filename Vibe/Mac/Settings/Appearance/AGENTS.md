# Themes pane: the theme list and editor

The pane identifier is `themes`; the directory and the class keep the Appearance name from before the Appearance pane split off (`../AGENTS.md`). Two pages in one pane. The list page, the page swap, import, export and the drop target are in the class file; the editor page is `+Editor.m`, with `SettingsAppearanceViewControllerInternal.h` carrying its outlets and the list-side methods it calls. Scaffolding and sizing are `../AGENTS.md`; the theme record and its sanitization gate are `Common/Mac/Theme/AGENTS.md`, the theme store `Common/Mac/AGENTS.md`.

## The list page

The theme table is one column, so no header: each name carries its theme's swatch (`swatchForThemeIdentifier:dark:`), the window color behind three bars of the waveform color, the active theme's from its working record. Group headers start at the swatches' edge.

Current theme comes first: the active name, Edit Theme… (Customize… for a built-in; both only open the editor), the quick waveform-style picker and a static renderer preview below it. Built-in divergence shows Modified and Revert; Customize copies that working state into an editable theme. The theme list follows.

- **Style is a THEME field surfaced outside the editor**: the same slot as the editor's Waveform style row, built by one helper, each edit re-selecting the other, written through the working-record funnel — so over a built-in it lands in the divergence key.
- **Both pages share one waveform preview image and refresh path.** The editor places it beside its waveform settings in Player. The cache key includes style, appearance, resolved colors, gradient, the playhead line's color, density, width and levels; waveform edits refresh it directly, including continuous sliders and color wells. The synthetic sample has no artwork, so Album Art uses the palette resolver's normal monochrome fallback.
- **Selection IS activation.** Clicking a theme row applies it (`applyThemeWithIdentifier:` + `ThemeApply`), the same as View > Theme; the selected row is the active theme, highlighted with the shared settings list selection fill, including while unfocused, no checkmark. **A header is an ordinary row the delegate refuses to select, not an AppKit group row** — that style adds a gap and its own height to a ten-row budget — so row-to-theme is arithmetic over the built-in count (`identifierForRow:`, nil for a header). The reselect after each reload scrolls, or an imported theme lands selected past the fold.
- Add ▾ (New Theme, Duplicate, Import…), Remove (custom themes only, restored through theme undo; disabled over a built-in with a tooltip saying why) and Export… manage the library. The current-theme button, a row double-click and the menu all open the editor through the window's history (`showThemeEditor`). Duplicate copies the working record and selects the new name for editing.
- **TRAP: the list's programmatic reload guards reentrancy** (`_refreshingThemeList`). `reloadData` and the reselect both post selection-changed, and treating those as activations recurses refresh into a stack overflow.
- **Import and the drop are one funnel** (`importThemesFromURLs:`). The drop validates against the pasteboard's content types, JSON or ZIP, never the file system, and retargets onto the whole list since an import always lands in the user group. Files are read mapped, so the size gate refuses a huge pick without loading it; each passes the same sanitize gate as `import_theme`; the last one is activated once, after the whole list; failures are named in one alert. Export decides ZIP-or-JSON from the record's artwork references (`AppTheme+Archive`), reads images only after the panel confirms, falls back to plain JSON when an image vanished, and reports a failed write with the system's error.

## The titlebar controls

- **The light/dark preview toggle** (both pages) writes `AppSettings.windowAppearancePreviewStyle`, the transient override, never the stored style: the Appearance pane's Window appearance popup keeps showing the stored choice, and the two disagreeing is the feature. `viewDidDisappear` drops the preview, so leaving the pane and closing the window are one revert; writing the stored style clears the preview. Under a single-mode theme both the preview toggle and the stored appearance popup disable; the popup's caption names the theme. The item is inserted while the pane is selected and removed otherwise, never hidden: `NSToolbarItem.hidden` needs macOS 15, and the delegate vends non-inserted copies during enumeration.
- **Navigation is the window's history** (`../AGENTS.md`): the editor is the location `themes/editor`, so Back leaves it and Forward returns, as for any pane. Choosing Themes in the sidebar opens the list, never the editor. The editor retitles the window `Theme: <name>` through the pane-title chain (`applyEditorTitle`, the Name field's live text while editing), and every page swap reaches `updateNavigation`.
- **The dice control** rolls settings or colors (`AppTheme`'s two dice, `Common/Mac/Theme/AGENTS.md`) as a whole-theme `ThemeApply`, on the editor page only (`editorShown`); over a built-in the roll is its first edit, so it forks. **The two arrows undo and redo edits and removals**, renames included. Edit > Undo (⌘Z) and Redo (⇧⌘Z) reach the same store history while Themes is selected, on either page; focused text fields retain native text undo/redo. `updateNavigation` keeps the arrows enabled and names a pending removal in their tooltips. A new edit discards redo; explicitly selecting a theme clears both directions.
- The toolbar sits outside the pane, beyond the walker: `settings_click Back|Forward`, `preview light|dark`, `randomize settings|colors` and `undo` are reserved names routed through the pane's model, and `dump_settings_ui`'s `toolbar` reports each segment's enabled flag.

## The editor page

Swapped in as a **sibling of the section stack**, and **scrolling inside whatever height the panes settled at**: `naturalPaneSize` takes its height from the base stack alone, so twenty editor rows cannot grow every pane. **Its WIDTH is not free, though**: the container is pinned leading-to-trailing in the pane and keeps that requirement while hidden, so the editor's widest row — the two-image `Playlist button images` cluster — sets the floor for the whole window (`../AGENTS.md`). A new editor row wider than that raises the settings window's minimum width. Every row action is one helper — write the `currentTheme` field, `currentThemeDidChange`, request the row's effect. Switches bind a typed field writer and their live effect at construction (`themeSwitchWithEffect:write:`); one action persists the edit, applies that effect and refreshes dependent controls.

- **TRAP: the document view is a FLIPPED stack** (`SettingsStackView`). Unflipped, the document's top is its maxY while the clip view keeps its bounds origin, so every relayout strands the page further under the toolbar. The scroll view keeps `automaticallyAdjustsContentInsets = NO`.
- **A built-in opens in the editor as it is, and its first edit copies it** (`forkBuiltInForEdit`, run by `themeFieldDidChange:` before it persists): the edit already sits in the working record, so a duplicate of that record becomes the active theme through `applyThemeWithIdentifier:`, which also clears the built-in's divergence, and the page refreshes onto the copy. The image picker forks once it confirms (the store refuses a built-in's images), and a rename forks unless the name is the built-in's own. The Name row's caption says so while a built-in is open. The list page's quick style picker is not an editor edit, so over a built-in it still lands in the divergence key.
- **Renaming is the Name field** (end-editing → `renameUserThemeWithIdentifier:`), not inline in the list, which would collide with double-click-to-open. The name may come back deduped, so the pane re-reads.
- **The fonts rows drive the system font panel** onto a slot ivar. **TRAP: Select… parks first responder on the pane's view first — a focused field editor is an `NSTextView`, which implements `changeFont:` and would eat the panel's sends** — and beginning to edit the Name closes the panel, the same trap from the other side. The panel closes on Back, on leaving the pane and when a read-only page takes over; it cannot be driven from the channel — `import_theme` and `set_theme` are the scripted path.
- **The editor's Theme color modes popup is the theme's `mode`** (Light & Dark Modes / Single Mode), the theme's colors, not the window's appearance. Under Single Mode `resolveLayoutStateFromSettings` collapses every Dark/Light well pair to the dark-keyed well, the single slot `AppTheme` reads and writes from either side; the light halves lie dormant, so flipping modes round-trips. Mode edits ride `ThemeApply`, which carries `WindowAppearance`, because a single-mode theme pins the window dark.
- Every color well is bound to its pair once (`wellForDark:base:effect:`), so one action, one refresh loop and one dark-first seed walk (`seedWellsIn:`) serve all of them; dark-first is what lets single mode's slot take the dark default. The five popups that reveal color rows are one helper (`chooseFromPopUp:revealing:wells:effect:write:`). Revealed wells are **seeded from their displayed fallbacks**, so the window matches the wells at once; alpha is part of every choice. The playlist's background rows mirror the window's popup and tint.
- **Show transport buttons defaults on and preserves the settings it disables**: it governs its section, including the gradient; the default artwork lives in Player and stays editable. Disabled color wells deactivate — **only an active one: `deactivate` creates the shared color panel, whose first layout brings up RenderBox's Metal device and the GPU driver's 256 MB texture heap.** Track information keeps only the readouts' font and the info and time colors, enabled whatever the app-wide readout switches say.
- **Corner radius** is Standard or Custom (`standardOrCustomPopUpWithAction:standard:`); Custom shows the slider (`VibeDetentSlider`, a magnetic detent at `kVibeThemeCornerRadiusDefault`) beside the choice. Under Standard the window draws the standard radius whatever the slider holds (`AppTheme.resolvedWindowCornerRadius`). The playlist columns' colors take the same shape, Automatic or Custom with their wells beside it, seeded on the switch to Custom.
- Waveform bar density and width share slider setup and updates, from 50% to 200% with a detent at the original 100%. The registry enables both for Basic, Cupertino, Sonic Cirrus and both Wiggles, and width alone for Cupertino Basic, where it adjusts pill height. Other styles keep the stored values dormant. Continuous edits coalesce into one undo and request `WaveformStyle`, which updates the existing renderer's count and thickness live.
- **Playhead line** follows Waveform gradient: the switch is `waveformPlayheadLine`, and on it reveals Playhead color, a Dark/Light pair that collapses under Single Mode like the others. Both request `WaveformTheme`. The wells show the pair's displayed fallback, which is also what the line draws, so nothing is seeded on reveal.
- **An image field is a preview, not a popup**: one image button per slot, keyed by field on the button's `identifier` (`imageClusterForKey:`), showing `previewImageForKey:`'s resolved image. A click opens the JPEG/PNG panel into `storeCustomImageData:`; hover reveals a clear badge **only while the slot holds a custom image** on an editable page, and clicking it writes the slot back to `""`. The hover rides tracking areas (`ActiveInActiveApp`, so it works while the color panel is key); posted debug events cannot fire them, so a scripted clear needs a real hover through `input.swift` before `settings_click "Clear custom image"`. Each slot's edit requests its own effect (`VibeThemeImageEditEffect`).
- **A transport button is a glyph popup with a color pair, or a picture** (`buttonRowsForImageKey:`). The popup lists `SettingsRules.h`'s curated SF Symbols as glyphs alone — the symbol name is an identifier, shown only as an item's tooltip — and ends in Custom image…; a JSON-authored glyph the menu lacks shows through a transient item. The color row and the image row swap on whether the button holds an image. **A button's On dark artwork and On light artwork wells follow artwork brightness**, not appearance (`MainWindow/APPEARANCE.md`), so they and the image pairs stay two-sided under Single Mode (`artKeyedColorPairForBase:`, `artKeyedImagePairForDarkKey:lightKey:`). **A glyph pick retires the button's image**, since the image wins while set, and a play pick writes the pause glyph (`VibePauseGlyphForPlayGlyph`); `AppTheme.setGlyph:forButtonImageKey:` owns that mutation. Play has an image row per state; an unset side draws the other's. Every button edit and the Button gradient popup (None / Show on hover / Show on artwork / Always) request `TransportButtons`; the App icon preview and the icon-shape switch request `AppIcon`.
- **Volume slider** sits after Track information: Location (Top right / Bottom, captioned: in the corner the slider swaps with the track information on hover), Show labels, Bar color (`volumeBar`: None / Artwork color / Waveform color / Custom, whose wells reveal like the window tint's) and Knob color (`volumeKnob`: Bar color's four with Same as bar, its default, after None; Waveform color is Bar color's default). The rows request `Volume`, except the two colors' wells: both colors re-resolve with every waveform theme resolution, so a well drag requests the lighter `WaveformTheme` rather than Volume's relayout.
- In the channel the theme table is addressed by its `#index` from `dump_settings_ui`, because the card's header labels every control in it; **header rows take indices of their own**, so read the row off `rows` rather than counting themes. Assert activation through `dump_state.settings.activeTheme`.
