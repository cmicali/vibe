# Settings window (macOS)

Vibe > Settings… (⌘,) is `SettingsWindowController`: an `NSSplitViewController` whose source-list sidebar (`SettingsSidebarController`) drives a tab-less `NSTabViewController` of panes, in the System Settings shape. The store is `AppSettings` (`Vibe/Common/`); this directory is only the window. `DefaultAppRegistration` lives here as the Launch Services half of `Common/DocumentTypes`. The Appearance pane — the theme list and editor — is `Appearance/`, with its own `CLAUDE.md`.

**A store-first write that must change the running app has one post-write path**: store the value, then request the exact `VibeSettingsLiveEffect` from `MainPlayerController+Settings`. The mapping is synchronous on main, applies only stored state, and never writes a setting or moves a window. A setting read at the next gesture requests nothing. Each pane row below names the effect it must request; a missing request silently breaks the setting.

## Window and chrome

- **The split controller must stay the window's `contentViewController`.** The sidebar tracking separator resolves through it, and hosting its view bare re-created macOS 26's titlebar scroll pocket as a window-wide band. The split items' `titlebarSeparatorStyle = None` governs that band; the window-level setting does not reach through. A `contentViewController` assigned after init does not bind the title, so `SettingsSplitViewController.setTitle:` pushes it explicitly.
- **The toolbar is icon-only** (`displayMode`): with labels allowed, a unified toolbar reserves a label row whether or not one is drawn. Labels stay set for accessibility.
- **Sidebar rows are built from the tab items**, so order, labels and symbols cannot drift, and selection syncs both ways through `didSelectTabViewItem:`, which owns only selection, sidebar and title. Rows are `SettingsAccentRowView`s whose `isEmphasized` override answers YES, keeping the accent while unfocused; `emphasized` set from `rowViewForRow:` is overwritten on every key-window change. **TRAP: never `reloadData` inside the sidebar's selection callback** — it resets the selection to row zero and reenters. The icon re-tint rides `SettingsSidebarCellView.setBackgroundStyle:` instead.
- **The window title is the title-propagation chain, never set directly.** Each pane's `title` names its sidebar row and the window; `didSelectTabViewItem:` pushes it onto the split controller. The first pane's title is seeded at init because the initial selection precedes the split controller.
- Each tab item carries a **stable, unlocalized identifier** (`general`, `audio`, `playback`, …), which `settings_open` selects by. Sidebar labels reuse menu strings where the word is the same; the rest are `settings.*` keys.
- `AppDelegate` creates the window lazily and keeps it alive. File > Close is nil-targeted, so this controller's `closeFile:` catches ⌘W ahead of the player's.
- Pane switches are immediate: `transitionOptions` is `None`, because the default crossfade composites two section headers and reads as a flash.

## Pane scaffolding

`SettingsPaneViewController` subclasses build panes on shared scaffolding; Audio and General are two instances of `SettingsGeneralViewController`, each building only its own page: the pane size, the grouped section stack, `switchWithAction:` (an `NSSwitch` that reads and writes like a checkbox) and `popUpButtonWithWidth:action:` (`VibeInlinePopUpButton`, the System Settings inline style — borderless, chevron badge, hover bezel, the width a cap rather than a size). A pane builds `SettingsSectionView`s of `SettingsRowView`s (`SettingsFormViews.h`): cards of hairline-separated rows, title and optional caption leading, controls trailing. Every flat surface is a `SettingsFillView`, a layer fill re-resolved on an appearance flip. Audio, Themes and Files share `SettingsRowView.listTableWithColumnIdentifiers:delegate:` and `listCellWithIdentifier:inTableView:imagePosition:` for table setup, labels and optional icons. `listRowViewForRow:` supplies the shared Sound settings palette: alternating backgrounds and a neutral selection fill in both appearances, with no row separators. A list inside a card is `SettingsRowView.rowWithTableView:rowCount:`: rounded edges, no bezel and 24-point rows. Multi-column lists use a shared label header without native column dividers and include it in the height budget. Header titles start 8 points into a column and row text starts 10 points in, including AppKit's leading cell margin; form-row padding stays separate. The palette is measured in Display P3 from the Sound settings reference; it does not inherit the main-window theme.

Disabled controls use `SettingsRowView.setControl:enabled:` (one control) or `setControlsInView:enabled:` (a row or a whole section, one appearance pass per row) across all panes: controls fade to 50% alpha, and a row whose controls are all disabled gives its title, caption and readouts the same alpha. Mixed rows leave their active controls and shared labels readable; separators do not dim.

**The debug walker keys off these classes**: a row's title labels the controls beside it, and a section header inherits down to untitled rows. A pane built from anything else loses `settings_click`'s by-name addressing. Row titles drop a trailing colon at display time (`NSString+FormLabel`).

**TRAP: a content row must never carry a required width, fixed or capped.** `rowWithContentView:` pins its content leading-to-trailing, so the pin climbs to the window's content view, which follows the frame only at `NSLayoutPriorityWindowSizeStayPut` — the content then stops short of a widened window, on every pane. A wrapping explainer follows its frame in `viewDidLayout` instead, with compression resistance below the fitting priority.

**Every pane shares one size — the largest pane's — and it is the window's FLOOR, not its size.** `naturalPaneSize` takes its **width from the pane view and its height from the section stack**, floored at `kSettingsPaneWidth` × `kSettingsPaneMinHeight` and capped at `kSettingsPaneMaxHeight`. **TRAP: the width has to be the pane's**, because a page swapped in beside the stack — the theme editor — keeps its required width while hidden, so the pane cannot lay out narrower than that whatever the stack asks for; a floor taken from the stack alone let the window sit 67 points narrower than the pane it hosts, and the pane then overflowed the tab view with every trailing control clipped, on every pane (#60). The height stays the stack's because a swapped-in page scrolls. The cost is two Auto Layout solves per measurement, which is why the gates below matter. `applySharedSizeToPanes:` writes the maximum into each pane's `sharedPaneSize` — **a plain property, never `preferredContentSize`, and the panes carry no size constraints** (next section) — and the tab controller turns the selected pane's into `contentMinSize`, grow-only. The floor is recomputed, never a high-water mark, so a row reveal raises it and hiding it lowers it, while the window keeps any larger size the user gave it. `settleSharedSizeForPanes:` runs at window creation: it loads every pane and runs the layout-only `resolveLayoutStateFromSettings` before the maximum is taken, so nothing is measured against rows nobody sees and no hidden pane starts refresh work. Each pane scrolls a flipped `SettingsStackView` inside a scroll view pinned below the safe-area top; content width follows the clip view. Long Files and Appearance pages therefore do not force every pane past the height cap. **Every scroll view in this window sets `autohidesScrollers`** — AppKit's default is NO, which draws a bar down a pane, a sidebar or a list with nothing to scroll, where System Settings shows none.

**TRAP: `loadView` runs before `resolveLayoutStateFromSettings`, so a row that hides itself is first measured visible** and would hold every pane at that height. `paneContentDidChange` therefore remeasures **all** panes, in one transaction with the stack layout and the window frame. Remeasuring is the only way: an inequality against the stack leaves the stack under-determined, and the solver spends the slack stretching the top card.

**It reaches that remeasurement through two gates, and both exist because `fittingSize` is a full Auto Layout solve, not a lookup.** A hidden window does nothing at all — there is no frame to move, and `showWindow:` settles every pane on the way back in. A visible one measures **itself first** and stops there when its own natural size has not moved: the shared size is a maximum over panes, so a pane that did not move cannot have moved it. **TRAP: a status line that changes during playback must never reach the solve at all**: without these gates one re-solved all seven panes inside a resize animation, on the main thread, on every audio event — and one visit to Settings left that cost in place for the rest of the process, window open or not. That is what froze transport and drag-seeking in #47; the samples are in the issue. The gates were not enough on their own: `setCaption:` used to answer whether the caption's *text* changed, so every status change still cost a layout pass and a pane solve. **It now answers whether the row's height changed, measured on that one label at its wrapping width** — no bit-perfect status wraps in any shipped language at the narrowest window (the widest, Dutch "file is lossy", is 549 of 552 points), so a status change during playback does no layout work beyond the label's own. A caption that does change its line count still takes the path above. The cost of the gates is that a pane whose rows changed while it was *not* selected can leave the floor stale until it is selected again or the window is reopened, which is recoverable and was worth trading for.

The selected pane calls `refreshFromSettings` on appearance, on regaining key, and after menu tracking ends. `SettingsWindowController.refreshSelectedPane` also refreshes it after a settled device switch changes bit-perfect mode, because menu tracking can end before the bind settles; the debug channel uses the same refresh entry. The sizing pass never calls it: Files probes folders and Advanced enumerates caches only while selected.

## TRAP: the fitting-size snap, and the one resize path

AppKit re-sizes a `contentViewController` window to its fitting size after every layout pass, and no constraint arrangement survives it resizable: equalities collapse the user's resize range, minimums lose the snap fight, and on macOS 26.5 a child's nonzero `preferredContentSize` becomes 501-priority equalities that pin the window. So the panes carry no size constraints and the snap is refused at its funnel: **`SettingsWindow` overrides `setFrame:display:`** and drops any size change that is not the user's live resize, a blessed call inside `resizeUnlocked:` (block-scoped and synchronous — a time-boxed unlock re-admitted the snap, and an animator's later frames would arrive locked out), or pre-visible setup. Every programmatic resize funnels through `SettingsWindowController.applyWindowFrame:`. The floor lives solely in `contentMinSize`; zoom is refused.

- **The pane's root view follows the tab view by autoresizing mask, never by host constraints.** The tab controller pins only the pane selected before the window existed; later selections set a frame and add nothing, so a pane without the mask collapses to its fitting size when selected second. `settings_open`'s `paneFillsTabView` is the oracle.
- **A real shared-size change is `paneContentDidChange`'s alone**: one `NSAnimationContext` at `kWindowResizeAnimationDuration` with implicit animation, inside which the remeasurement, the pane layout and a synchronous `setFrame:` through `applyContentSize:` all run. The target frame is computed from the engine's own numbers, since anything else is re-snapped by the next flush. **TRAP: the section stack must stay layer-backed** — implicit animation moves only layer-backed views, and plain headers would jump.
- **Both the tab and split controllers swallow `setPreferredContentSize:`**, since AppKit resizes the window immediately on it. A pane's size change therefore reaches the window only through `SettingsPaneSizeHost`, which the tab controller answers by re-setting `contentMinSize` and growing the window where needed.

## Panes

Rows are listed by the effect they must request.

**General.** Load last playlist on launch → `ReopenLastPlaylist`. Always on top → `AlwaysOnTop`, which also pushes the About and Settings windows' levels. Waveform drag and Artwork drag request nothing: each view reads the setting per gesture. Default music player: `DefaultAppRegistration` registers each audio type **one at a time**, since every request can raise a system panel and a refusal stops the walk; there is no alert of our own. **The folder declaration is excluded on purpose: Vibe must never become the default folder handler.**

**Audio Output.** Follows General in the sidebar (stable identifier `audio`). The Output list has a fixed-width glyph column followed by Name and Type columns; the type label and SF Symbol share one transport mapping. System Output uses a computer glyph. The list starts with System Output (the default policy, device ID -1) first, then the manager's device snapshot. Selecting a row calls `OutputDevicesMenuController.selectOutputDevice:`, the one funnel the Output menu uses too; the selected row follows the requested device ID, never its position in the changing list. It shares the other settings lists' neutral selection, and every row stays selectable whatever the mode. Device and system-default notifications reload the snapshot; programmatic reload/reselection is guarded so it cannot request a device. The player's settled callback reaches `SettingsWindowController.audioPane`, including changes made through the Output menu.

- **Declick**, first in the section (`AppSettings.declick`, default on, one choice for every device and every mode): whether a transport edge ramps over the 10 ms declick or cuts (`Audio/CLAUDE.md`). Always enabled. It requests only the `Declick` live effect, which pushes the choice to the player and rebuilds nothing.
- **Bit-perfect output** switch, below Declick (`AppSettings.bitPerfectOutput`) — **the switch is the selected device's own**: it and Exclusive output are remembered per device UID, so selecting another row shows that device's modes, every row stays selectable whatever the mode, and the list goes through `OutputDevicesMenuController.selectOutputDevice:`, which tracks outstanding selections until each player completion, including failure. **TRAP: until the bind settles, mode writes still name the old saved UID**, so both mode switches remain disabled while any selection is pending. The player queries the destination UID's modes before binding. Off deletes the device's stored mode rather than storing NO, and an unplugged device keeps its entry. **TRAP: building the pane tiles the output table before its first refresh, and AppKit, denied an empty selection, selects row 0 itself** — read as a request, that switched the output to System Output and persisted it on every first showing of the pane, so `loadAudioPane` holds `_refreshingOutputList` for its whole construction. It writes the setting, then requests `BitPerfect | FXControls | Crossfade`: the FX and crossfade branches, reading the derived `audioFXAllowed` and `effectiveCrossfadeMilliseconds`, are what withdraw the FX and drop the crossfade, the same path the FX switch and the crossfade popup take themselves. **Turning the switch on requires a nonempty persistent device UID and a device the mode can drive** (`VibeBitPerfectDeviceEligible`, `Audio/Mac/Devices/OutputFormatRules.h`) — never System Output, never Bluetooth or another transport off the allowlist. **The two ways that fails get two captions, because they need different remedies**: a requested id of -1 is the System Output policy, which names no device at all and whose own device may well be wired, so it says that row cannot be used; a concrete id off the transport allowlist says to choose a wired device. Telling a user with a wired DAC as their system output to "choose a wired device" is what sent #47 looking in the wrong place. Turning it off is always allowed, including when the saved device is absent at launch; on, the caption is the player's own report through `bitPerfectStatusText`, the same sentence the header's open lock shows on hover. The row and Output list refresh from the player's settled device callback as well as the pane's device observation (menu tracking can end before an asynchronous bind finishes), and follows the report through `refreshBitPerfectRows`, which `MainPlayerController` calls from `audioPlayerDidChangeBitPerfectReport:` — the pane has no playback observation of its own. **Verification trap: the debug channel refreshes the selected pane after every verb**, reads included, so a scripted check of this caption must screenshot as the first command after the transition settled, or the dispatcher's refresh masks a missing production one.
- **Exclusive output**, directly below Bit-perfect output (`AppSettings.exclusiveOutput`, default off), asks for exclusive device use while playing. Enabled only with bit-perfect output on and an eligible device whose HAL hog property is writable (`CoreAudioUtil.supportsHogModeForDeviceID:`) — the device that is currently the macOS system output is eligible like any other, and taking it moves the system default elsewhere (`Audio/Mac/Devices/CLAUDE.md`). Virtual devices follow the same check as physical devices; the caption distinguishes unsupported exclusive access from the other unmet conditions, and an ineligible selection reuses whichever of Bit-perfect output's own two captions applies. The saved choice is per device too and survives disabling bit-perfect output. It requests only the `BitPerfect` live effect, which sends both preferences together; it does not change FX or crossfade settings. Both rows refresh from the same report and device callbacks. `VIBE_ENABLE_EXCLUSIVE_OUTPUT=0` omits this row and its action (build flag documented in `Audio/Mac/Devices/CLAUDE.md`).

**Playback.** Track transitions groups track end and crossfade; Playback controls groups pitch, skips and audio effects; Track analysis groups detection. On track end → `EndOfTrack`. **TRAP: without it a mid-track switch to Pause leaves an armed gapless splice that advances anyway** — the effect re-parks or drops the successor handle. Pitch range and crossfade request theirs; skip-step presets are read at the next skip. Audio FX → `FXControls`: off clears all five effects and hides the FX menu and keys. Both directions apply the audio route live through the same rebuild as bit-perfect; the first enable creates the FX nodes. Bit-perfect output disables the FX switch and crossfade popup with an explanatory caption; `audioFXAllowed` withdraws the effects and `effectiveCrossfadeMilliseconds` holds fades at the declick minimum. The BPM and key toggles decide only whether a key is detected; how it is written is Appearance's.

**FLAC conversion lives in Files.** Enable FLAC conversion → `ConvertMenu`, which hides the Convert menu in place (`Mac/Menu/CLAUDE.md`) and disables the destination and Trash rows.

**Advanced.** The Audio group is `audioPathSnapshot` (`Mac/App/CLAUDE.md`), one row per stage in one shape — name · rate · depth · channels · status · latency, each column only where the stage has one, so the rows read across: the source's codec and declared depth; the decoder's output format and how the file reaches it; the bus's voices; the pitch, effects and meter a bare Off while the signal bypasses them, else at the format they carry (the bus's, else the output's) with On and what they add; the output's activity and IO buffer; the device's name, the rate and depth it runs at, the channels the output drives on it (not its stream's width), its bit-perfect or exclusive standing as the debug tags BP and Hog, and its own latency. Refreshed once a second off the queue while the pane is visible. Playhead refresh cap → `UIUpdateRate`. Cache size sums both stores, generation-guarded against a stale reply landing after Clear Cache. Reset to defaults preserves custom themes; Factory reset deletes them through `AppSettings.factoryReset`. Both use `resetToDefaults`, request `All`, select System Output through `OutputDevicesMenuController`, restore window shape separately and reload every pane. **TRAP: clearing the saved device UID while retaining the old binding leaves mode switches enabled for a device their setters cannot write to.** The shared selection path keeps the switches disabled until the reset's device change settles; a refused switch reannounces the retained device, restoring its saved UID before the controls re-enable. Reset enables while a setting differs from its default (`VibeSettingsAreAtDefaults`, `SettingsRules.h`); Factory reset also enables when custom themes remain. Stored themes alone are not a changed setting. **TRAP: the two window-shape settings are cleared with everything else and no pane shows them** — the reset must call `MainWindow.resetToDefaultShape` after `All`, or the window keeps a shape the store disagrees with and snaps at the next launch. The Build group reads from the bundle, not the catalog. **Debug info → Save…** writes `DebugInfo`'s report (`Mac/App/CLAUDE.md`) wherever the user picks in a save panel — the sandbox's user-selected grant, as Save Playlist uses — and reveals it in Finder; it requests no live effect, and the button stays disabled until the write finishes. **Audio**, last, lists the render chain stage by stage from `AudioPlayer.audioPathSnapshot` — source file, decoder, mixing bus, pitch, effects, level meter, output, output device — as one readout per row, refreshed once a second while the pane is on screen and on every pane refresh. The readouts are single-line and truncate, so a change costs the label's own layout and never a pane solve (the trap above); the debug channel's `dump_audio_path` and the debug report read the same model.

**About.** The identity block sits outside any card (`loadPaneWithSections:` stacks a plain view where a section would go); the icon opens the About window through the nil-targeted `showAboutWindow:`. The copyright is the About window's alone.

**A stored value matching no preset is snapped on read** by `AppSettings` (`SettingsRules.h`), not by the pane, so a hand-edited plist cannot show one value while the audio uses another.

## The Files pane

**When opening a folder** (`folderOpenSort`, the enum itself on `representedObject`) requests nothing and needs nothing: the order governs the *next* open, and re-sorting the playlist on screen would discard one built by hand. Both shells read it at open time (`Util/CLAUDE.md`).

**Album art** (`useFolderArt`, identifiers `file_only` and `file_then_folder`). **TRAP: the pane must request `FolderArt` after writing it** — the resolver caches the setting, and that effect is the one thing that drops the cache, so a write without it is not observed at all (`Audio/Metadata/FolderArt/CLAUDE.md`).

**Granted folders** is the alternating-row list over `FolderAccessManager` (`Mac/App/`). Every folder the user opens, drops or adds is an app-scoped security bookmark re-opened at launch. **A stored row is visible immediately but authorizes nothing until restoration has started its scope**, so a row carries a `VibeGrantedFolderState` and an unavailable one is dimmed and suffixed. The list multi-selects, so Remove Access takes a batch, and Edit > Select All reaches it through the responder chain. Persistence is the manager's own `VibeGrantedFolders` key — bookmark blobs, not `AppSettings`.

- **TRAP: never stat a row or a drag.** `viewForTableColumn:` runs on main per reload and drag validation per mouse move, and a dead mount blocks a stat for an automounter timeout. State comes from the manager's resolve, the icon is the generic folder icon, and folder-ness is asked of the **pasteboard** (`public.folder`, which also refuses a package during the drag). A folder deleted while the app runs reads active until the next launch.
- **TRAP: a Finder drag delivers file-reference URLs** — pin to `fileURLWithPath:`, the main window's trap.
- **TRAP: `getpwuid`, not `NSHomeDirectory`** (`Mac/App/CLAUDE.md`). Add Common Folder stages the real home, Documents, iCloud Drive or Dropbox in an open panel with nothing selected, since the sandbox grants nothing unpicked. Each item carries its own disabled reason, "Not found" or "Already accessible"; the not-found probes run off main, generation-guarded, because two candidates are provider roots where a stat blocks. An unavailable row is excluded from "Already accessible" — it is the folder worth offering again.

A playlist file grants that file alone, not the audio it names, so an unreadable entry raises `requestAccessForPlaylistFolder:` — the same picker and bookmark as Add Folder, **serialized on its own gate because powerbox prompts must not stack**, blocking the expansion worker. It lives here rather than in `NSURLUtil`, reached through the handler `AppDelegate` installs. The auto-add hook is the open funnel, `AppDelegate.openURLsWithRestoredAccess:token:`, bookmarking only directories outside an active grant and outside ~/Music, which the entitlement covers.

## Driving this window from the debug channel

**Never with `click`, `drag` or the `key*` verbs**: they post into the main player window's event stream. `settings_open`, `dump_settings_ui`, `settings_click`, `settings_resize` and `settings_close` address it structurally — pane by identifier, control by the name its row shows — and the `vibe-debug` skill documents them. Re-run `dump_settings_ui` after changing a pane's layout: a control kind the walker does not model, or a name two controls share, shows up there first.
