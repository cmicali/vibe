# Themes pane: the theme list and editor

The Themes pane (identifier `themes`) is `SettingsThemesViewController`. The Appearance pane is `SettingsAppearanceViewController` (`../AGENTS.md`). The Themes pane has two pages. The list page, the page swap, import, export and the drop target are in the class file. The editor page is two categories. `+Editor.m` builds it, with one builder per section. `+EditorActions.m` holds its layout state, its refresh and every row's action. `SettingsThemesViewControllerInternal.h` carries the editor's outlets, the list-side methods it calls and the actions the builders name. Scaffolding and sizing are `../AGENTS.md`. The theme record and its sanitization gate are `Common/Mac/Theme/AGENTS.md`, and the theme store is `Common/Mac/AGENTS.md`.

## The list page

The theme table has one column and no header. Each name carries its theme's swatch (`swatchForThemeIdentifier:dark:`): the window color behind three bars. The style picks the bars' colors (`WaveformRendererRegistry.swatchColorsForIdentifier:theme:`). They are the waveform color, 3-Band's bands, or Spectrum's palette. The active theme's swatch comes from its working record.

The theme list comes first, since its selected row is the current theme. Under it, the library's buttons lead (Add ▾, Remove, Export…) and the selected theme's own trail: Revert, shown only for a built-in that diverged, and Edit Theme… (Customize… for a built-in; both only open the editor). A diverged built-in also reads Modified on its own row. The editor's first edit of a built-in copies that working state into an editable theme. A Waveform card follows, with the quick waveform-style picker and a static preview.

- **Style is a THEME field shown outside the editor.** It is the same slot as the editor's Waveform style row, built by one helper, and each edit re-selects the other. It writes through the working-record funnel, so over a built-in it lands in the divergence key. The Type row is the editor's alone. It shows only for a style with types (`WaveformUI/Renderers/AGENTS.md`).
- **Both pages share one waveform preview image and refresh path.** The cache key includes the style, appearance, `paletteSignature`, gradient, playhead line color, density, width and levels. The signature covers every palette a style can paint, so a Spectrum palette or band well edit redraws it. Waveform edits refresh it directly, continuous sliders and color wells included. The sample has no artwork, so Album Art shows the palette's monochrome fallback.
- **Selection IS activation.** Clicking a theme row applies it (`applyThemeWithIdentifier:` and `ThemeApply`), as View > Theme does. The selected row is the active theme, with no checkmark. **A group header is an ordinary row the delegate refuses to select, not an AppKit group row.** That style adds a gap and its own height to a ten-row budget. The rows are `_themeRows`, rebuilt from the store order on each refresh: the User group first while the user has any themes, then Built-in. A header is a sentinel entry (`identifierForRow:` answers nil for it). The reselect after each reload scrolls, so an imported theme lands selected even past the fold.
- Add ▾ (New Theme, Duplicate, Import…), Remove and Export… manage the library. Remove acts on custom themes only, and theme undo restores a removal. Over a built-in it is disabled with a tooltip saying why. The Edit Theme… button, a row double-click and the menu all open the editor through the window's history (`showThemeEditor`). It records the theme list on the way in, so the editor's Back is the list however it was reached. Duplicate copies the working record and selects the new name for editing.
- **TRAP: the list's programmatic reload guards reentrancy** (`_refreshingThemeList`). `reloadData` and the reselect both post selection changes. Treated as activations, they recurse into a stack overflow.
- **Import and the drop are one funnel** (`importThemesFromURLs:`). The drop validates against the pasteboard's content types, JSON or ZIP. The pasteboard answers with a `getattrlist` per URL. Validation asks it once per drag, through the pane base's `pasteboardOfDrag:canReadURLsWithOptions:`. It retargets onto the whole list, since an import always lands in the user group. Files are read mapped, so the size gate refuses a huge pick without loading it. Each passes the same sanitize gate as `import_theme`. The last one is activated once, after the whole list. Failures are named in one alert.
- **Export** chooses ZIP or JSON from the record's artwork references (`AppTheme+Archive`). It reads images only after the panel confirms. Missing images are omitted from the ZIP. If none can be read, it writes plain JSON. A failed write reports the system's error.
- **Import and the image pick read the user's file off main**, since it can sit on a share or in iCloud. The record work and the alerts stay on main. Export still writes on main, like any save the user waits on.

## The titlebar controls

- **The light/dark preview toggle** (both pages) writes `AppSettings.windowAppearancePreviewStyle`, the transient override, never the stored style. The Appearance pane's Window appearance popup keeps showing the stored choice, and the two disagreeing is the feature. `viewDidDisappear` drops the preview, so leaving the pane and closing the window are one revert. Writing the stored style clears the preview. Under a single-mode theme the toggle disables. The item is inserted while the pane is selected and removed otherwise, never hidden. `NSToolbarItem.hidden` needs macOS 15, and the delegate vends non-inserted copies during enumeration.
- **Navigation is the window's history** (`../AGENTS.md`). The editor is the location `themes/editor`, so Back leaves it and Forward returns, as for any pane. Choosing Themes in the sidebar opens the list, even when Themes is already selected. The editor retitles the window `Theme: <name>` through the pane-title chain (`applyEditorTitle`, using the Name field's live text while editing). Every page swap reaches `updateNavigation`.
- **The dice control** rolls settings or colors (`AppTheme`'s two dice, `Common/Mac/Theme/AGENTS.md`) as a whole-theme `ThemeApply`. It is enabled on the editor page only (`editorShown`). Over a built-in the roll is its first edit, so it forks the theme.
- **The history control's two arrows undo and redo edits and removals**, renames included. It is its own toolbar item (`theme_history`), apart from the dice, so a missed undo cannot reroll the theme. Edit > Undo (⌘Z) and Redo (⇧⌘Z) reach the same store history while Themes is selected, on either page. A focused text field keeps its own text undo. `updateNavigation` keeps the arrows' state and names a pending removal in their tooltips. A new edit discards redo. Selecting a theme explicitly clears both directions.
- The toolbar sits outside the pane, beyond the walker. `settings_click` takes reserved names for it: `Back`, `Forward`, `preview light|dark`, `randomize settings|colors`, `undo` and `search`. They are routed through the models. `dump_settings_ui`'s `toolbar` reports each segment's enabled flag.

## The editor page

The editor is swapped in as a **sibling of the section stack**, and **scrolls inside whatever height the panes settled at**. `naturalPaneSize` takes its height from the base stack alone, so twenty editor rows cannot grow every pane. **Its WIDTH is not free.** The container is pinned leading to trailing in the pane and keeps that requirement while hidden. So the editor's widest row, the two-image Playlist button images cluster, sets the minimum width of the whole window (`../AGENTS.md`). A wider new editor row raises it.

**A jump bar sits above the page**: one capsule segment per card, in page order, with the cards' full headers as tooltips. The first, Theme, is the Name card, so it is the way back to the top. A click scrolls that card's header to the top through `SettingsPaneViewController.scrollCardToTop:animated:`, which the debug channel's `settings_reveal` also uses, clamped to the document's end. The selected segment follows every scroll (`editorDidScroll:`, from the clip view's bounds notification), and is synced by hand when the page shows, since no scroll fires then. It is the one way to a card without scrolling seventy rows.

Every row action is one helper: write the `currentTheme` field, call `currentThemeDidChange`, request the row's effect. Switches bind a typed field writer and their live effect at construction (`themeSwitchWithEffect:write:`).

- **TRAP: the document view is a FLIPPED stack** (`SettingsStackView`). Unflipped, the document's top is its maxY while the clip view keeps its bounds origin, so every relayout strands the page further under the toolbar. The scroll view keeps `automaticallyAdjustsContentInsets = NO`.
- **A built-in opens in the editor as it is, and its first edit copies it** (`forkBuiltInForEdit`, run by `themeFieldDidChange:` before it persists). The edit already sits in the working record. A duplicate of that record becomes the active theme through `applyThemeWithIdentifier:`, which also clears the built-in's divergence, and the page refreshes onto the copy. The image picker forks once it confirms, since the store refuses a built-in's images. A rename forks unless the name is the built-in's own. The Name row's caption says so while a built-in is open. The list page's quick style picker is not an editor edit, so over a built-in it lands in the divergence key.
- **Renaming is the Name field** (end-editing calls `renameUserThemeWithIdentifier:`), not inline in the list, which would collide with double-click-to-open. The name may come back deduplicated, so the pane reads it again.
- **The font rows drive the system font panel** onto a slot ivar. **TRAP: Select… parks first responder on the pane's view first.** A focused field editor is an `NSTextView`, which implements `changeFont:` and would eat the panel's sends. Beginning to edit the Name closes the panel for the same reason. The panel also closes when the editor page hides and when the pane leaves the screen (`closeEditorPanels`). The channel cannot drive it, so `import_theme` and `set_theme` are the scripted path.
- **Theme color modes is the theme's `mode`** (Light & Dark Modes or Single Mode). It is the theme's colors, not the window's appearance. Under Single Mode, `resolveLayoutStateFromSettings` collapses every Dark/Light well pair to the dark-keyed well, the one slot `AppTheme` reads and writes from either side. The light halves lie dormant, so flipping modes round-trips. Mode edits ride `ThemeApply`, which carries `WindowAppearance`, because a single-mode theme pins the window dark.
- **Every color well is bound to its pair once** (`wellForDark:base:effect:`). So one action, one refresh loop and one dark-first seed walk (`seedWellsIn:`) serve them all. Dark first is what lets single mode's slot take the dark default. Every popup that reveals color wells is one helper (`chooseFromPopUp:revealing:wells:effect:write:`). Revealed wells are **seeded from their displayed fallbacks**, so the window matches the wells at once. Every choice includes alpha except 3-Band's bands. **A choice that takes colors keeps its Dark/Light pair beside the popup, in one row**: the window and playlist backgrounds and tints, the volume bar and knob, and the playlist's switched colors. The pair hides while the choice takes no color, and single mode folds it to one well. Only the waveform's custom colors keep their own Dark colors and Light colors rows, since each side holds two or three captioned wells.
- **TRAP: a disabled color well deactivates only if it is active.** `deactivate` creates the shared color panel when none exists. Creating the panel can initialize Metal resources.
- **Default artwork** opens Player display: Artwork, Clear, Window, Symbol or Custom color (`defaultArtwork`; the Symbol choice is the record's `glyph`, the code's word for an SF Symbol name since the transport buttons). Artwork reveals the Image row, the placeholder pair's previews. Symbol reveals a symbol popup (`glyphPopUpWithGlyphs:action:`, the transport buttons' menu shape, over `SettingsRules.h`'s `VibeDefaultArtworkGlyphs`) with its color pair beside it, a Symbol name field for any SF Symbol the menu lacks (end-editing writes the free-text field; the popup's hidden item 0 then shows the name; a name this Mac lacks keeps a caption), and a size slider with a detent at the default. Custom color shows its pair beside the choice, seeded on the switch like the tints. The popup requests the image slots' effect plus `WindowChrome`, since Window moves the header's panel.
- **Show transport buttons** defaults on. It governs its section, the gradient included, and keeps the settings it disables. The default artwork lives in Player and stays editable. Track information keeps only the readouts' font and the info and time colors. They stay enabled whatever the app-wide readout switches say.
- **Corner radius** is Standard or Custom (`standardOrCustomPopUpWithAction:standard:`). Custom shows the slider beside the choice (`VibeDetentSlider`, with a magnetic detent at `kVibeThemeCornerRadiusDefault`). Under Standard the window draws the standard radius whatever the slider holds (`AppTheme.resolvedWindowCornerRadius`). The playlist columns' colors take the same shape: Automatic or Custom, with their wells beside it, seeded on the switch to Custom. So do the playing and selected rows' text colors, one per column, listed after their row's fill. Automatic keeps each column's own color. Their edits request `PlaylistRowColors`, as the fills do, not `PlaylistAppearance`. The cell rebuild clears the table's selection, so a selected row being previewed would vanish.
- **Waveform bar density and width** share slider setup, from 50% to 200% with a detent at 100%. The registry enables both for Bars, Cupertino, Sonic Cirrus and Wiggle, and width alone for Progress, where it sets pill height. Other styles keep the stored values dormant. Continuous edits coalesce into one undo and request `WaveformStyle`, which updates the existing renderer live.
- **Under 3-Band the band wells replace Waveform color.** The editor hides `waveformTheme`'s popup and its Played and Unplayed wells. It shows Low, Mid and High wells per appearance, and Shade overlaps. The wells show their displayed fallback, Rekord Bin's bands, which is what draws, so nothing is seeded. Under Spectrum the editor hides the waveform color and shows Spectrum's palette popup: RGB, Blue, Green and Custom. It also shows the Coloring popup, By section or Precise, which requests `WaveformTheme` as the palette does. Custom reveals the same band wells, unseeded, as 3-Band shows them. `WaveformRendererRegistry.paletteKindForIdentifier:` decides which of these rows show. **A style's own settings sit right under Waveform style**, above the preview: Detailed's Type, Spectrum's Coloring and 3-Band's Shade overlaps. The color rows stay below the preview, since every style has one. The record stores them opaque, so their wells offer no alpha on macOS 14 and later. On macOS 13 the shared panel's alpha is stored opaque.
- **Playhead line** follows Waveform gradient. The switch is `waveformPlayheadLine`, and on, it reveals Playhead color, a Dark/Light pair that collapses under Single Mode like the others. Both request `WaveformTheme`. The wells show the pair's displayed fallback, which is what the line draws, so nothing is seeded.
- **An image field is a preview, not a popup.** Each slot is one image button, keyed by field on the button's `identifier` (`imageClusterForKey:`), showing `previewImageForKey:`'s resolved image. A click opens the JPEG/PNG panel. The pick is read off main, then stored through `storeCustomImageData:`. **TRAP: the slot can change while the file reads.** Each pick holds its slot's token (`_imagePickTokens`). A later pick replaces it, and a clear or a glyph drops it. A read that lands without its token stores nothing. Hover reveals a clear badge **only while the slot holds a custom image** on an editable page. Clicking the badge writes the slot back to `""`. The hover rides tracking areas (`ActiveInActiveApp`, so it works while the color panel is key). Posted debug events cannot fire them, so a scripted clear needs a real hover through the `vibe-debug` skill's `input.swift` before `settings_click "Clear custom image"`. Each slot's edit requests its own effect (`VibeThemeImageEditEffect`).
- **A transport button is a glyph popup with a color pair, or a picture** (`buttonRowsForImageKey:`). The card's second row is one explainer line, that the buttons follow the artwork behind them and not the appearance, so each well's caption is two words, Dark art or Light art. The popup lists `SettingsRules.h`'s curated SF Symbols as glyphs alone, with the symbol name only in an item's tooltip. It ends in Custom image…. A JSON-authored glyph the menu lacks shows through a transient item. The color row and the image row swap on whether the button holds an image. **A button's On dark artwork and On light artwork wells follow artwork brightness, not appearance** (`MainWindow/LAYOUT.md`). So they and the image pairs stay two-sided under Single Mode (`artKeyedColorPairForBase:`, `artKeyedImagePairForDarkKey:lightKey:`). **A glyph pick retires the button's image**, since the image wins while set. A play pick also writes the pause glyph (`VibePauseGlyphForPlayGlyph`). `AppTheme.setGlyph:forButtonImageKey:` owns that mutation. Play has an image row per state, and an unset side draws the other's. Every button edit and the Button gradient popup (None, Show on hover, Show on artwork, Always) request `TransportButtons`. The App icon preview and the icon-shape switch request `AppIcon`.
- **Volume slider** sits after Track information. Location is Top right or Bottom. Its caption says the corner slider swaps with the track information on hover. Show is `volumeVisibility`: Always, On hover (close) or On hover (exact), with close the default. Then come Show labels, Bar color (`volumeBar`: None, Artwork color, Waveform color or Custom, with Waveform color the default and Custom's wells revealed like the window tint's) and Knob color (`volumeKnob`: the same four plus Same as bar, its default). The rows request `Volume`, except the two colors' wells. Both colors re-resolve with every waveform theme resolution, so a well drag requests the lighter `WaveformTheme` rather than Volume's relayout.

In the debug channel the theme table is addressed by its `#index` from `dump_settings_ui`, because the card's header labels every control in it. **Header rows take indices of their own**, so read the row off `rows` rather than counting themes. Assert activation through `dump_state.settings.activeTheme`.
