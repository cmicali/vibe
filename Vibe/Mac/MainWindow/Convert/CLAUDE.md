# Convert to FLAC: the swap and its undo

`Audio/Mac/Convert/` is the engine and the file round trip; this category is what happens in the playlist when a conversion finishes and when it is undone. The controller is `../CLAUDE.md`.

**The FLAC takes the row its source occupied.** `didConvertTrack:toURL:error:` resolves the rows at completion, not at start, since a mid-encode re-drop replaces the playlist: no row → nothing, the FLAC stays on disk; every row holding the source is swapped, since the same file can sit in the playlist twice; the current row replays with its captured intent. **The playlist entry is swapped before the replay** (`AudioPlayer.play:atPosition:startPaused:`), so `didStartPlaying:`'s identity guard passes and the ordinary per-track refresh comes free. Currency is the current row's, not the converted object's: a same-URL duplicate made current mid-encode must not be swapped out from under the player.

**`Playlist.replaceTracksMatchingTrack:withURL:` mints a fresh `AudioTrack`**: `AudioTrack` memoizes its cache key with no invalidation, so a track still carrying the WAV's key would file the FLAC's waveform and metadata under the WAV's entries. Duration and detected BPM carry across by hand, or the row blanks until the new decode lands.

**Disposing of the source is the last step, and the ordering is the point**: the converter preflights the placed FLAC, the controller swaps, then calls `trashSourceIfEnabled:convertedTo:` — the swap is what stops the row and the player pointing at the file about to go. The source URL is read before the swap, pinned to a plain path (`../CLAUDE.md`'s file-reference trap), and the trash runs whether or not a row was found. A same-path output is refused before the swap, so no undo action can have the same file on both sides. The disposal completion is where the conversion becomes undoable: a `VibeFLACConversionRecord` with each file's current location (`ExpectedPath`, `KnownTrashURL`, `UnknownTrashURL`), registered as "Convert to FLAC" on the window's `NSUndoManager`. The move outcome, never URL presence, decides whether the source was trashed.

Progress is the waveform's sweep, forwarded to `trackDisplay.setConvertSweepFraction:` **only while the converting track is `displayedTrack`**.

**One undo/redo transaction may be in flight at a time.** The controller reads `AudioFileConverter.isUndoRedoInFlight` to disable both items and reject action entry points until the restore/trash chain settles, so rapid commands cannot interleave file moves against one mutable record. `AudioFileConverter.registerUndoForConversion:undoManager:swap:completion:` owns the common inverse — register the opposite action synchronously, restore and verify, ask the shell to swap surviving rows, dispose of the retired file (`Audio/Mac/Convert/CLAUDE.md` for its location and failed-inverse rules). The shell supplies `swapConvertedTrack:toURL:` and the completion that refreshes state, reports failure, reveals a stranded Trash item and consumes the debug settlement handler. `VibeFLACSwapPlaybackIntent` preserves playhead and paused/playing intent only for a loaded current row; a stopped or noncurrent row never starts playback.
