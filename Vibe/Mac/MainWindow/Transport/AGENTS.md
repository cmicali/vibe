# Transport: bare keys, skips and FX toggles

`TransportKeyMonitor` handles the bare keys; `MainPlayerController+Transport` is the skips and the five effect setters; `TransportMath.h` is the skip arithmetic, tested. The controller is `../AGENTS.md`, the menu twins `Mac/Menu/AGENTS.md`.

**Keys are remappable and matched by physical key.** The defaults are Space, B, N, P, Tab; A/S/D skip forward, Z/X/C back; the playlist's Return and Delete; and the dual-mode effect keys Q, W, E, R, T (R = 1/8-note delay taps, T = 1/16). The monitor matches a keyDown's key code and exact ⌘⌥⌃⇧ set against `ShortcutRules.h` over `AppSettings.shortcutOverrides`, read per keypress, so the A/S/D row skips under AZERTY and Greek alike; the characters a layout types never move a key-code binding. The character defaults (⌘O, ⌘S, ⇧⌘C, ⌥⌘S, ⌘R) match by the character typed: under Command the layout's ⌘-layer letter (`characters`) first, so Dvorak – QWERTY ⌘ and Greek agree with the menu bar, then the unmodified one, since Option bends the typed letter (⌥⌘S types ß); `VibeShortcutCommandForPress` is that whole match, reserved shortcuts included. Every command but the effect keys goes through `performMenuCommandWithIdentifier:` and `MainPlayerController.performMenuItem:`, so its menu validation applies. **A disabled command swallows its key** — that is what keeps Play Selected and Remove dead over a collapsed playlist — **while a hidden one passes it on as unbound** (Convert to FLAC bound to K with Convert switched off). **Only Next, Previous and the six skips honor hardware repeat**; a held Space, P, Tab or ⌘R would flutter. In the player window the monitor applies that to every binding; elsewhere the menu bar performs a binding and AppKit repeats it, so the monitor swallows the repeats of a non-repeating Command binding there and nothing else, since a bare key there may be typing. **A tap toggles, a hold is momentary**: the effect flips at keyDown, and keyUp reverts when the press ran past the ~0.35s threshold. **keyUp decides tap vs hold**, matched by the key code remembered at keyDown so a modifier released first cannot hide the release, which is why the menu items' key equivalents are display and fallback only.

**Some keys are never bindings.** The fixed system shortcuts pass on even when a key-code binding lands on one after a layout switch (⌘Q wins), and so do the arrows, Escape and every keypad key but Enter, which a menu cannot draw apart from the main keyboard's (`VibeShortcutIsReserved`).

**The FX keys act only while this run has an `AudioFX` controls object and `AppSettings.audioFXAllowed` is true (the FX setting with bit-perfect output outranking it).** Turning the setting off clears all five live states and stops the monitor changing FX at once, and the player disconnects the FX segment in the same output-stopped rebuild; the menu builder drops the fallback equivalents and validation disables the items. **The five effect setters are the single funnel** for menus, keys and debug commands; each calls `updateFXIndicators`, which re-reads the live `AudioFX` flags rather than the caller's intent. The codec line is the indicator (`../APPEARANCE.md`).

**The playlist keys are dead while the playlist is collapsed** — the physical Return, keypad Enter, Up and Down arrows, Backspace and Forward Delete, unmodified, whatever is bound to them, and Play Selected and Remove wherever they are bound. The table keeps focus off screen when the window shrinks, so the monitor swallows them rather than passing them on: an unhandled key reaching the focused table wedges its input context. Showing, the arrows go to the table's `moveUp:`/`moveDown:` and Return plays the selection through `PlaylistController.playSelectedTrack`, the double-click's two steps. The monitor acts only on the player window's own events; Play Selected Track and Remove from Playlist validate on `hasVisiblePlaylistSelection` — player window key, playlist showing, a row selected — so a Return or Delete falling through to their key equivalents from Settings or About cannot act on an invisible playlist.

**Backspace and Forward Delete are the delete pair**, removing every selected row through `removeSelectedPlaylistTracks:`, the Edit menu's target. Remove **ignores hardware repeat**: a held delete takes one gesture's rows rather than walking the playlist. Keypad Enter and Forward Delete fold into Return and Delete (`VibeShortcutCanonicalKeyCode`), so a binding of either answers both. The menu advertises Backspace alone, as `NSBackspaceCharacter` (what AppKit draws as ⌫; a real press delivers `NSDeleteCharacter`); Forward Delete is a physical twin only the monitor knows.

[TransportKeyMonitorTests](../../../../Tests/TransportKeyMonitorTests.m) runs the real monitor handler with constructed key events and duck controller/window collaborators: tap/hold, repeated downs, releases lost to focus/menu/window tracking, disabled FX, Delete-repeat suppression, remaps, layout-independent matching, the collapsed swallow, the character defaults held and under other layouts, repeats outside the player window and a hidden command's key passing on. `ShortcutRulesTests` covers the rules themselves. The native callback supplies `event.window` to `handleKeyEvent:inWindow:`; tests supply identity directly without creating a window or posting input.

**Skips seek by bars when the tempo is known** — tagged beats analyzed, the BPM label's precedence — at `AppSettings.skipBaseBars` (4, 8 or 16), twice it and four times it; bars are file time, so the jump stays on the grid at any pitch. Without a tempo: 10/30/60 wall-clock seconds. A forward skip past the end calls `AudioPlayer.finishCurrentTrack`, so the ordinary track-end path handles it. **Skips need a player that is not Stopped, gated in both `skipByFileSeconds:` (the debug verbs call it directly) and menu validation: after the playlist ends the finished file stays open, so `duration` alone still looks seekable while no voice exists.**
