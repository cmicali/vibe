# Transport: bare keys, skips and FX toggles

`TransportKeyMonitor` handles the bare keys; `MainPlayerController+Transport` is the skips and the five effect setters; `TransportMath.h` is the skip arithmetic, tested. The controller is `../CLAUDE.md`, the menu twins `Mac/Menu/CLAUDE.md`.

**Keys.** Space, B, N, P, Tab; A/S/D skip forward, Z/X/C back; the playlist's Return, arrows and delete keys; and the dual-mode effect keys Q, W, E, R, T (R = 1/8-note delay taps, T = 1/16). **A tap toggles, a hold is momentary**: the effect flips at keyDown, and keyUp reverts when the press ran past the ~0.35s threshold. **keyUp decides tap vs hold**, which is why the menu items' key equivalents are display and fallback only.

**The FX keys act only while this run has an `AudioFX` graph and `AppSettings.audioFXAllowed` is true (the FX setting with bit-perfect output outranking it).** Turning the setting off clears all five live states and stops the monitor changing FX at once, though the graph itself waits for relaunch; the menu builder drops the fallback equivalents and validation disables the items. **The five effect setters are the single funnel** for menus, keys and debug commands; each calls `updateFXIndicators`, which re-reads the live `AudioFX` flags rather than the caller's intent. The codec line is the indicator (`../APPEARANCE.md`).

**The playlist keys are dead while the playlist is collapsed** — Return, keypad Enter, the arrows, Backspace and Forward Delete. The table keeps focus off screen when the window shrinks, so the monitor swallows all six rather than passing them on: an unhandled key reaching the focused table wedges its input context. Showing, the arrows go to the table's `moveUp:`/`moveDown:` and Return plays the selection through `PlaylistController.playSelectedTrack`, the double-click's two steps. Play Selected Track, Remove from Playlist and the bare keys all validate on `hasVisiblePlaylistSelection` — player window key, playlist showing, a row selected — so a Return or Delete falling through from Settings or About cannot act on an invisible playlist.

**Backspace and Forward Delete are the delete pair**, removing every selected row through `removeSelectedPlaylistTracks:`, the Edit menu's target. They are the one bare-key pair that **ignores hardware repeat**: a held delete takes one gesture's rows rather than walking the playlist. The menu advertises Backspace alone, as `NSBackspaceCharacter` (what AppKit draws as ⌫; a real press delivers `NSDeleteCharacter`); Forward Delete is a physical twin only the monitor knows.

[TransportKeyMonitorTests](../../../../Tests/TransportKeyMonitorTests.m) runs the real monitor handler with constructed key events and duck controller/window collaborators: tap/hold, repeated downs, releases lost to focus/menu/window tracking, disabled FX and Delete-repeat suppression. The native callback supplies `event.window` to `handleKeyEvent:inWindow:`; tests supply identity directly without creating a window or posting input.

**Skips seek by bars when the tempo is known** — tagged beats analyzed, the BPM label's precedence — at `AppSettings.skipBaseBars` (4, 8 or 16), twice it and four times it; bars are file time, so the jump stays on the grid at any pitch. Without a tempo: 10/30/60 wall-clock seconds. A forward skip past the end calls `AudioPlayer.finishCurrentTrack`, so the ordinary track-end path handles it. **Skips need a player that is not Stopped, gated in both `skipByFileSeconds:` (bare keys bypass validation) and menu validation: after the playlist ends the finished file stays open, so `duration` alone still looks seekable while no node exists.**
