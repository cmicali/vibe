# Main window (macOS)

**Layout geometry, the Liquid Glass chrome, the art-tint pipeline and the codec line are `APPEARANCE.md`, beside this file — read it before changing any of those.** This file is behavior: the controller, display states, the playlist edits the shell owns, and the window's resize and drop rules. `Transport/` (bare keys, skips, FX toggles) and `Convert/` (the FLAC swap and its undo) carry their own `CLAUDE.md`.

## The controller

`MainPlayerController` (`NSWindowController`) is the coordinator. `MainPlayerController.m` keeps the `updateUI` funnel, display-state resolution and the open and playlist entry points; each `MainPlayerController+*.h` preamble states what its category owns. **A method a category implements is declared in that category's header**, never in `MainPlayerController.h` or `MainPlayerControllerInternal.h` (the shared class extension: outlets, collaborators, the ivars a category touches), or the compiler cannot check either side. `+Debug` is declared in `Vibe/Debug/Mac/Introspection/`, never here.

**Menu identifiers and the domain that decides each are `MenuValidationRules.h`** — one `kVibeMenu*` constant per identifier and the literal nowhere else, so a rename that misses a site fails the build. **TRAP: an identifier that reaches Unknown is DISABLED, not enabled** — a new controller-targeted menu item must be added there, or it silently skips validation.

**`+PlayerEvents` and `+Delivery` implement the root doc's staleness guarantee**: every callback can be stale and must match the delivered track against the playlist's current one, and `stop` fires no callback. The decisions are seams, both tested: `PlaybackDeliveryRules.h` (track-end advance, seek settlement, the deferred-metadata gate) and `AudioErrorRules.h` (benign and wrong-URL errors).

## Folder art invalidation

`FolderArtResolver` (`Audio/Metadata/FolderArt/`) is the feature; this controller owns invalidation and redraw. The `FolderArt` effect calls `refreshFolderArt` → `folderArtSettingDidChange`: **the resolver caches the setting on the cell-draw path, so this effect is what makes a write observable at all**, and it keeps settled answers. A grant change (`FolderAccessManagerDidChangeNotification`, observed here because a grant can change with the Files pane gone) is narrower: `invalidateDirectoriesSettledWithoutGrant` forgets no-grant answers and re-arms known cover reads. `folderArtDidResolve:`, fired for "none" as well as a cover, coalesces a visible-rows-only reload over a short delay, because the resolver is serial and a per-turn gate would coalesce nothing. Neither may be a full wipe (`Audio/Metadata/FolderArt/CLAUDE.md`).

## The UI tick

Listening statistics follow `audioPlayer:didChangeOutputAudioActive:` and its current snapshot, just as the equalizer does. This includes outgoing fades, excludes silent Loading time, and replaces transport-callback bookkeeping. Quit still flushes the clock in the app delegate.

`UIUpdateTimer` (`Vibe/Util/`) drives `updatePlaybackUI` only while playback wants updates and the window is unoccluded; `windowDidChangeOcclusionState:` pushes the gate and refreshes once on reveal. The full `updateUI` runs on transport events and metadata deliveries, and its header work is one phase, `renderTrackPresentationForState:track:displayTrack:`, all against one display-state decision. A recovered thumbnail takes that path only when its exact metadata object is still displayed. Rate and position updates stay separate so they reload no artwork or rows. A same-track refresh reloads no row (`_lastReloadedTrack`): the gutter's three states reconcile on their own edges (`Playlist/Mac/CLAUDE.md`).

**The tick rate follows the playhead's on-screen speed.** `syncUITimerRate` feeds the waveform's `devicePixelWidth`, the duration and the varispeed rate to `VibeUIUpdateHzForPlayhead` (`Util/UIUpdateMath.h`, tested): the Hz that steps the playhead about two device pixels, floored at 3 and capped by `AppSettings.uiUpdateHzCap`. **Every input mover must call the sync** — track start, transport events, fader ticks (`updateRateDependentUI`), `windowDidResize:` including live-drag frames, and the cap. `check_consistency`'s `ui.update_rate_follows_inputs` catches a mover that forgot. The rate is affordable because `AudioWaveformView.setProgress:` repaints only on device-pixel crossings and the time labels are change-guarded at one second.

## Track end, close and save

**Whether a track end advances is `AppSettings.pauseAtTrackEnd`, enforced at both places an end can advance from**: `successorPrefetchTrack` for the audio (nil under Pause, so no gapless splice is armed) and `advanceOrParkAtTrackEnd` for the shell (re-reads the setting, since it decides from `hasNextTrack` alone). Root `CLAUDE.md` carries the guarantee.

**File > Close (⌘W, `closeFile:`) is nil-targeted**: the key window's target owns the action and the shared item's title. The player retitles it Close File / Close All Files and enables it for a nonempty playlist; Settings and About restore the singular and close themselves. The player's action calls `AudioPlayer.stop` (no delegate event), clears the playlist, cancels the deferred metadata load, and drops the scan loader with `cancelScan` — **a cancelled loader still strongly holds every queued track**.

**File > Save Playlist… (⌘S) validates on the player window being key and the playlist nonempty**, since its sheet attaches here and ⌘S over Settings must not raise one behind it. `writePlaylistToURL:error:` is the one write path (snapshot at OK, relative to the chosen folder, atomic, noted in Open Recent), shared with the `save_playlist` debug verb.

## The last playlist

`AppSettings.reopenLastPlaylist` (off by default) mirrors the playlist to `Application Support/<bundle id>/LastPlaylist.m3u` at quit and reopens it at launch. `PlaylistFile` owns the session save and restore with explicit URL and defaults inputs: a failed save removes both the old mirror and the cursor, and restoration clamps a negative cursor to the first row and an oversized one to the last. `saveLastPlaylist` writes absolute paths, never Open Recent, with the current row in the `VibeLastPlaylistCurrentIndex` defaults key (state, not a preference, so a factory reset leaves it), and deletes the mirror when the setting is off or the playlist is empty; turning the setting off deletes it at once (`applyReopenLastPlaylist`). `restoreLastPlaylist` lands **parked** — `loadURLs:selectingIndex:startPaused:YES`, the replacement path `play:` also takes. Every row comes back, readable or not: the mirror is read through `PlaylistFile.fileURLsInM3UData:`, not the open funnel, so nothing is stat'd and no grant panel is raised. `AppDelegate` calls it only after grants restore and only when no launch-time open drained (`Mac/App/CLAUDE.md`). A cloud-only current track downloading at launch through the ordinary parked refresh is accepted, not special-cased. **The app does not opt into sudden termination**: every quit must reach `applicationWillTerminate:` for the write, and `NSSupportsSuddenTermination` would make an idle quit a SIGKILL.

## Removing playlist rows

`removePlaylistTracks:` is the one funnel: the Edit menu and the two delete keys act on the whole selection (`PlaylistController.selectedTracks`), and the row context menu arrives through `removeTracksRequestHandler`. It receives exact `AudioTrack`s and resolves each live row once, so shifted objects are followed and departed ones drop out. **`Playlist.removeTracksAtIndexes:` touches no audio, so the playback consequences are decided here** (root `CLAUDE.md`), and **the source files are never touched**. The method's inline comments carry each step and its rationale; the shape is resolve once, treat removing every row as `closeFile:` rather than an edit, resolve the ordered intent through `AudioPlayer.getPlaybackIntent:forTrack:` before mutating, one model call and one event, leave a surviving current identity's audio alone, and submit a removed current row through the play funnel so its old settlement dies on `submittedPlayIsCurrent:`. Nothing synthesizes a delegate callback or treats a removal as a track end.

**A removal is undoable as the list edit it is.** The funnel registers `reinsertPlaylistTracks:atIndexes:generation:` under the item's action name. Undo restores the exact objects to their rows, selected and revealed, metadata re-requested through `loadMetadataNow:` since removal abandoned their scan work — and never replays a removed current row. **The registration is stamped with `PlaylistController.structureGeneration`**, which forwards the model's own generation, bumped by every replace or clear before its announcement, so a restore whose playlist was replaced dies quietly; its redo no-ops in the funnel's guard and the dead pair falls off both stacks. `levelsOfUndo` is capped so dead registrations cannot pin tracks unboundedly. Whole-playlist removal routes to `closeFile:` before registering, so Close stays un-undoable. **Re-prefetch after a removal, a restore or an append (`reconcileAfterPlaylistStructureEdit`) is gated on a not-Stopped player**: a Stopped player advances nothing, so an errored player must not open or download a successor over a list edit.

## Reordering playlist rows

The drag is `Playlist/Mac/CLAUDE.md`'s. This side owns **`playlistOrderDidChangeHandler`, a reorder's entire follow-up**: register the inverse, re-park through `successorPrefetchTrack` behind the same not-Stopped gate, refresh the metadata neighborhood once, `updateUI`. **A move never enters a play funnel**: the current object survives at its new row, so a Loading row keeps its pending play and a paused row stays paused, with no Open Recent, waveform, artwork or stats work. `prefetchTrack:` already unqueues a parked wrong successor.

**The handler is the ONE undo registration point.** The model op is its own inverse — the two sets swapped — so the handler registers `movePlaylistTracksFromIndexes:toIndexes:generation:` under `STR_MENU_EDIT_REORDER`, and because it fires for every completed move, drag, undo and redo alike, `NSUndoManager` chains undo and redo with no second path. The registration carries bare row sets, kept exact by **LIFO plus the generation**: every undoable edit between a move and its undo has been unwound, and no un-undoable edit shifts rows without replacing the list (appends extend, the convert swap keeps its row, Close and every replacement bump `structureGeneration`). A stale restore performs no move and registers nothing.

## Display states and time labels

**All header rendering resolves through one five-state `TrackDisplayState`** — track, loading, empty, launch-grace, error — decided in `displayState` (`TrackDisplayRules.h`, tested) and shared by `updateUI`, `updatePlaybackUI` and the Now Playing publish. `TrackDisplayController` draws it and holds no player or playlist state.

- **Loading**: the incoming tags and `--:--`. The waveform's loading line starts only when the player's 0.5s slow-open threshold fires `didBeginLoading:`, so a fast play never flashes it.
- **Empty**: midline placeholder, `--:--`, the drop hint, at half strength. The `revealEmptyState` launch grace suppresses it, so a launch-time open never flashes it.
- **Error**: inline, no modal, no auto-skip. `displayedTrack` masks the errored track through `_erroredTrack`/`_errorStatus`, written only via `setErrorMaskForTrack:status:` and `clearErrorMask`; the track stays for a retry, and late deliveries are ignored while masked.

`currentTheme.showTimeLabels` hides both time fields in the full display-state render, including their click target; updates still carry the current position and duration, so revealing them is immediate. The right time label shows duration or minus-prefixed remaining, toggled by click and persisted in the theme's `showRemainingTime`. Both are wall-clock (file time over the varispeed rate), and **every write goes through `renderRightTimeLabelWithDisplayPosition:duration:rate:`**, which delegates rate adjustment, remaining-time subtraction, clamping and the whole-second string cache to `Formatters.durationStringForFileDuration:rate:elapsedDisplayTime:remaining:`; `VibeTrackTimeMayUpdate` keeps placeholder states intact. The tick skips the label when the duration cache is 0, or the end-of-playlist park would read `-0:00`.

**Now Playing** publishes the same wall-clock position and duration, rate 1.0 playing and 0 paused, and nothing until the first real play — `NowPlayingController`'s rule (`System/CLAUDE.md`). Artwork reads non-blocking: `cachedArt`, else the 128px `cachedThumbnail`, refreshed when the full art resolves.

## The window

Undo and Redo forward from the window to its controller so responder-chain menu routing retains the conversion-in-flight guard.

**The height has a second floor that is a band.** A playlist pane under `kPlaylistPaneMinHeight` is a sliver, so nothing rests between `kMainWindowSmallHeight` and `kMainWindowMinLargeHeight`: `restingHeightForDraggedHeight:` sends a drag to the nearer end and `loadSettings` clamps a restored frame out of it. The rule reaches drags through `windowWillResize:toSize:`, **gated on `inLiveResize`** so the app's own animated resizes are not snapped mid-flight. All three programmatic resizes use one fixed `animationResizeTime:` (`kWindowResizeAnimationDuration`) rather than AppKit's distance-scaled default.

**The pitch-panel toggle is the one resize the two `contentView` siblings must not follow** — the reveal is the right edge sweeping past a stationary panel — so `togglePitchPanel:` swaps in fixed masks for the animation and restores the resizable ones after.

**TRAP: a Finder drag delivers file-reference URLs** (`file:///.file/id=…`), whose `.path` re-resolves to wherever the file *is*, while everything downstream treats a track's URL as fixed: cache keys hash it, and the convert-undo record restores to it. Unpinned, a converted source's URL follows the file into the Trash and the undo restore becomes a move onto itself. **Invisible when testing with `open`.** Every drop is pinned to `fileURLWithPath:` in `performDragOperation:`, and `didConvertTrack:` pins the undo record's source again.

A drop resolves the empty-state wells into append-or-replace **synchronously**, since the dragging session is gone by the time the expansion lands, then hands the URLs to `AppDelegate.openDroppedURLs:appending:`, the one open funnel (`Mac/App/CLAUDE.md`).
