# Main window

## Layout and chrome

- Programmatic layout, no nibs, absolute frames + autoresizing masks: every number lives in one named layout block at the top of `MainPlayerContentView.m`; frames are authored at the design size (`kMainWindowContentWidth` × `kDesignHeight`, edge-reaching values derived from the width) and each subview's mask says how it stretches from there to the user's window size. One overhang is deliberate and named: the header glass panel bleeds `kHeaderPanelRightBleed` past the window's right edge so the window shape clips its right-side corner arcs off-screen — the glass rounds all corners uniformly, and without the bleed the header's right edge shows visible curves instead of running square to the edge. `MainWindow` configures itself in `init` (borderless, frame autosave, drag-and-drop registration); the main-window view hierarchy lives in `MainPlayerContentView` (a plain transparent `NSView` exposing the subviews as readonly properties — the window's glass backdrop provides all background; the backdrop and the pitch panel are the two exceptions, installed by the controller as `contentView` siblings), which `MainPlayerController` adopts as its outlets in `buildContentInWindow:` (called from `init`; `windowDidLoad` is invoked manually since AppKit only fires it on the nib path). Playlist cell views are built in `PlaylistTableView` (`makeCellViewWithIdentifier:`) and recycled through the table's normal reuse queue.
- Window chrome is Liquid Glass (macOS 26+ `NSGlassEffectView`), three layers with different jobs. (1) `buildContentInWindow:` installs a window-spanning glass backdrop (style **Clear** — very transparent; pitch panel included) behind everything. (2) The header/waveform area gets its own **Regular**-style glass panel in `MainPlayerContentView` (Regular is the `NSGlassEffectView` default — no explicit `.style` to grep for) plus `headerTintView`, a passthrough layer view washed with the current track's dominant art color — computed by `NSImage+Util`'s `dominantColor` (saturation×brightness-weighted hue histogram; monochrome art falls back to its average gray) and applied by `ArtworkDisplayController`, which also owns the art view, dock icon, and deferred art loads. The wash is deliberately NOT the glass's own `tintColor`: AppKit silently discards a glass view's tint whenever the window isn't key (no public override), whereas the design keeps the window as close to key-state-independent as public API allows: the app-controlled pieces (header tint wash, playlist frost via `NSVisualEffectStateActive`) never dim, while the glass views' own subtle inactive dimming is accepted — there is no public opt-out (`isKeyWindow` overrides don't affect it, only the private `resignKeyAppearance` does — verified by pixel-diffing active/inactive captures — and private API is off-limits: App Store). Tint changes fade over `kVibeArtCrossfadeDuration` (shared with the art crossfade in `CrossfadingImageView`). (3) The playlist sits on a behind-window `NSVisualEffectView` frost (`UnderWindowBackground` in BOTH appearances — the light `WindowBackground` material is effectively opaque paint — with a brightening white wash in light mode only) — row text isn't readable over Clear glass. TRAP: never give an `NSGlassEffectView` height-flexible autoresizing in a user-resizable window — its SwiftUI hosting internals fight the resize and the window silently refuses to change height (the playlist frost is an `NSVisualEffectView` for exactly this reason). Width-flexible is fine: both glass views are `NSViewWidthSizable` and drag-resize cleanly. All corner rounding shares `kMainWindowCornerRadius` (Constants.h, 20pt = the macOS 27 standardized window radius): the contentView layer mask, both glass views, the header tint layer, and the pitch panel's right-edge path.

## Controller, transport, and Now Playing

- `MainPlayerController` (NSWindowController) is the central coordinator. It implements `AudioPlayerDelegate`, `AudioWaveformViewDelegate`, `AudioWaveformCacheDelegate`, `AudioTrackMetadataCacheDelegate`, and `FileDropDelegate` — all in the class extension; the public header exposes only collaborators, actions, and `NSMenuDelegate` (public so `MainMenuBuilder` can wire the controller as the waveform-style submenu's delegate). Several pieces are split out of the main file: menu validation and the delegate-built waveform-style submenu live in `MainPlayerController+Menus` (`NSMenuItemValidation` conformance is declared on that category), the system Now Playing bridge (the `updateNowPlaying` publish and the `NowPlayingControllerDelegate` command routing) lives in `MainPlayerController+NowPlaying` (same conformance-on-category pattern), the relative-seek skips and the DJ effect toggles live in `MainPlayerController+Transport` (their declarations too — the category header, not the main one; they touch only public collaborators), and the bare transport keys (Space/B/N/P/Tab, plus A/S/D forward / Z/X/C back for skip-seek, and the dual-mode effect keys Q/W/E/R/T for low-kill/low-kill-boost/reverb/delay (R = 1/8-note taps, T = 1/16) — a tap toggles the effect, a hold is momentary: the effect flips at keyDown and keyUp reverts to the pre-press state when the press ran longer than the ~0.35 s tap threshold) are handled by `TransportKeyMonitor`, a local keyDown+keyUp monitor the controller owns (keyUp decides tap vs hold). The debug command channel's extra surface lives in `MainPlayerController+Debug.h`. A 3 Hz timer (`UIUpdateTimer`, Util/ — owns the suspend/resume trap dance) drives the playback-position UI (`updatePlaybackUI`); it runs only while playback wants updates AND the window is unoccluded (`windowDidChangeOcclusionState:` pushes the visibility gate and refreshes once on reveal — Control Center keeps counting on its own). The full `updateUI` runs on transport events and metadata deliveries. Metadata loading for a dropped playlist is deferred until playback starts (2 s fallback) so the first track plays immediately on large folder drops. The skip actions (skip/more/most) seek by ±8 / ±16 / ±32 bars when the track's tempo is known (tagged BPM wins over analyzed, same precedence as the BPM label) — bars are fixed spans of file time, so the jump stays on the musical grid at any pitch; without a tempo they fall back to ±10 s / ±30 s / ±60 s in the pitch-adjusted wall-clock seconds the labels show. A forward skip past the end calls `AudioPlayer.finishCurrentTrack`, which fires `didFinishPlaying:` so the same auto-advance/end-of-playlist-stop path handles it — no next-vs-stop branching in the controller. Skips need a non-Stopped player, gated in both `skipByFileSeconds:` (the bare keys bypass validation) and menu validation: after the playlist ends the finished file stays open, so `duration` alone still looks seekable while no node exists. File > Close (⌘W, `closeFile:`; the menu item retitles "Close File"/"Close All Files" in validation) calls `AudioPlayer.stop` (no delegate event), clears the playlist, cancels the deferred metadata load, drops the metadata scan loader (`cancelAll` — a cancelled loader still strongly holds every track it queued, thumbnails included, and after a Close nothing would ever replace it), and returns to the empty state. The empty state (no track): waveform shows a static midline placeholder, both time labels read `--:--`, a "Drop a file or press ⌘O" hint appears, all at half strength; at launch it's suppressed to a blank header (`revealEmptyState` grace) so a launch-time open never flashes it. Play errors render inline in the same empty-state style — no modal, no auto-skip: `displayedTrack` masks the errored track (the `_erroredTrack`/`_errorStatus` pair, written only via `setErrorMaskForTrack:status:`/`clearErrorMask`; error text on the artist line over the track's title), the track stays in the playlist for retry, and late metadata/art deliveries for it are ignored while masked. All header rendering resolves through one five-state `TrackDisplayState` (track / loading / empty / launch-grace / error), resolved in one place (`displayState`) and shared by `updateUI`, `updatePlaybackUI`, and the Now Playing publish, so the branches can't drift; the rendering itself — header labels (title shrink-to-fit, codec/BPM corner, drop hint) plus the waveform view's progress/shimmer/placeholder states — is drawn by `TrackDisplayController`, a pure decide-vs-draw split: the controller resolves WHAT to show and hands it over, the display controller holds no player or playlist state.
- `NowPlayingController` bridges the player to the system Now Playing UI (Control Center, the hardware media keys, AirPods/Bluetooth transport) via MediaPlayer's `MPRemoteCommandCenter` + `MPNowPlayingInfoCenter`. The controller owns it and, from the `updateUI` funnel (plus the seek and pitch-change paths), calls `updateNowPlaying` to publish title/artist/artwork/duration/elapsed/rate/state; command handlers route back through the `NowPlayingControllerDelegate` to the same `playPause:`/`next:`/`previous:`/seek entry points the on-screen buttons use. Position and duration are reported in wall-clock (pitch-adjusted) time — file time divided by the varispeed `playbackRate`, matching the app's own current/total time labels — so the Control Center readout tracks the pitch fader; the MediaPlayer rate is then 1.0 while playing (wall-clock elapsed advances at real time) / 0 while paused. The system is told nothing until the first track plays, so Vibe doesn't steal Now Playing from other apps at launch. Artwork is read non-blocking (`albumArt` = already-decoded-or-nil) and refreshed when art resolves. Debug-build inspection: `Vibe --debug-cmd dump_now_playing`.
- `MainWindow` is a custom NSWindow that accepts file drag-and-drop (NSDraggingDestination) and supports small/large layout toggle. It is freely resizable in both axes — the frame is the user's, kept by the autosave; the window enforces only the floor (`kMainWindowMinContentWidth` plus the pitch panel's slice when showing, `kMainWindowSmallHeight`) and applies the size changes the app makes itself: the playlist toggle's height, the pitch panel's ±`kPitchPanelWidth`, and the View > Size width presets. All three animate at one fixed `animationResizeTime:` (`kWindowResizeAnimationDuration`) rather than AppKit's distance-scaled default, which made the playlist's 250pt jump drag and would have put a Large→Small preset near a second. The pitch-panel toggle is the one place the two `contentView` siblings must NOT follow the resize (the reveal is the window's right edge sweeping past a stationary panel), so `togglePitchPanel:` swaps in fixed masks for the animation and restores the resizable ones (body width-sizable, panel right-anchored) after. Dropped folders expand on a serial queue (`NSURLUtil`) so overlapping drops complete in submission order. A folder's recursive walk is sorted by full path with `localizedStandardCompare:` (Finder's numeric ordering, subfolders staying grouped) — `NSDirectoryEnumerator` hands back APFS hash order, which played an album shuffled; an explicit multi-file drop keeps its pasteboard order, which is the user's own.
