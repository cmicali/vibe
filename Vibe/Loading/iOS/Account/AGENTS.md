# Cloud accounts (iOS)

This directory holds what every cloud account shares. Each service subclasses the two classes here: Dropbox (`../Dropbox/AGENTS.md`) and Google Drive (`../GoogleDrive/AGENTS.md`). This directory has no UI. The shell sees every account through `AccountMirror` and loops over `AccountMirror.mirrors` (`Vibe/iOS/AGENTS.md`). `VibeiOSAppDelegate` installs each mirror as a remote fetch backend at launch (`Loading/AGENTS.md`), beside the Links store.

| File | Owns |
| --- | --- |
| `OAuthAccountClient` | The account: PKCE sign-in in `ASWebAuthenticationSession`, the refresh token in the Keychain, the access token in memory, and one failure ladder. It subclasses `HTTPTransferClient` (`Loading/Net/AGENTS.md`), which runs the streamed download and the ranged read. A service's client names its endpoints and reads its answers through the hooks in `OAuthAccountClientInternal.h`. |
| `AccountMirror` | The account as local files, in the part every service shares. That is the account's directory, the pruning of other accounts, the playlist files' download claim, the sweep of what left the service, the downloads notification, and the shared folder link road. It is also the one face the shell calls. It subclasses `RemotePlaceholderStore` (`Loading/Net/AGENTS.md`). A service's mirror lists, names and searches through `AccountMirrorInternal.h`. |
| `AccountRules.h` | The shared decisions with no network or disk: PKCE, the query and form encoding, the JSON body, the revoked grant, the timestamps, the index key, which names are mirrored, and the download budgets. Tested (`AccountRulesTests`). |

Both classes compile into the macOS `VibeTests`, with each service's pair. The client also uses AuthenticationServices for sign-in and Security for the Keychain.

**A new service is a client, a mirror, a rules header, a glyph and a budget key.** Add its mirror to `AccountMirror.mirrors`, whose order is the order every screen lists. Nothing in the shell names a service. A screen that needs a service's name reads `serviceName`. Strings name the service through `%@`, never in their text.

## The account

**Each service's refresh token is one Keychain item, `AfterFirstUnlockThisDeviceOnly`.** The item holds the refresh token, the account id and the account name. Its service is the client's `keychainService`. Dropbox's is `com.commonwealthrecordings.Vibe.dropbox`, which has shipped. A refresh must work under the lock screen while background playback downloads the next track. A backup restored on another phone signs in again. **TRAP: before first unlock the item reads as locked (`errSecInteractionNotAllowed`), not absent.** Read as absent, the whole session would run signed out. The client remembers the lock and reads again at the next use (`isLinked`, `accountID`, any call). It reads at most once every `kAccountLoadRetryInterval`, and it posts the account change when the read lands. Nothing is deleted at launch, only on a real account change.

**TRAP: the default simulator build cannot reach the Keychain.** It is unsigned, so every `SecItem` call answers `-34018` (`errSecMissingEntitlement`). Sign-in works for the session, but the refresh token is never saved, and the next launch is signed out. Build with `VIBE_SIGN_SIM=1` to test anything across a relaunch (the `vibe-debug` skill). A device build is always signed.

**Sign-in fails at once when the client id is empty.** A token answer that names the account links it at once, and the name follows (`refreshAccountNameWithCompletion:`). A token answer that does not name it reads the identity first, because the account id names the mirror's directory. Dropbox's answer names it. Google's does not.

**One refresh is in flight at a time.** It is the refresh claim, and every caller arriving during it is a waiter on it. `_accountGeneration` moves on every sign-in and sign-out. So a refresh or a 401 from the previous account can neither restore nor unlink the current one. **TRAP: a Keychain save checks its generation inside the Keychain lock**, which a delete also takes. Delete-then-add is two calls, and a sign-out between them left the signed-out account linked at the next launch. A late answer to the identity call cannot stamp its name and id on the next account.

**Every call and transfer shares one failure ladder.** A refused call whose token only aged out refreshes once and resends (`isExpiredAccessTokenStatus:body:`). A refused call the grant has no scope for fails and never unlinks (`isMissingScopeStatus:body:`). **TRAP: a missing scope can be a 401.** Dropbox's is. Unlinked, a grant from before a scope the app added would sign the user out and prune every download at its first call that needs the scope. Any other 401 unlinks. A refresh refused as a revoked grant also unlinks (`VibeAccountIsRevokedGrant`). A throttle the service names waits and resends as a 429 does (`isThrottleStatus:body:`). Anything else fails with `VibeAccountErrorAPI` and the service's one-line summary. A cancel's rules are the base's (`Loading/Net/AGENTS.md`).

**Unlinking posts `VibeAccountDidChangeNotification`, with the client as its object.** The mirror then prunes every directory but the account's and its links'. `PlaybackController` clears a playlist reaching into that mirror, whole, as Clear Playlist does. Signing out forgets the account at once. It then attempts to revoke the grant in the background, with a fresh access token (`revokeRefreshToken:accessToken:`). A failed request can leave the remote grant active after local sign-out.

**The launch warms each linked account once** (`warmUp`, off main). The access token lives in memory, so a launch's first request would otherwise refresh. The warm-up refreshes it and then sends the service's own warm-up requests (`warmUpConnectionsWithAccessToken:`). These open the connections the first play would use. It never runs on a foreground, or before first unlock.

## The mirror

`Library/Application Support/<service>/<account id>/`, excluded from backup and outside Documents, so the Files app never shows it. Each service names its root directory. **It is lazy: a remote folder exists here only once something listed it.** The browser lists on every visit. A search hit lists its parent before it opens. An open lists a folder nothing has listed yet (`FolderSession`'s `listFromAccountIfMirrored:`, which asks `hasListedDirectory:`). A folder its parent's listing made carries only what names it in its index. A folder listed itself carries its files. There is no full sync, and search is the service's.

- **A placeholder is a sparse file of the remote size and a remote date, with no permissions.** How it is written is the store's (`Loading/Net/AGENTS.md`). Size plus mtime is the cache key. Each service decides which date keeps that key honest.
- **Only playable audio and playlist files (`.cue`, `.m3u`, `.m3u8`) are mirrored** (`VibeAccountNameIsMirrored`). The playlists download with the listing, off the disk queue, since `rowsForWalk:` reads a sheet while the folder opens and a tap on an M3U reads it at once (`finishListingOfDirectory:…`). **TRAP: one download per sheet** (`_sidecarWaiters`, the claim). Two listings of one folder both find the sheet missing and share its part file. The first to finish would rename the other's half-written bytes into place. So a listing that finds the sheet claimed waits on that download.
- **TRAP: a name read back from disk is never sent to a service.** A file URL's path comes back decomposed (NFD), while a service keeps names as uploaded, usually composed. Each directory's index (the store's xattr) holds what the service said, keyed by `VibeAccountIndexKey`.
- **TRAP: a directory a reconcile deletes takes the cached indexes with it** (`removeDepartedIn:existing:kept:`). Kept, a folder that leaves the service and comes back is made empty, still reads as listed, and its open plays nothing.
- **TRAP: the stale-part sweep goes by ctime, never mtime.** The install dates a finished part to its version just before the rename, and a sweep between the two would delete it. The sweep takes a part a dead process left after a day.
- **Past the download budget the oldest downloads go back to placeholders** (the store's eviction). The budget counts the linked account's directory and its links' (`budgetRootURL` is the root while linked, which then holds nothing else). Each mirror has its own. The user chooses it in Settings › Files and Accounts › Maximum Size (`kVibeAccountDownloadBudgets`). Settings saves it under the mirror's `downloadBudgetKey`, which the mirror starts from, then sets `downloadBudget`. A smaller budget applies at once. Every change to the downloads' total posts `VibeAccountDownloadsDidChangeNotification`, with the total already counted. Size and mtime are kept, so the cached tags and waveform still match. A player still reading an evicted file keeps its open descriptor. Remove Downloads does the same to all of them.

## Shared folder links

**A Dropbox or Google Drive folder link opened while signed in to that service is listed through the account** (`openSharedFolderLink:completion:`). Open URL's resolve on iOS chooses this road (`PlaybackController+ReplacePrompt`'s `resolveLinkString:completion:`). It asks each linked mirror `opensSharedFolderLink:`. Any failure falls back to `LinkStore`'s road with no account (`Loading/Net/AGENTS.md`).

**The service's half is one hook and its listing.** `lookUpSharedFolderLink:completion:` names the folder and answers the index its top directory starts from. `refreshDirectoryAtURL:completion:` then lists each directory from what its index records. The open lists every folder below the link, one directory at a time. Any failure fails the open. A file downloads through the account, with the failure ladder, resume and version pin of any download.

**The links' tree is `linksURL`, beside the account's directory** (`<account id> links/`). A listing of the account's root deletes every name the service does not hold there. The links' tree therefore cannot sit inside it. Each link has a directory named by its URL's hash. That directory holds the folder under its own name. Recents names the hash directory for the service (`LocationStore displayNameForFolderURL:`). `isMirroredURL:` covers both trees, and `isSharedLinkURL:` covers only the links'. `FolderSession` covers `linksURL` as it covers the account's directory. An account change prunes the links with the account.

Opens are the shell's ordinary roads. A mirror directory is an app-container URL with no security scope, which `FolderSession` treats as a root every open covers. A file opened alone becomes its folder with it selected, bookmarks persist, and a relaunch restores from the placeholders offline.
