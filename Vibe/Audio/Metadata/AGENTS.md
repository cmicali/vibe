# Metadata and artwork

Tags, their disk cache, the playlist scan and embedded artwork. `FolderArt/` — the sidecar-cover fallback — carries its own `AGENTS.md`. `AudioTrackMetadataCache` is the facade, `AudioTrackMetadataLoader` the one sweep behind it (private), `MetadataParseCoordinator` the per-path owner/waiter table and nothing else, `AudioTrackMetadata` the immutable tags plus the display-facing art API, `AudioTrackArtwork` one row's art lifecycle (private behind the metadata), `ArtworkLoadRegistry` that lifecycle's admission counters — a file boundary, not a second owner. **Do not add a runner, driver or second coordinator**: straight-line metadata work goes in the loader, per-row art work in `AudioTrackArtwork`. The lettered items cited (`spec A1`, `J4`, `J6`) are `docs/file-loading-spec.md`'s, where the admission and retry decisions were settled.

## The scan

**A metadata request may start before a file is materialized; a TagLib parse may not.** The disk-cache check never reads audio, so known rows populate without touching their files; on a miss `AudioFileMaterializationCoordinator` must report `Ready` before the parse enters a worker. **The one exception is a remote placeholder (iOS's Dropbox mirror) while a remote read is installed**: its tags are read by range, so the scan settles it Ready with no claim at submission (`submitMaterializationForEntry:`) and `TagLibAudioFile` reads it through `VibeRangedStream` — about three requests and a few hundred KB per file, artwork included, where materializing would download the whole file. It takes no claim because stage 1 is one claim per path shared by every role: a metadata Ready on a placeholder would hand a playback open joining that claim an unreadable file. It is still a network read, so it stays behind the foreground rule below, which gates every non-local pick.

**The playlist sweep has two stages, and only stage 2 can download.** Stage 1 checks every file against the cache once, behind an operation-queue barrier that waits for enumeration and every check; stage 2 admits the misses. **A record is a file, not a row**: the rows sharing a standardized path — a cue sheet's forty, a file listed twice — are one record, so the file is checked, materialized and parsed once and its answer settles every row as copies. A failed parse gives its fallback to the row it read for, the marked row when there is one, and requeues the rest as a record of their own, so each still tries the file. The scan registers exactly one `MetadataScan` materialization at a time.

**The current track is not a second lane: it is the record holding a row the loader has marked.** It materializes through its own slot beside the scan's, is exempt from the stage-1 barrier, is submitted even under the foreground rule (a same-path playback claim serves it for free — spec J4) and parses at user-initiated QoS. Demotion removes the mark, so no stale mark survives a requeue, and so does removing the marked row (`abandonQueuedTrack:`), since a marked URL holds its file's other records out of the scan; every mark carries a generation and its exact target track, and settlement retires only a mark it actually resolved. A repeat edge reactivates one submission so it can join a new same-path foreground claim. Both slots spend the one per-path retry ledger; there is no priority budget. A `loadMetadataNow:` before any sweep builds a loader over that one track; the real sweep replaces it wholesale and re-prioritizes the weakly held current track. `cancelScan` (File > Close) drops every pending record, priority included — which is what makes playlist replacement drop the old playlist's downloads by construction — and detaches central tokens without cancelling a same-path foreground owner.

**The foreground rule is the coordinator's; this directory only asks.** The sweep asks `isForegroundTransferActive` before submitting a dataless record and re-asks on a bounded 1s clock while gated (`recheckForegroundGate`, the seam tests drive). Cache checks continue while gated, and **an already-local file is exempt** — the rule bounds provider downloads, which a local miss never starts — so on a partially downloaded folder local tags land straight through. The loader probes locality with `NSURLUtil.isDatalessFile:` at every enqueue, submit and requeue edge, because the playback open routinely downloads the very file a yielded record is parked on.

**Materialization results, not error text, decide retries** (`MetadataRetryRules.h`, tested):

- `Yielded` spends no attempt; a scan record requeues at its rank. A yielded **priority** record is re-judged on each gated tick: local now → retry at once, hold or no hold (spec A1's exemption; waiting cost the now-playing tags the successor's whole prefetch); still dataless → wait rather than re-pick, since a re-pick installs a fresh `Probing` claim, burns a probe slot and yields again; and at the **first idle tick** still dataless means the open failed, so it demotes to an ordinary sweep candidate instead of re-downloading a dead pick behind its own error UI.
- `Failed` spends the bounded per-path budget and re-enters below untried rows. `AdmissionExhausted` spends the same budget after a 0.25–2s delay.

A loader snapshots `AudioLoadingConfiguration`; a settings change reaches only later loaders.

**Pending misses are app-owned records picked one at a time, never sorted** (`MetadataScanOrderRules.h`, tested): already-local first, then untried before deferred, then neighborhood rank, then playlist index. A real playlist holds more than 100,000 misses, so a track change replaces only the small locked neighborhood snapshot and enqueues a coalesced kick. Each shell sends that snapshot from its one current-index funnel through `setNeighborhoodTracks:`, handing over the playlist's `neighborhoodTracks` — the next, the one after and the previous in play order, so under shuffle the scan ranks what will actually play — never the whole list, whose mac getter's defensive copy costs one retain per track.

## Duplicate rows and delivery

**One parse per standardized path** (`VibeStandardizedAudioOpenPath`, the spelling every loader identity uses, so two spellings cannot get two owners). `MetadataParseCoordinator` holds duplicate rows weakly as waiters; the owner rechecks the disk cache after claiming, since another lane may have won. Its answer, that hit or a successful parse, is copied into every unresolved waiter while the holder still gates new owners, and the last empty drain releases the claim before publication. Each copy has its own mutable artwork state.

**A file TagLib has no parser for takes its facts from CoreAudio's**: CAF and W64 among the playable ones, and any file TagLib refuses that CoreAudio reads. Duration, rate, bitrate, the codec or container name, and the info dictionary's title and artist, with no art, so it parses OK, caches, and the folder's cover can stand in (`loadCoreAudioFactsFromURL:`). It reads them through playback's own parser open (`AudioFileHandle`'s `initParserForReading:`, no decoder), so the two never disagree on a file and the open's guards and traps live there alone. **TRAP: the TagLib parse must refuse what that open refuses** — TagLib's FLAC sniff takes FLAC in Ogg, which playback refuses, so no Ogg stream parses as FLAC (`AudioTrackMetadata.mm`) and such a file is a failed parse, not a row that looks playable. **A file neither reads is a failed parse: filename-fallback metadata, never cached**; holder and every waiter get independent fallback copies so no row stays unresolved. Installation and publication compare the exact metadata object under the track monitor, so a racing success replaces a fallback and the stale fallback delivery then drops rather than publishing twice.

**Every delivery runs on main and revalidates the exact installed object while holding the track monitor through the delegate call.** Delegates may update observers and UI synchronously; they must never wait on a metadata worker.

## Embedded artwork

`AudioTrackMetadata.h` is the only display API and states each call's contract; `cachedArt` and `cachedThumbnail` are non-blocking and safe while drawing, and a cache miss never decodes from a drawing path.

**Across all rows, at most two art reads or decodes run and five sit pending** (`ArtworkLoadRegistry.h`). A request past the bound is dropped *before* it marks the row pending, so the next redraw re-requests it cleanly (spec J6). Only a source-file extraction asks for `MetadataPriority` materialization; an in-memory decode or the folder fallback uses the worker admission without rematerializing the song. `Yielded`, `AdmissionExhausted` and worker rejection retry at capped 0.1–1s backoff without spending the three-failure budget; `Failed` spends it. A generation captured at admission must still match before a worker claims extraction or stores its result.

**Parsed metadata is compacted before publication**: a 128px thumbnail is encoded, then the original bytes released. Rows hold only those compact bytes; decoded thumbnails live in one 16,384-entry LRU (flushed on an iOS memory warning, and each entry removed when its row's artwork deallocates, since its key is that instance) that only the display request path populates — construction and archive encoding decode on their worker without touching it, so a playlist-wide scan cannot evict visible pixels. A miss enters a two-running, 126-pending decode bound, then a main-thread notification redraws only visible rows still showing that metadata. **Staleness has one fence**: every data transition replaces the row's identity key and clears the single-flight pending flag, so a decode is current exactly when its captured key is still installed. Full art decodes on demand at no more than 1024px. Which surfaces use the thumbnail is the root guarantee.

**Compaction also archives a display-art rendition beside the entry** — a `#displayArt`-suffixed key in the same store, on the same LRU and age terms — sized per platform to match the live decode it stands in for: `kVibeArchivedDisplayArtDimension` is 640 on the mac (the header renders at ≤~525px) and 1024 on iOS. Bytes already within the bound are archived verbatim; larger art is downscaled aspect-preserved, the square crop staying display-time policy so Now Playing gets uncropped art. **The rendition is disk-resident only: rows never retain it.** The parse hands it to the loader as an out-param, so a skipped cache write releases it with the frame, and per-row memory stays at the 128px bytes whatever the sidecar weighs.

**The rendition is both big surfaces' decode source.** The loader stamps `archivedDisplayArtProvider` on every art-bearing row on both platforms, and the full-art ladder reads decoded art → in-memory bytes → archived rendition → source-file extraction. The rendition read is a cache hit that registers no materialization, so a track change or page swipe never re-reads (or re-downloads) the song. A provider whose read comes back empty or undecodable is dropped and the load takes the demotion fence, so `finishRequest` re-requests a still-wanted row and the fresh pass reaches extraction — one extra hop, never a stall, and never `_embeddedUndecodable`, since the file's own art may be fine.

**Embedded extraction is tri-state — art, conclusively none, or read failed — and only conclusive none opens the folder fallback.** A failed read stays unknown and retryable: three reads per display pass, a two-second per-row backoff. `hasEmbeddedArt` is archived separately from the thumbnail bytes, so an entry without them is not mistaken for artless, and its row thumbnail decodes from the archived rendition instead.

**No artwork monitor is held across file I/O or image decoding** — a provider read can block indefinitely. An entered TagLib read is uncancellable and keeps its scheduler slot to completion; demotion (`discardDecodedArt`) fences its store and re-enters admission if the row becomes wanted again, and deliberately leaves the in-flight extraction claim set, or the next pass could start a second uncancellable read (`AudioTrackArtwork.m`'s `TRAP:`).
