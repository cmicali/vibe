# Metadata and artwork

Tags, their disk cache, the playlist scan and embedded artwork. The artwork classes live in `Artwork/`. `Artwork/FolderArt/` is the sidecar-cover fallback, and it has its own `AGENTS.md`.

- `AudioTrackMetadataCache` is the facade, and `AudioTrackMetadataLoader` the one sweep behind it (private).
- The loader is one object in three files. `AudioTrackMetadataLoader.m` is its life and the sweep's stage 1. `+Materialization.m` is the lane: priority marks, the two slots, the foreground gate and each completion's settlement. `+Parse.m` is the cache read, the parse, installation, settlement and publication, with the display-art rendition's sidecar. `AudioTrackMetadataLoader.h` holds its ivars and each file's shared methods. `MetadataScanEntry` holds its two records, the scan entry and the priority mark.
- `MetadataParseCoordinator` is the per-path owner/waiter table and nothing else.
- `AudioTrackMetadata` is the immutable tags plus the display-facing art API.
- `TagLibAudioFile` is the TagLib side of the parse: the file factory, the ranged stream, the format name and the embedded-art read. Its header is C++, so only `.mm` files import it.
- `AudioTrackArtwork` is one row's art lifecycle (private behind the metadata). `ArtworkLoadRegistry` is its admission counters, a file boundary, not a second owner.
- `EmbeddedThumbnailCache` is the decoded thumbnails every row shares, in one bounded LRU.

**Do not add a runner, driver or second coordinator.** Straight-line metadata work goes in the loader, per-row art work in `AudioTrackArtwork`. The lettered items cited (`spec A1`, `J4`, `J6`) are `docs/file-loading-spec.md`'s.

## The scan

**A metadata request may start before a file is materialized; a TagLib parse may not.** The disk-cache check never reads audio, so known rows populate without touching their files. On a miss, `AudioFileMaterializationCoordinator` must report `Ready` before the parse enters a worker.

**The one exception is a remote placeholder of a format TagLib parses**: a link's on both platforms, or a Dropbox mirror file's on iOS. The rule is `PlaceholderFiles readsRemotePlaceholderByRange:`, over `PlayableExtensions.tagParsed`, and the art loader shares it. Other formats take CoreAudio's facts, which need the whole file, so they materialize. The scan settles such a placeholder Ready with no claim (`submitMaterializationForEntry:`). `TagLibAudioFile` reads it by range through `VibeRangedStream`, about three requests and a few hundred KB per file, artwork included. A file the backend is streaming is read from the stream, at no request cost (`Loading/Net/AGENTS.md`). A link whose server answers no range fails the ranged read, and its tags come once the file is local. It takes no claim because stage 1 is one claim per path shared by every role. A metadata Ready on a placeholder would hand a playback open joining that claim an unreadable file. It is still a network read, so the foreground rule below gates it.

**The playlist sweep has two stages, and only stage 2 can download.** Stage 1 checks every file against the cache once, behind an operation-queue barrier that waits for enumeration and every check. Stage 2 admits the misses. **A record is a file, not a row.** The rows sharing a standardized path (a cue sheet's forty, a file listed twice) are one record: checked, materialized and parsed once, with its answer copied to every row. A failed parse gives its fallback to the row it read for (the marked row when there is one) and requeues the rest as a record of their own. The scan registers exactly one `MetadataScan` materialization at a time.

**The current track is not a second lane: it is the record holding a row the loader has marked.** It materializes through its own slot beside the scan's, skips the stage-1 barrier, and is submitted even under the foreground rule, since a same-path playback claim serves it for free (spec J4). It parses at user-initiated QoS. Demotion removes the mark, and so does removing the marked row (`abandonQueuedTrack:`), since a marked URL holds its file's other records out of the scan. Every mark carries a generation and its exact target track, and settlement retires only a mark it resolved. A repeat edge reactivates one submission so it can join a new same-path foreground claim. Both slots spend the one per-path retry ledger. A `loadMetadataNow:` before any sweep builds a loader over that one track. The real sweep replaces it and re-prioritizes the weakly held current track. `cancelScan` (File > Close) drops every pending record, priority included, so playlist replacement drops the old playlist's downloads. It detaches central tokens without cancelling a same-path foreground owner.

**`loadCachedMetadata:` is the cache check alone**, for rows whose audio is not on the device (the iOS browser's placeholders and dataless files). A hit installs and publishes as the sweep's does. A miss ends there, with no record, materialization or parse (`loadFromCacheOnly:`). It runs on a loader of its own that is never cancelled, so a later `loadMetadata:` or `cancelScan` cannot drop a lookup the caller will not repeat.

**The foreground rule is the coordinator's; this directory only asks** (root `AGENTS.md`, `Loading/AGENTS.md`). The sweep asks `isForegroundTransferActive` before submitting a dataless record, and re-asks on a bounded 1 s clock while gated (`recheckForegroundGate`, the seam tests drive). Cache checks continue while gated. **An already-local file is exempt**, so on a partly downloaded folder local tags land straight through. The loader probes locality with `PlaceholderFiles.isDatalessFile:` at every enqueue, submit and requeue, because the playback open routinely downloads the very file a yielded record waits on.

**Materialization results, not error text, decide retries** (`MetadataRetryRules.h`, tested):

- `Yielded` spends no attempt, and a scan record requeues at its rank. A yielded **priority** record is re-judged on each gated tick. Local now, it retries at once (spec A1), since waiting cost the now-playing tags the successor's whole prefetch. Still dataless, it waits rather than re-pick, since a re-pick installs a fresh `Probing` claim and yields again. At the **first idle tick**, still dataless means the open failed, so it demotes to an ordinary sweep candidate.
- `Failed` spends the bounded per-path budget and re-enters below untried rows. `AdmissionExhausted` spends the same budget after a 0.25–2 s delay.

A loader snapshots `AudioLoadingConfiguration`, so a settings change reaches only later loaders.

**Pending misses are app-owned records picked one at a time, never sorted** (`MetadataScanOrderRules.h`, tested): already-local first, then untried before deferred, then neighborhood rank, then playlist index. A real playlist holds more than 100,000 misses, so a track change replaces only a small locked neighborhood snapshot and enqueues a coalesced kick. Each shell sends it from its one current-index funnel through `setNeighborhoodTracks:`. It hands over the playlist's `neighborhoodTracks` (the next two and the previous in play order, so shuffle ranks what will play), never the whole list, whose mac getter copies it.

**The cache key is the row's `AudioTrack.cacheKey`, memoized for the row's life**, until a download installs another version than its placeholder's (`Loading/AGENTS.md`). Then every memo is retired and the next lookup stats the file again. A row already holding metadata keeps it until it is next parsed.

## Duplicate rows and delivery

**One parse per standardized path** (`VibeStandardizedAudioOpenPath`, the spelling every loader identity uses). `MetadataParseCoordinator` holds duplicate rows weakly as waiters. The owner rechecks the disk cache after claiming, since another lane may have won. Its answer is copied into every unresolved waiter while the holder still gates new owners, and the last empty drain releases the claim before publication. Each copy has its own artwork state.

**A file TagLib has no parser for takes its facts from CoreAudio's**: CAF and W64 among the playable ones, and any file TagLib refuses that CoreAudio reads. Those are duration, rate, bitrate, the codec or container name, and the info dictionary's title and artist, with no art. It parses OK, caches, and the folder's cover can stand in (`loadCoreAudioFactsFromURL:`). It reads them through playback's own parser open (`AudioFileHandle`'s `initParserForReading:`, no decoder), so the two never disagree on a file.

**A parse never waits for a download, and never reads ahead.** Both fallback opens, the FLAC-length one included, pass `VibeNeverWaitsForAStream` (`AudioFileHandle.h`, compared by identity). Against a file a transfer is still writing, the open fails at once, and the facts come once the file is on disk. On a network share the open reads the file directly, as TagLib's parse does.

**TRAP: the TagLib parse must refuse what that open refuses.** TagLib's FLAC sniff takes FLAC in Ogg, which playback refuses. So no Ogg stream parses as FLAC (`TagLibAudioFile.mm`). Such a file is a failed parse, not a row that looks playable.

**A file neither reads is a failed parse: filename-fallback metadata, never cached.** The holder and every waiter get their own fallback copies, so no row stays unresolved. Installation and publication compare the exact metadata object under the track monitor. A racing success replaces a fallback, and the stale fallback's delivery drops.

**Every delivery runs on main and revalidates the exact installed object while holding the track monitor through the delegate call.** Delegates may update UI synchronously. They must never wait on a metadata worker.

## Embedded artwork

`AudioTrackMetadata.h` is the only display API and states each call's contract. `cachedArt` and `cachedThumbnail` never block and are safe while drawing. A cache miss never decodes from a drawing path.

**Across all rows, at most two art reads or decodes run and five wait** (`ArtworkLoadRegistry.h`). A request past the bound is dropped *before* it marks the row pending, so the next redraw re-requests it (spec J6). Only a source-file extraction asks for `MetadataPriority` materialization. A remote placeholder's art is read by range as its tags are (`beginRequest:`), or a lost rendition would download the whole song to show its picture. It still waits out a foreground transfer, as the scan does. An in-memory decode or the folder fallback uses worker admission without materializing the song. `Yielded`, `AdmissionExhausted` and worker rejection retry at a capped 0.1–1 s backoff without spending the three-failure budget. `Failed` spends it. A generation captured at admission must still match before a worker claims extraction or stores its result.

**Parsed metadata is compacted before publication**: a 128px thumbnail is encoded, then the original bytes released. Rows hold only those bytes. Decoded thumbnails live in one 16,384-entry LRU (`EmbeddedThumbnailCache`), flushed on an iOS memory warning, with each entry removed when its row's artwork deallocates. Only the display path populates it, so a playlist-wide scan cannot evict visible pixels. A miss enters a two-running, 126-pending decode bound. A main-thread notification then redraws only visible rows still showing that metadata. **Staleness has one fence**: every data change replaces the row's identity key and clears its pending flag, so a decode is current exactly when its captured key is still installed. Full art decodes on demand at no more than 1024px. Which surfaces use the thumbnail is the root guarantee.

**Compaction also archives a display-art rendition beside the entry.** It has a `#displayArt`-suffixed key in the same store, on the same LRU and age terms. `kVibeArchivedDisplayArtDimension` is 640 on the mac and 1024 on iOS, the size of the live decode it stands in for. Bytes within the bound are archived verbatim. Larger art is downscaled with its aspect kept, since the square crop is display-time policy and Now Playing gets uncropped art. **The rendition lives only on disk: rows never retain it.** The parse hands it to the loader as an out-param, so per-row memory stays at the 128px bytes.

**The rendition is both big surfaces' decode source.** The loader sets `archivedDisplayArtProvider` on every art-bearing row on both platforms. The full-art ladder reads decoded art, then in-memory bytes, then the archived rendition, then source-file extraction. The rendition read is a cache hit with no materialization, so a track change or page swipe never re-reads the song. A provider whose read is empty or undecodable is dropped, and the load takes the demotion fence. `finishRequest` then re-requests a still-wanted row, which reaches extraction. It never sets `_embeddedUndecodable`, since the file's own art may be fine.

**Embedded extraction is tri-state (art, conclusively none, or read failed), and only conclusive none opens the folder fallback.** A failed read stays unknown and retryable: three reads per display pass, with a two-second per-row backoff. `hasEmbeddedArt` is archived apart from the thumbnail bytes, so an entry without them is not mistaken for artless. Its row thumbnail then decodes from the rendition.

**No artwork monitor is held across file I/O or image decoding**, since a provider read can block indefinitely. An entered TagLib read cannot be cancelled and keeps its scheduler slot to completion. Demotion (`discardDecodedArt`) fences its store and re-enters admission if the row is wanted again. **TRAP:** demotion leaves the in-flight extraction claim set, or the next pass could start a second uncancellable read (`AudioTrackArtwork.m`).
