# Live output levels

This directory is the demand-driven output-metering pipeline used by the shared equalizer indicator. It is separate from `../Analysis/`, which owns offline BPM and key detection riding the waveform decode pass; nothing here opens or analyzes a file.

`AudioPlayer.levelsEnabled` installs an `AudioLevelTap`; `copyBandLevels:count:sequence:` reads the latest coherent five-level snapshot without taking the player queue or allocating. The `AudioLevelPublisher` is stable for the player's lifetime, while each graph installation gets a new session. Its monotonic sequence lets the display distinguish a new analysis result from repeated reads, and invalidating a session makes its old snapshot unavailable immediately.

The small-file split is the readability boundary between separate responsibilities:

| File | Owns |
| --- | --- |
| `AudioLevelTap.{h,m}` | `AVAudioNode` install, remove and abandon, plus the lifetime of one graph session. |
| `AudioLevelAnalyzer.{h,m}` | Pure preallocated FFT, chunk accumulation, stereo-power combination and mode-specific callback aggregation. No AVFoundation, publication or view knowledge. |
| `AudioLevelPublisher.{h,m}` | The coherent player-lifetime snapshot, session validity and monotonic sequence read by the display. |
| `AudioLevelPublisherInternal.h` | The narrow tap-session writer API; display clients never import it. |
| `AudioLevelMath.h` | Tested numeric decisions: cadence, band edges, energy scaling and level mapping. |

**The tap goes on whatever feeds `outputNode`, and that is not the same node on both.** With no FX segment — which is what `enableFX:NO` gives the iOS player — `mainMixerNode` *is* that node: post-fade, post-varispeed, and the crossfade sum comes free because both chains already meet there. With the segment present, the reverb and delay returns re-enter **downstream** of the mixer, so a tap there would miss every wet tail; the signal reaching the speaker is `AudioFX.masterBusOutputNode`, the sum of the dry path and every return. `AudioPlayer.applyLevelTapOnQueue` picks between them, so the bars follow what is actually heard on either platform, and macOS launched with FX switched off quietly lands on the iOS wiring.

**The connected output bus is tapped with `format:nil`.** Its current output format supplies the analyzer's initial sample rate and a legal ~100 ms buffer request; analyzer storage is already fixed for the maximum supported FFT. Passing that format back to `installTapOnBus:` is invalid for some connected graphs. The delivered buffer's sample rate is authoritative and rebinds the analyzer without allocating. One callback can hold several analysis windows, and every complete one is consumed. Relative activity updates and normalizes each band's private reference per window, then retains the largest normalized level per band. Shared spectrum converts each band's integrated energy to energy per octave, averages it across those windows, advances its one reference once for the full analyzed duration, and normalizes the coherent five-band average. Balanced spectrum combines those existing summaries without another FFT or callback cadence. The tap publishes the selected callback summary once.

The analysis clock is bounded and independent of the screen. `VibeLevelFFTSizeForSampleRate` chooses the nearest power-of-two window to about 24 decisions per second, from 256 through 8192 frames, so a high-rate route does not multiply decision cadence. The window grows with sample rate — 8192 points at 192 kHz versus 2048 at 48 kHz — so each high-rate decision still has more FFT arithmetic. Five explicit bands span 40–100, 100–250, 250–800, 800–4000 and 4000–20000 Hz, reserving the first three bars for bass and low mids; routes above 40 kHz never spend a bar on ultrasonic content. Each edge maps with `ceil` to the first FFT bin whose center is at or above it, and the same edge is the exclusive top of one half-open band and the bottom of the next. A below-edge bin therefore cannot leak into a band, and no bin can drive two bars. Left and right are transformed separately and their power is averaged after magnitude-squaring, so opposite-polarity stereo cannot cancel to false silence. FFT energy is normalized by window size before the selected reference and level mapping, keeping the tuning stable across sample rates.

The default `VibeAudioLevelNormalizationModeBalancedSpectrum` starts from the coherent shared energy-per-octave callback average, reserves 9% display headroom, and adds a shared-support-gated 35% of only the positive difference to the existing per-window private-reference activity summary; unsupported bands remain dark. It reuses one FFT and callback cadence. `VibeAudioLevelNormalizationModeSharedSpectrum` remains the unmodified common-reference endpoint, while `VibeAudioLevelNormalizationModeRelativeActivity` remains the unmodified five-private-reference endpoint. The `spectrum` and `activity` debug tokens expose those endpoints for comparison. None claims to reconstruct Apple's visualizer: Apple's band mapping and normalization are not public and are not inferred here.

The render callback allocates nothing, takes no locks and performs no logging. `AudioLevelTap` reads the delivered `AVAudioPCMBuffer`; `AudioLevelAnalyzer` then uses preallocated plain storage, and `AudioLevelPublisher` makes the five values available as one versioned snapshot with a new sequence. The audio thread never performs display smoothing. The consumer, activity and animation contracts live with the shared renderer in `../../Controls/CLAUDE.md`.

Demand-driven rather than fixed at player initialization like `enableFX`, the tap is absent whenever nothing can draw it. **The demand is the indicators', not play intent** — each shell counts active indicators declaring themselves consumers through `equalizerLevelsWanted:` and enables levels only while modeled output audio and material visibility also hold. Stopping an indicator destroys its poller and balances demand immediately, so the tap and poller are both absent at zero. An audio-only stop may leave one finite compositor release to dots, but it owns no analyzer, timer, callback or app-side frame loop; any pixel or ownership loss cancels it immediately. `../../iOS/CLAUDE.md` and `../../Playlist/Mac/CLAUDE.md` own those platform facts. A failed temporary installation is nil rather than inert, so a later eligible engine-start edge can retry.

`AudioPlayer.outputAudioActive` is the nonblocking liveness fact the shells use: a current playing node or any counted retired fade (registered or declick-length) is active; Loading intent by itself is not. Its delegate edge is delivered on main only when that modeled value changes. **`AVAudioEngine` exposes no reliable "wet tail is now silent" fact**, so a reverb or delay tail after every source node has stopped is not modeled and is never approximated with a wakeup timer.

**TRAP: `AudioPlayer.applyLevelTapOnQueue` is the only point that installs or removes a tap — demand changes, engine starts and the master-bus wiring all reconcile through it — and `installMasterBusOnQueue` is the only rebuild edge.** That wiring is what the media-services rebuild re-runs, so a tap installed outside the funnel dies with the old engine and silently never returns — no error, no log, the bars just stop. Each installation re-reads the sample rate a reset is free to have changed, which is what the band edges are bound from. `AudioPlayer.dropEngineBoundStateOnQueue` **abandons** the tap rather than removing it, since removing would message the defunct engine's node.

Normalization mode is immutable for one `AudioLevelTap`. Debug `set_equalizer_mode balanced|activity|spectrum` synchronously reconciles the audio queue: changing an active mode ends the old publisher session, removes and replaces the tap, and starts with an empty partial window and fresh reference history; changing it while inactive stores the choice for the next eligible tap. Engine-graph replacement likewise creates fresh analyzer history but retains the selected mode for the rest of that app process. A delivered sample-rate change rebinds the existing analyzer and resets its partial window and references. No mode is persisted, so every launch starts in `balanced`.

The tunable audio half is `AudioLevelMath.h` — analysis cadence, band edges, energy aggregation, normalization and running references — header-only and tested. Display target threshold and attack/release animation durations live separately in `../../Controls/EqualizerAnimationMath.h`, so changing visual motion cannot increase FFT work.

**TRAP: `--silent` zeroes `mainMixerNode.outputVolume`, and the tap is downstream of it**, so every band correctly reads 0 under the debug scripts' default launch. `--no-audio-hw` alone still manually renders through the tap and is suitable for functional bar/counter checks, but not audible-start-latency measurements. On the iOS simulator use `VIBE_AUDIBLE=1` for reactive validation. Moving the tap upstream to dodge this would make it per-track and require re-plumbing every crossfade.
