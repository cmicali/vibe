# Live output levels

This directory is the demand-driven output-metering pipeline used by the shared equalizer indicator. It is separate from `../Analysis/`, which owns offline BPM and key detection riding the waveform decode pass; nothing here opens or analyzes a file.

`AudioPlayer.levelsEnabled` installs an `AudioLevelMeter`, the **meter**: a plain C struct (`VibeLevelMeter`) the render feeds through `VibeLevelMeterRender`, owned by the meter object for its life. `copyBandLevels:count:sequence:` reads the latest coherent five-level snapshot without taking the player queue or allocating. The `AudioLevelPublisher` is stable for the player's lifetime, while each installation gets a new session. Its monotonic sequence lets the display distinguish a new analysis result from repeated reads, and invalidating a session makes its old snapshot unavailable immediately.

The small-file split is the readability boundary between separate responsibilities:

| File | Owns |
| --- | --- |
| `AudioLevelMeter.{h,m}` | The meter: the render's entry `VibeLevelMeterRender`, its ~100 ms publication cadence and the lifetime of one publisher session; `remove`; the beta signal probe. |
| `AudioLevelAnalyzer.{h,m}` | Pure preallocated FFT, window accumulation, stereo-power combination and the mode-specific summary across windows. No AVFoundation, publication or view knowledge. |
| `AudioLevelPublisher.{h,m}` | The coherent player-lifetime snapshot, session validity and monotonic sequence read by the display. |
| `AudioLevelPublisherInternal.h` | The narrow meter-session writer API; display clients never import it. |
| `AudioLevelMath.h` | Tested numeric decisions: cadence, band edges, energy scaling and level mapping. |

**The meter reads the final samples of the render, on both platforms.** It is the last stage of `VibeMasterBusRender` (`../AudioPlayer+Pipeline.h`): post-bus, post-varispeed, after the FX returns have re-entered beside the dry path, and before the debug `--silent` zero — so the bars follow what actually reaches the device, wet tails included, and macOS with FX switched off is the same render as iOS. `AudioPlayer.applyLevelMeterOnQueue` creates the meter at the first demand and keeps it: a demand toggle is the render's pointer and a publisher session, live, and an install restarts the accumulator and the analyzer — its partial window and its references — so no earlier audio is published: the meter is kept across demand changes, and restarting the accumulator alone let the previous track's partial window open the next session's bars. The render reads the session once, at the callback's entry: it is the identity the callback restarts on and the one it publishes into, so a callback that began before a remove-and-reinstall publishes into the session that ended, and the publisher drops it; read again at publication, it labelled the previous session's audio with the new one. The meter is freed only for a replacement — the output's rate or the normalization mode — once the render was seen outside it (`dropLevelMeterOnQueue`; a render stuck past the wait's bound keeps it alive until then).

**The analyzer accumulates whole windows; the meter publishes about every 100 ms.** Every slice goes straight to the analyzer, which copies it into its partial window, analyzes each window in the callback that fills it — so the FFT work is spread across callbacks instead of several windows landing in one — and folds the result into a running summary. `VibeLevelPublicationFrameCount` (about 100 ms) is the publication cadence: once the meter has fed that many frames it summarizes the windows so far and publishes once. Analyzer storage is fixed for the maximum supported FFT and sized once at the meter's rate: a meter has one sample rate for its life, and an output rate change drops it and applies a new one (`setMasterBusFormatOnQueue:`). Relative activity updates and normalizes each band's private reference per window, then retains the largest normalized level per band. Shared spectrum converts each band's integrated energy to energy per octave, averages it across those windows, advances its one reference once for the full analyzed duration, and normalizes the coherent five-band average. Balanced spectrum combines those existing summaries without another FFT or callback cadence. The meter publishes the selected callback summary once.

The analysis clock is bounded and independent of the screen. `VibeLevelFFTSizeForSampleRate` chooses the nearest power-of-two window to about 24 decisions per second, from 256 through 8192 frames, so a high-rate route does not multiply decision cadence. The window grows with sample rate — 8192 points at 192 kHz versus 2048 at 48 kHz — so each high-rate decision still has more FFT arithmetic. Five explicit bands span 40–100, 100–250, 250–800, 800–4000 and 4000–20000 Hz, reserving the first three bars for bass and low mids; routes above 40 kHz never spend a bar on ultrasonic content. Each edge maps with `ceil` to the first FFT bin whose center is at or above it, and the same edge is the exclusive top of one half-open band and the bottom of the next. A below-edge bin therefore cannot leak into a band, and no bin can drive two bars. Left and right are transformed separately and their power is averaged after magnitude-squaring, so opposite-polarity stereo cannot cancel to false silence. FFT energy is normalized by window size before the selected reference and level mapping, keeping the tuning stable across sample rates.

The default `VibeAudioLevelNormalizationModeBalancedSpectrum` starts from the coherent shared energy-per-octave callback average, reserves 9% display headroom, and adds a shared-support-gated 35% of only the positive difference to the existing per-window private-reference activity summary; unsupported bands remain dark. It reuses one FFT and callback cadence. `VibeAudioLevelNormalizationModeSharedSpectrum` remains the unmodified common-reference endpoint, while `VibeAudioLevelNormalizationModeRelativeActivity` remains the unmodified five-private-reference endpoint. The `spectrum` and `activity` debug tokens expose those endpoints for comparison. None claims to reconstruct Apple's visualizer: Apple's band mapping and normalization are not public and are not inferred here.

`VibeLevelMeterRender` is a checked realtime function (`CA_REALTIME_API` under `-Werror=function-effects`): it allocates nothing, takes no locks, performs no logging and sends no Objective-C message; the analyzer's vDSP FFT is wrapped inside the analyzer for the checker, the publisher's writes are declared `CA_REALTIME_API` outside the checked region, and the analyzer's accumulation and summary are checked with it. `AudioLevelAnalyzer` uses preallocated plain storage, and `AudioLevelPublisher` makes the five values available as one versioned snapshot with a new sequence. The audio thread never performs display smoothing. The consumer, activity and animation contracts live with the shared renderer in `../../Controls/CLAUDE.md`.

The meter is absent whenever nothing can draw it. **The demand is the indicators', not play intent** — each shell counts active indicators declaring themselves consumers through `equalizerLevelsWanted:` and enables levels only while modeled output audio and material visibility also hold. Stopping an indicator destroys its poller and balances demand immediately, so the meter and poller are both absent at zero. An audio-only stop may leave one finite compositor release to dots, but it owns no analyzer, timer, callback or app-side frame loop; any pixel or ownership loss cancels it immediately. `../../iOS/CLAUDE.md` and `../../Playlist/Mac/CLAUDE.md` own those platform facts. A failed temporary installation is nil rather than inert, so a later eligible output-start edge can retry.

`AudioPlayer.outputAudioActive` is the nonblocking liveness fact the shells use: the output running and either the current voice playing or a voice still fading out is active; Loading intent by itself is not, and a paused voice is inactive the moment the pause is published. Its delegate edge is delivered on main only when that modeled value changes. **No "wet tail is now silent" fact is modeled**: a reverb or delay tail after every voice has stopped is never approximated with a wakeup timer.

**The meter needs no reconciling against the route**, because it is not on one: it is the last stage of the render whether the FX segment is in it or not, and a rate change replaces it at the new rate rather than retuning it in place. The iOS media-services reset (`AudioPlayer.dropEngineBoundStateOnQueue`) retires the meter with the rest of the pipeline rather than messaging anything defunct.

Normalization mode is immutable for one `AudioLevelMeter`. Debug `set_equalizer_mode balanced|activity|spectrum` synchronously reconciles the audio queue: changing an active mode ends the old publisher session, retires and replaces the meter, and starts with an empty partial window and fresh reference history; changing it while inactive stores the choice for the next eligible meter. A rate change likewise creates fresh analyzer history (a source-segment rebuild at the same rate keeps the meter), and the selected mode is retained for the rest of that app process. No mode is persisted, so every launch starts in `balanced`.

The tunable audio half is `AudioLevelMath.h` — analysis cadence, band edges, energy aggregation, normalization and running references — header-only and tested. Display target threshold and attack/release animation durations live separately in `../../Controls/EqualizerAnimationMath.h`, so changing visual motion cannot increase FFT work.

**`--silent` zeroes the output's buffers *after* the meter**, so the bars are live under the debug scripts' default launch (`--no-audio-hw --silent`) and under `--silent` alone; `dump_equalizer` reports the flags. `--no-audio-hw` drives the same render from the debug pump and is suitable for functional bar/counter checks, but not audible-start-latency measurements. On the iOS simulator use `VIBE_AUDIBLE=1` for reactive validation.

## Beta signal probe

`VIBE_VERBOSE_LOGGING=1` automatically arms the existing meter on every voice start, resume and seek, on gapless promotion and when a meter appears during playback; no launch argument is needed. On hardware, each start also holds the meter itself (`_signalProbeWanted`) from the voice start until its capture completes, so a hidden indicator — the playlist collapsed, or a theme hiding the number column, as on #47's Mac — still yields a measurement; the hold is released on the player queue, never from inside the meter's own completion, and only by the newest request. The debug pump never holds it (the hold needs `drivesOutputDeviceOnQueue`), and a missing meter still logs unavailable. Each request observes through the first buffer containing signal above −60 dBFS, bounded to three seconds of wall time or captured frames, and records sample time, buffer host time, frame offset, observed leading silence in milliseconds, peak, finite-sample RMS and nonfinite count over that window. Before first signal, a rate change removes the meter, which completes the capture as "meter removed".

The meter owns the accumulators and lock-free atomic result words, and the capture is a C function over the render's channel pointers and stamp. It performs no allocation, locks, logging or file reads; the player queue polls every 100 ms and emits one summary on first signal or expiry. Removal and replacement complete immediately with the last coherent partial capture, or explicitly report no buffers; stale polls cannot complete a newer request. The terminal snapshot survives removal, and a busy read retains any prior coherent sample data with `snapshotBusy` set. Summaries retain the filename, play/voice and start reason after track publication; gapless keeps the owning play identifier but names the promoted file. Empty superseded summaries and per-arm chatter are omitted.

The pipeline's own clock anchors each start: the master bus's frames rendered plus the block in flight, the same on every carrier. Block timestamps exclude older audio. An outgoing fade blocks capture until the drain sees the last fading voice dead, padded by the varispeed's declared latency when the varispeed is in the chain (`Audio/CLAUDE.md`); the meter retains that boundary if it arrives before deferred arming. Every carrier supplies the exact next frame, and on the sample clock every offset is computed in whole frames. `observationStartMS` exposes the excluded prefix, `observedLeadingSilenceMS` counts only inspected silent frames, and `firstSignalAfterStartMS` locates the threshold crossing relative to the start, or is −1 if none was observed. Discarded overlap is never counted as silence. A missing start clock is explicitly unavailable.

These are **post-mix samples**, potentially including FX tails, not DAC or acoustic measurements or an isolated file analysis. A late meter can miss the file's beginning, and no threshold crossing means the observed silence is a lower bound over captured frames. Keep the playlist’s equalizer visible and active when collecting them under the manual pump, which has no independent probe hold. `--silent` leaves the meter’s signal intact and zeroes only the later output buffers. Signal-enabled render tests retain full PCM comparisons and exercise loud-track replacement, long fades, sample-rate conversion and gapless promotion.
