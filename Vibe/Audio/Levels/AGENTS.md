# Live output levels

The demand-driven output meter behind the shared equalizer indicator. It is separate from `../Analysis/`, the offline BPM and key detection. Nothing here opens or analyzes a file. The root `AGENTS.md` equalizer guarantees are the contract. This is the producer half. The consumer, activity and animation contracts are `../../Controls/AGENTS.md`'s.

| File | Owns |
| --- | --- |
| `AudioLevelMeter.{h,m}` | The meter: the render's entry `VibeLevelMeterRender`, its ~100 ms publication cadence, the lifetime of one publisher session, `remove`, and the beta signal probe. |
| `AudioLevelAnalyzer.{h,m}` | The preallocated FFT, window accumulation, stereo-power combination and the mode's summary across windows. No publication or view knowledge. |
| `AudioLevelPublisher.{h,m}` | The coherent player-lifetime snapshot, session validity and the monotonic sequence the display reads. |
| `AudioLevelPublisherInternal.h` | The narrow meter-session writer API and the publisher's state. Display clients never import it. The debug counters are read in `Vibe/Debug/Seams/AudioLevelPublisher+Debug.m`. |
| `AudioLevelMath.h` | Tested numeric decisions: cadence, band edges, energy scaling, normalization and level mapping. |

`AudioPlayer.levelsEnabled` installs an `AudioLevelMeter`, the **meter**. It is a plain C struct (`VibeLevelMeter`) the render feeds through `VibeLevelMeterRender`. `copyBandLevels:count:sequence:` reads the latest coherent five-level snapshot without the player queue or an allocation. The `AudioLevelPublisher` lives as long as the player, and each installation gets a new session. The sequence tells a new result from a repeated read. An ended session's snapshot is unavailable at once.

## The meter in the render

**The meter reads the final samples of the render, on both platforms.** It is the last stage of `VibeMasterBusRender` (`../AudioMasterBus.h`) but the volume. It is after the bus, the varispeed and the FX returns, and before the mac's volume and the debug `--silent` zero. So the bars follow what reaches the device at full volume, wet tails included, and do not shrink with the volume slider.

**The meter is created at the first demand and kept.** `AudioPlayer.applyLevelMeterOnQueue` points the render at it and begins a publisher session while levels are wanted. It withdraws the pointer and ends the session otherwise, live and without waiting. **TRAP: a new session restarts the accumulator and the analyzer**, its partial window and references included (`AudioLevelMeter.m`). The meter is kept across demand changes, so the previous track's audio would otherwise open the next session's bars. **TRAP: the render reads the session once, at the callback's entry**, and both restarts on it and publishes into it. A callback that began before a remove-and-reinstall then publishes into the ended session, and the publisher drops it. Read again at publication, it would label the old session's audio as the new one's.

**The meter is freed only for a replacement**: the output's rate or the normalization mode changing, or the iOS media-services reset. It is freed once the render was seen outside it (`dropLevelMeterOnQueue`). A render stuck past the wait's bound keeps it alive until then. The meter needs no reconciling against the route, since it is a fixed stage of the render whether the FX segment is in or not.

`VibeLevelMeterRender` is a checked realtime function (`CA_REALTIME_API` under `-Werror=function-effects`). It allocates nothing, takes no locks, logs nothing and sends no Objective-C message. The analyzer's vDSP FFT is wrapped for the checker. The publisher's writes are declared `CA_REALTIME_API` outside the checked region. The audio thread never smooths for display.

## Analysis

**The analyzer accumulates whole windows; the meter publishes about every 100 ms.** Every slice goes to the analyzer, which copies it into its partial window and analyzes each window in the callback that fills it. That spreads the FFT work across callbacks. Once the meter has fed `VibeLevelPublicationFrameCount` frames, it summarizes the windows so far and publishes once. Analyzer storage is allocated once for the maximum FFT size. The meter's rate selects the working window. A meter has one rate for its life, and an output rate change replaces it (`setMasterBusFormatOnQueue:`).

The analysis clock is bounded and independent of the screen. `VibeLevelFFTSizeForSampleRate` picks the power-of-two window nearest about 24 decisions per second, from 256 through 8192 frames. So a high-rate route does not multiply the decision rate, though each decision does more FFT work (8192 points at 192 kHz against 2048 at 48 kHz). Five bands span 40–100, 100–250, 250–800, 800–4000 and 4000–20000 Hz, keeping three bars for bass and low mids. Routes above 40 kHz never spend a bar on ultrasonic content. Each edge maps with `ceil` to the first bin whose center is at or above it, and is the exclusive top of one band and the bottom of the next. So no bin leaks below an edge or drives two bars. Left and right are transformed separately and their power is averaged, so opposite-polarity stereo cannot cancel to false silence. FFT energy is normalized by window size, keeping the tuning stable across rates.

**Three normalization modes, one FFT.** Relative activity normalizes each band against its own private reference per window and keeps each band's largest level. Shared spectrum converts each band's energy to energy per octave, averages it across the windows, and normalizes the five bands against one common reference. The default, balanced spectrum (`VibeAudioLevelNormalizationModeBalancedSpectrum`), starts from the shared level. Where the activity level is higher, it moves 35% of the way toward it, gated by shared support, so unsupported bands stay dark. The result keeps 9% display headroom. It reuses the same FFT and cadence. `VibeAudioLevelNormalizationModeSharedSpectrum` and `VibeAudioLevelNormalizationModeRelativeActivity` are the two unmodified endpoints. None claims to reconstruct Apple's visualizer, whose band mapping and normalization are not public.

A meter's mode is fixed for its life. Debug `set_equalizer_mode balanced|activity|spectrum` reconciles the audio queue synchronously. Changing an active mode ends the publisher session and replaces the meter, with fresh history. Changing it while inactive stores the choice for the next meter. The mode lasts for the process and is never persisted, so every launch starts in `balanced`.

The tunable audio half is `AudioLevelMath.h`. The display threshold and the attack/release durations are `../../Controls/EqualizerAnimationMath.h`, so changing visual motion cannot add FFT work.

## Demand

Outside the beta signal probe, the meter is absent whenever nothing can draw it. **The demand is the indicators', not play intent.** Each shell counts indicators declaring themselves consumers through `equalizerLevelsWanted:`, and enables levels only while modeled output audio (`AudioPlayer.outputAudioActive`, `Audio/AGENTS.md`) and material visibility also hold. Stopping an indicator balances demand at once, so the poller stops at zero. The meter is withdrawn too unless a beta signal probe holds it. The platform halves are `../../iOS/AGENTS.md` and `../../Playlist/Mac/AGENTS.md`. A failed temporary installation is nil rather than inert, so a later output-start edge can retry.

**`--silent` zeroes the output's buffers *after* the meter** (it is the volume stage's target of 0). So the bars are live under the debug scripts' default launch (`--no-audio-hw --silent`) and under `--silent` alone. `dump_equalizer` reports the flags. `--no-audio-hw` drives the same render from the debug pump. It suits functional bar and counter checks, not audible-start-latency measurements. On the iOS simulator use `VIBE_AUDIBLE=1` for reactive validation.

## Beta signal probe

With `VIBE_VERBOSE_LOGGING=1` the existing meter is armed on every voice start, resume and seek, gapless promotion, output format change, device rebind and iOS output recovery, and when a meter appears during playback. On hardware each start also holds the meter itself (`_signalProbeWanted`) until its capture completes, so a hidden indicator still yields a measurement. The hold is released on the player queue, never from inside the meter's completion, and only by the newest request. The debug pump never holds it (the hold needs `drivesOutputDeviceOnQueue`), and a missing meter logs unavailable.

Each request observes through the first buffer with signal at or above −60 dBFS, bounded to three seconds of accumulated poll intervals or captured frames. A delayed poll can extend the wall time. It records sample time, buffer host time, frame offset, observed leading silence in milliseconds, peak, finite-sample RMS and the nonfinite count. Before first signal, a rate change removes the meter, which completes the capture as "meter removed".

The meter owns the accumulators and lock-free result words. The capture is a C function over the render's channel pointers and stamp, with no allocation, locks, logging or file reads. The player queue polls every 100 ms and emits one summary on first signal or expiry. Removal and replacement complete at once with the last coherent partial capture, or report no buffers. Stale polls cannot complete a newer request. A busy read keeps any prior coherent sample data with `snapshotBusy` set. Summaries keep the filename, play, voice and start reason. Gapless keeps the owning play identifier but names the promoted file. Empty superseded summaries are omitted.

The pipeline's own clock anchors each start: the master bus's frames rendered plus the block in flight, the same under the output unit and the pump. An outgoing fade blocks capture until the drain sees the last fading voice dead. That cutoff is padded by the varispeed's delay while the varispeed is in the chain (`Audio/AGENTS.md`). The meter keeps that boundary if it arrives before deferred arming. Every offset is computed in whole frames. `observationStartMS` exposes the excluded prefix. `observedLeadingSilenceMS` counts only inspected silent frames. `firstSignalAfterStartMS` locates the threshold crossing relative to the start, or is −1 if none was seen. A missing start clock is reported unavailable.

These are **post-mix samples**, FX tails included, not DAC or acoustic measurements. A late meter can miss the file's beginning. With no threshold crossing, the observed silence is a lower bound. Under the manual pump, which has no probe hold, keep the playlist's equalizer visible and active while collecting them.
