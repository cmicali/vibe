# Audio

The playback engine: `AudioPlayer` and its categories, `AudioVoiceBus`, `AudioTrack`, `AudioError`, `MusicalKey.h`, and the fade math. Every feature beside it has its own `CLAUDE.md`: `FX/` (the DJ master-bus segment), `Loading/` (materialization, admission, the transfer registry), `Metadata/`, `Waveform/` (data only; rendering is `Vibe/WaveformUI/`), `Analysis/`, `Levels/`, `Mac/Devices/`, `Mac/Convert/` and `iOS/`.

## The model in one page

Vibe owns playback; `AVAudioEngine` only carries it. One `AVAudioSourceNode` is fed by the **voice bus** (`AudioVoiceBus`): decode → ring → per-frame gain → mix, on both platforms. The graph is `voice bus → [varispeed] → mainMixer → [FX] → output`; the FX segment, the level tap and `AVAudioSession` are Apple's, untouched. On macOS the output is Vibe's too: the engine renders in realtime manual mode and a hosted HAL output unit bound to the chosen device pulls it from its render callback (`AudioPlayer+Graph.h`, `Mac/Devices/CLAUDE.md`); iOS keeps the engine's output node.

- A **voice** is one file being rendered: a decoder filling a ring, a gain with at most one pending ramp, an optional queued successor file. At most one voice is **current** — the transport's track — and the rest are **retiring**, fading out after a track change, seek or stop, and dying on their own.
- The **transport** (`AudioPlayer.m`) is the state machine `{Stopped, Loading, Playing, Paused}`. Every verb publishes its new state and delivers its delegate event **at once, on the queue**; the audio follows within the declick length. Nothing in the transport waits for a fade.
- The transport hears three things from the bus, through a **drain** it runs itself: a voice went **live** (its first frames are buffered), the current voice passed its **boundary** into the queued successor (promote, `didAutoAdvance`), a voice **ended** (the current one: `didFinishPlaying`; a retiring one: the output-liveness fold).
- **Every fade exists only to keep the output click-free.** A ramp is evaluated per frame on the audio thread from the frame index, so it lands on its target exactly. **Bit-perfect output ramps its edges or nothing**: with Declick on, the default, every transport edge is the ≤10 ms declick and every other frame is untouched; with it off every edge is a cut, because a ramp changes the bitstream.

The reading path is `AudioPlayer.h` → `AudioPlayer.m` → `AudioVoiceBus.h` → `AudioPlayer+Graph.h` → the platform half.

| `iOS/AudioPlayer+Recovery` | session verdicts (`iOS/CLAUDE.md`) |

**`AudioPlayer.m` is the single writer of the state it publishes; each category owns one vocabulary and declares its methods in its own header.** All of them share `AudioPlayerInternal.h`. **That shared header is the cost of every split**: a category that pushes more state into it than it takes out of `AudioPlayer.m` is not worth making.

**State is `{Stopped, Playing, Paused, Loading}`, and Loading keeps its intent live.** Loading covers the in-flight open and reports zero position and duration; play/pause during it toggles whether the opened file starts or parks, and a seek replaces its start position. Exactly one of `isPlaying`/`isPaused`/`isStopped` is true; `isLoading` is orthogonal. A pause reports Paused the moment it is requested. An action that must order itself after already-submitted transport commands calls `getPlaybackIntent:forTrack:` once: Loading answers the request's intent, otherwise `(position, state == Paused)`.

**`PlaybackRequestCoordinator` owns the in-flight open**: identity, row, intent, slow-load state and what the delegate must be told (Foundation-only, tested). An identifier is never reused, not even across `invalidate`, so a worker blocked on a dead mount cannot consume a later open of the same path. A re-drop or replay rebinds the row in place instead of starting a second open, re-firing `didBeginLoading:` when the request is already slow. A seek is accepted on either identity, the row or the exact submitted play, because the identifier covers a seek issued before its play reached the queue and the row one issued after.

**The published tuple is written whole.** `publishState:voice:file:startSeconds:baseFrames:` writes state, voice, file (as rate and length scalars, so a getter never messages an object) and the position's origin under `_stateLock` in one acquisition; the two `unpublishVoiceOnQueue…` variants are the only partial writers, safe because they never move the origin. Position is `startSeconds + (consumed − promotedBaseFrames) / busRate`, read from the voice's own counter, so it holds across an engine stop and needs no cache.

## The voice bus

`AudioVoiceBus.h` carries the contract; this is the shape.

**Format.** The source node has one format for the bus's life, so the bus owns conversion. Ordinary playback: float32 non-interleaved at the mixer's output rate and channels — on macOS the bound device's rate — so a mode toggle or a device rate change rebuilds the segment. Bit-perfect: the current file's rate and channels, rebuilt at a settlement or mode toggle. A file whose format differs is converted on the decode queue by `AVAudioConverter` at maximum quality (mono→stereo is an explicit channel map). The 16-bit bit-perfect decode of a lossy source keeps its one rounding: the converter goes to Int16 and the decoder expands back to float exactly (`v / 32768`), so the mixer and output unit carry 16-bit-grid values unchanged. `decodeFormatOnQueueForFile:` is the voice's **decode format**.

**Slots.** Eight, each a plain C struct with a power-of-two ring of at least one second at the bus rate, allocated once and owned by the render block through an associated object, so a defunct engine's late render touches valid memory. State `free → armed → live → dead → free`, one owner per transition: the queue does free→armed and armed→dead, the decoder armed→live, **only the audio thread live→dead** (end of stream, or a retire landing; a kill is a retire of zero frames). dead→free runs on the decode queue after a render has completed past the death, so no reader or writer is inside the slot. Counters are never reset: `written` and `consumed` are monotonic for the slot's life, and the recycle aligns them. A start never fails: at two free slots the oldest retiring voice is cut, and a start that still finds none is **pending**, bound to the first slot the drain frees. **Every started voice ends exactly once through the drain**, a pending one killed before it had a slot included.

**The audio thread** runs `VibeVoiceBusRender`, a C function under `CA_REALTIME_API` and `-Werror=function-effects`: a lock, allocation, Objective-C send or dispatch call is a build error. It reads plain memory and atomics, writes the buffers, takes its stamps from the block's timestamp, and never signals anyone. Per live voice: adopt a new ramp sequence from the current gain (adoption un-pauses; zero frames land at once); mix `min(frames, written − consumed)` at the per-frame gain; zero-fill the rest as an underrun unless the end is known; land a pause or retire on its exact frame. `renderSequence` and `inRender` let the queue tell "no render is inside any slot" from "the engine says it is stopped".

**Gain.** One 64-bit atomic per voice: target, frames, curve, action (none / pause / retire), sequence. The declick curve is **linear** — a 10 ms log ramp's last-sample slope fails the envelope bound at 44.1 kHz — and every longer fade is one side of an equal-power crossfade (`FadeMath.h`, tested per frame). **Bit-perfect with Declick off: every ramp is zero frames** (`leavesSamplesUntouchedOnQueue`, the one gain rule; `bitPerfectOnQueue` is the mode itself, which the segment choice reads). With it on, `rampOnQueueToGain:` clamps every ramp to the declick length — the crossfade setting is already held at the minimum under the mode, but a play submitted before the mode landed carries the length it was retired with — so the only gain the mode ever applies is 10 ms per edge. Nothing renders under a stopped engine, so retiring voices are killed there and a pause is a cut that lands at the first render after any restart.

**The decoder** is one serial queue (`QOS_CLASS_USER_INTERACTIVE`), or the caller's thread under the frame-driven test pump, in single-chunk turns of 4096 frames so a start never waits behind a full fill (initial fill eight chunks, live at one, topped up below half). It is the only thing that touches an `AVAudioFile` after a start. **End of stream is a read that returns no frames or an error**, never `framePosition == length`, so a truncated file ends. A voice retired at declick length reads no more, so its file may be handed to the next voice at once.

**The successor.** `queueSuccessor:` hands the parked file to the current voice; the decoder continues into it at the file's end and publishes the **boundary** before the successor's first frames, so a render that sees them sees where they begin. The hand-off is one atomic `{none, queued, switching}`: the decoder wins queued→switching, an unqueue wins queued→none, and whoever loses has its answer. **A stream that ended before its successor was named is reopened**: a file shorter than the ring decodes whole before its boundary renders, so a live voice still takes a successor after its end — the decoder publishes the boundary at the old end and withdraws the end; a render that had already loaded the end dies at it, and the ordinary track end takes over. **One voice chains any number of successors**, so the drain reports boundaries by value, and the transport queues the next only after the previous one was reported.

**The drain** (`drainVoiceBusOnQueue`) binds pending voices, emits each voice's events in the order live → boundary → ended, tops up rings, and recycles dead slots. On hardware it is a 10 ms timer on the player queue **iff the engine is running and a slot is occupied** — nothing at idle, nothing while paused-and-idle-stopped — plus a hop from the decoder when a voice goes live; under the debug pump it runs after every rendered slice.

## Threading

**Every engine mutation runs on the serial player queue; the UI getters take the `os_unfair_lock` snapshot and compute off it**, never a queue round trip. The queue's QoS is Default, because it calls `AVAudioEngine` APIs that wait on the engine's own Default-QoS thread; the latency-critical work — the open and the decode — runs on its own lanes. The main mixer uses maximum render quality; `make test-audio` checks passband gain and alias rejection through the production graph.

**There are no staleness counters for the audio; the voice's identity is that job.** A `VibeVoiceID` is minted once per start and is the slot's generation for as long as it holds one, so a stale id never addresses a reused slot, and a ramp or event for a voice the transport no longer publishes is simply not the current voice. Deliveries to main are guarded by submitted-play identity (below), not by any counter.

## Crossfades, pauses and seeks

**`VibeIncomingFadeMilliseconds` (`FadeMath.h`, tested) is the one place that decides a fade's length.** `crossfadeMilliseconds` (default the 10 ms declick minimum; Settings > Playback offers 500 and 2000) applies only when a play replaces an audibly playing track; first plays, the pause/seek/stop declicks and `play:atPosition:startPaused:` force the minimum. A track change is a true crossfade on one bus: the outgoing voice fades on its own ramp while the incoming one fades in beside it, and nothing is rewired. **Bit-perfect output with Declick off writes no gain at all** (`leavesSamplesUntouchedOnQueue`): every edge cuts, and `testBitPerfectTransportCutsWithoutChangingSamples` requires every audible frame across seek, pause, resume, a track change and stop to continue an exact excerpt of the source. With Declick on, the default, each of those edges is the 10 ms declick and nothing else is touched (`testBitPerfectDeclickRampsOnlyTheEdges`); the choice is `AudioPlayer.declick`, pushed from Settings > Audio (`Mac/Devices/CLAUDE.md`).

**A voice that cannot be heard is killed, not faded** — not yet live, paused, cut by bit-perfect output, or under a stopped engine — and is silent at once, so only fading voices are `_retiringVoices` (`retiredFades` in the debug channel). Stop, pause, a parked play and the failure reset cut every retiring voice to the declick length; skips never do, so rapid skips keep the full fade-out.

**A seek is a new voice at the target with the old one fading out beside it**: one shape for playing and paused, nothing rescheduled, nothing to wait for; `didFinishSeeking:` settles every seek, dropped ones included. **A pause fades the voice to silence and stops consuming on the exact landing frame**; a resume is a newer ramp, which un-pauses by being newer. The engine's deferred idle stop (Stopped or Paused, ~6 s, releasing the output device) is cancelled by generation in `startEngineOnQueue:`, the one funnel every start and resume goes through. Voices keep their state across an engine stop, so a paused idle stop, a device rebind and an iOS configuration change reschedule nothing.

**The source segment is built lazily** at the first settlement, and rebuilt only when the mode or the bus format the file wants differs — a rebuild kills every voice, so its callers guarantee nothing audible and re-voice at the retained intent (`Mac/Devices/CLAUDE.md`). Pitch is the one varispeed's rate and bypass (a ratio of 1.0 is not a pass-through, so zero pitch bypasses); bit-perfect output has no varispeed.

## Prefetch and gapless

**`prefetchTrack:` on every track start pre-opens the likely next track, and the next `play:` of that path consumes the parked `AVAudioFile`.** The request state is `AudioPrefetchRules.h`: a different-path prefetch requested while an open is in flight is retained and suppressed, resumed by that open's success and dropped by its failure, abandonment, a newer play (same-path rebind included) or a later prefetch; its identity also drops every late callback. There is no acknowledgement handshake with the loading side, because the foreground rule is derived inside the coordinator (`Loading/CLAUDE.md`).

**At play submission an unrelated prefetch is cancelled before the foreground open starts**, so its transfer cannot compete with the file the user chose. A same-path prefetch stays alive: its handle run and the playback run ride one path claim, whichever succeeds first consumes the play request, and the winner retires the loser's park state so the current track cannot become its own successor.

**The successor is the park itself.** With the crossfade at its minimum (`VibeGaplessArmAllowed`) — and, under bit-perfect output, the next file wanting the device's current rate and channels, since a continuation on one voice cannot switch the device — `maybeArmSuccessorOnQueue` queues the parked file on the current voice. No second handle exists: the bus's decoder is the only reader of a file after a voice starts. The boundary event promotes the successor in place — same voice, no stop, no fade — with the bus frames consumed before it as the new base for the position, fires `didAutoAdvanceFromTrack:toTrack:` so the controller advances the playlist without `play:`, and **consumes the park**, so a replay of the promoted row opens fresh. **A track's end fires exactly one of `didFinishPlaying:` or the auto-advance callback, never both.** When the playlist's next changes under a queued successor, or the crossfade setting is raised, `unqueueSuccessorOnQueue` drops it and the voice ends at its own file; lowering the setting re-queues the park.

CoreAudio honors LAME/iTunes gapless metadata, so tagged MP3/AAC and all lossless files continue seamlessly; an untagged MP3's encoder padding is the one gap this cannot remove. `isGaplessArmed` surfaces the queued state to `dump_state`.

**A main-thread action snapshots its track at dispatch**, because a promote can land between the action and its queue block: `seekToPosition:` and `finishCurrentTrack` drop the request if the boundary advanced it.

## Settlement identity

**A settlement for a superseded submission is never delivered, and it is matched by submitted-play identity, never by track** (root `CLAUDE.md`: a same-row replay is the same `AudioTrack` and the same URL). `didStartPlaying:` and the play-path errors are dropped on main by `submittedPlayIsCurrent:`, checked inside the delivery block because what matters is whether a newer play existed when the callback ran. The comparison is `PlaybackDeliveryRules.h` (tested): `VibePlaybackDeliveryIsCurrent`, and `VibePlaybackSubmissionStateIsUnchanged` for the media-services reset, where zero is a valid initial snapshot because a reset is not a play. The coordinator's own rule ("a superseded open's result is never consumed") cannot cover this: once a result is dispatched to main, nothing can retract it.

Track-end captures its track and submission before optional device recovery, since a failed bind resets the active identifier. A failure reset defers saved-device resolution until its caller has returned, and never schedules a retry from an already-active lookup.

**Resume and seek-restart failures use the same identity even though their errors carry no URL.** They belong to the sounding voice, whose `_activeSubmittedPlayIdentifier` survives gapless promotion; a same-row replay could otherwise make the shell accept the old generic error and tear down the newer play's state.

**TRAP: the counter is `_nextSubmittedPlayIdentifier`, which only increments, never `_lastSubmittedPlayIdentifier`**, the pre-Loading handoff cleared to 0 as soon as its play reaches Loading. Comparing against that one reports every settlement as superseded, delivers nothing, and strands whatever the shells release on settlement.

## Opening a file

**Files open off-queue against an abandon deadline, so a cloud placeholder cannot wedge playback**; a slow open surfaces Loading instead. `AudioFileOpenTimeoutMath.h` (`Loading/`) owns the monotonic deadline: a 60 s no-progress baseline both platforms share, extended (never shortened) to 60 s past each positive raw movement. `AudioLoadingConfiguration.openTimeouts` is snapshotted when the underlying open starts, so a mid-open configuration change cannot move its deadline.

**Progress is matched by the underlying open identifier, never by path or submitted-play identity.** A same-row replay changes submission identity but keeps the same `PlaybackRequestCoordinator.identifier`, transfer, monitor baseline and timeout snapshot; a later retry of that URL gets a new identifier, so a callback retained by the previous monitor cannot extend it. `didBeginLoading:` carries the open identifier to both shells, its main-thread delivery guarded separately by submitted-play identity. The player accepts `noteOpenProgressForOpenRequestIdentifier:` only while both the pending request and the playback-open slot carry the identifier. The claim, admission and transfer-publication machinery underneath is `Loading/CLAUDE.md`'s.

**`stop` (File > Close) unloads outright and fires no transport or track-end callback** (root `CLAUDE.md`): it supersedes any in-flight open so a Loading track never starts and fades the voice to silence; the caller owns the UI reset. Every failure path lands in the same `resetToStoppedStateOnQueue`, which retires the current voice, invalidates the open, drops the park and the successor, and publishes Stopped.

## Live output levels

**`levelsEnabled` installs the demand-driven tap in `Levels/`**; `copyBandLevels:count:sequence:` reads the latest coherent snapshot without the player queue or an allocation. `outputAudioActive` is the shell-facing liveness fact: the engine running and either the current voice playing or a voice still fading; Loading intent alone is not, and a paused voice is inactive the moment the pause is published.

**TRAP: every master-bus rewire must reconcile the tap on the new output path.** `reconnectMasterBusOnQueueWithFormat:` removes the old tap and calls `applyLevelTapOnQueue`; init, live FX routing and device-rate changes share it. `dropEngineBoundStateOnQueue` abandons rather than removes a tap bound to a defunct engine. The ownership, callback, FFT, publication, demand and `--silent` contracts are `Levels/CLAUDE.md`'s.

## Error text

**`VibeAudioError*` descriptions are for logs and are never localized.** The one line a screen shows is `VibeStatusForPlayError` (`AudioErrorRules.h`, tested), mapping `VibeAudioErrorCode` to a `STR_ERROR_*` string; it lives beside the enum because both screens render the same wording.

## Beta diagnostics

With `VIBE_VERBOSE_LOGGING=1`, `Timeline:` joins input/submission, queue admission, open settlement, the voice start, the first render (the voice's live event and its start-of-consumption stamp), callback decisions/delivery and the first UI position **beyond the published playing position**. `Phase:` brackets output preparation, format confirmation, ownership, device pin and engine start. `Callback:` lines report every bus event with the voice's consumed and underrun counts; `Recovery:` explains device decisions. `Stall:` reports main-thread, player-queue and output-render-clock stalls, and on macOS the IO cycles the hosted output unit wrote as silence because the engine could not render (`outputDropouts`, cumulative, in `debugEngineCounts` and `dump_health`): a stuck thread is sampled 250 ms in and every 500 ms after, six times at most, an unchanged sample in one line; the player queue through whichever pool thread `THREAD_IDENTIFIER_INFO` says is draining it, and a stalled render clock samples CoreAudio's `com.apple.audio.IOThread.client`. **TRAP: the unified log truncates a message near 1 KB**, so a sample spans numbered `Stall stack:` lines; Vibe's frames are offsets into the executable: `atos -o <dSYM DWARF> -arch arm64 -l 0x100000000 <0x100000000 + offset>` names them, which is why each beta's dSYM is kept.

Every voice start, resume, seek, gapless promotion and late tap installation arms the bounded `Signal:` probe described in `Levels/CLAUDE.md`; it reads no file, and on hardware holds the tap only for each start's capture. The probe's origin is the output's render clock at the start — the hosted unit's frames rendered plus the block in flight on macOS, the engine's on iOS; its cutoff, when a track change is still fading out, is the render that saw the last fading voice die. **TRAP: the FX segment's dry path is about a millisecond behind the bus** — `AUNBandEQ` holds roughly 45 frames it never declares — so that cutoff is padded by `kMasterBusProcessingDelaySeconds` whenever the segment is in the chain, or the probe reads the outgoing track's tail as the incoming one's first signal (`AudioPlayer+Diagnostics.m`).
