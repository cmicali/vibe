# Util/Mac (AppKit only)

The AppKit half of `Vibe/Util/`, under the parent's admission test: **no feature**. The iOS mirror is `Util/iOS/`. A category on an AppKit class belongs here. A portable one belongs in `Util/Categories/`, and one on the app's own classes beside that class.

- **`Fonts`**: the app's typography. The five themed slots (`VibeFontSlot`, declared with the theme) resolve against the theme that `MainPlayerController.applyStoredFonts` **pushes** through `applyThemeFonts:`, since Util may not read a setting. Until the first push they resolve the factory look. An empty or uninstalled face falls back to the slot's built-in font, so a slot accessor never returns nil.
- **`WindowAnimation.h`**: `kWindowResizeAnimationDuration` (0.12s), the one resize timing the player and Settings windows share. No single feature owns it. Every programmatic resize uses it through `animationResizeTime:`, rather than AppKit's distance-scaled default, which drags on big jumps.
- **`TrackCommands`**: reveal in Finder, copy the files, and copy the names, over an array of tracks. Copying the files skips a remote placeholder, whose bytes no other app could read (`handsOutURL:`, tested in `NSURLUtilTests`). Menu validation reads no file, so Copy File stays enabled over a placeholder. When nothing is left to copy, it beeps. The playlist's drag out asks `handsOutURL:` too.
- **`NSColor+OKLCH`**: perceptual lightness and chroma clamping for the artwork-derived header wash, because HSB brightness is hue-blind (`Mac/MainWindow/APPEARANCE.md`).
- **`NSImage+Util`**: includes `dominantColor`, a forward to `Common/PlatformImage.h`'s `VibeDominantColorOfImage`. It also has `symbolNamed:pointSize:weight:palette:accessibilityDescription:`, the one way an SF Symbol is built with palette colors. The palette configuration is applied over the sized one, since a symbol image holds only one. Tested (`NSImageUtilTests`).
- **`NSView+DarkMode`**: the mirror of `iOS/`'s `UIView+DarkMode`. The separate names are what let `make check-layout` allow both. The file also holds `NSAppearance (DarkMode)`, the Aqua/DarkAqua `bestMatch` fold the view's `isDark` is written in terms of. A caller holding an appearance rather than a view asks that one, as `AppTheme`'s dynamic colors and its two-sided artwork wrapper do.
- **`NSDockTile+Util`**: the Dock tile and the app icon behind it.
  - `setDockIcon:shaped:` composes artwork onto the icon grid off main. With the theme's App icon shape off, it installs the picture as it is.
  - `setAppIcon:shaped:` composes a theme's custom icon the same way into `NSApp.applicationIconImage`, so the Dock, the app switcher and the About surfaces agree. Nil resets to the bundle icon.
  - `resetToAppIcon` puts the application's icon back in the tile. It reads the icon live, so a custom icon shows through.
  - The file's `TRAP:`s are the authority. One view is installed for good and only its image swaps, since detaching and re-installing a view leaks a 256KB dock-tile context per transition. Assigning `applicationIconImage` replaces the tile's content view, so every install re-attaches ours. **Each custom-icon-then-reset round trip of `applicationIconImage` also leaks one 256KB context inside AppKit's setter**, so `setAppIcon:shaped:` assigns only on a change.
- **`NSDraggingImageComponent+Util`**: the text label of a drag image.
