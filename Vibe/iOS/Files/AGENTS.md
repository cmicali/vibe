# The Files tab (iOS)

This directory holds the Files tab: the browser (`BrowserViewController`), with its paste row, its Open URL sheet (`OpenURLSheetController`) and `RecentsViewController`.
It also holds `FileRow`, the row pieces that Search, Favorites, the Playlist tab and the mini player share too.

The shell, `PlaybackController` and `FolderSession` are `../AGENTS.md`.

## BrowserViewController

The Files tab. It is also the Playlist tab's add sheet (`appending:YES`), where every action appends and closes the sheet; it is titled Add to Playlist at its root. One `UITableViewController` per level sits in a navigation controller. It is not a `UIDocumentBrowserViewController`, whose Open button spins forever under multi-select and whose floating bar collides with the tab bar.

**The root's groups** are Locations (On My iPhone, then Dropbox once linked, then `SearchFolderStore`'s folders), then Recents, then Choose File… and Open URL…, then the paste row while the clipboard holds a link. `VibeBrowserRootRows` (`../Search/FileSearchRules.h`, tested from the macOS suite) is the one answer to what a root row is. `VibeBrowserRootLocationIndex` beside it maps a Locations row to its folder in the store. Both read whether Dropbox was linked at the root's last reload, never the live account. The account flips off main before its change is posted. A live read in that gap would open or delete the folder beside the one shown. The root's plus menu holds Add Folder… and, until an account is linked, Connect to Dropbox…. It is built each time it opens. It then follows the account. **A directory lists its folders, then its M3U playlists, then its playable files and CUE sheets**, each in `AppSettings.folderOpenSort`'s order through `FolderWalk listDirectory:sortedBy:folders:playlists:audio:`. That is the open's own filter and sort, so a song row shown is a row that plays, in the order shown. A playlist is not part of its folder's play: a tap plays it, and its long press has no Play in Folder.

- **A file tap plays that file alone, where it was tapped. A folder tap opens it.** The browser, Search and Recents share this rule. A one-track open presents the card but keeps the tab (`playbackDidOpenNewFolder:`). A folder, a file in its folder, or several picks bring the Playlist tab forward first. The long press has Play in Folder on a file and Play on a folder. Every open is a `PlaybackController` road: `openFileURL:inFolder:` for a tap, `addURLs:` for an Add, and `bookmarkFolderURL:` then `FavoritesStore` for a folder's star.
- **A replace asks first when the playlist was built by hand.** Every replacing tap (the browser's, Recents', Search's and Favorites') goes through `PlaybackController`'s `confirmReplacingPlaylistFrom:openingURLs:inFolder:token:`. `PlaybackController.playlistHasAdditions` is `FolderSession.hasAdditions`, YES once an Add has landed or for a playlist restored with additions. The alert offers Replace, Add Instead and Cancel. Any other playlist is replaced at once.
- **A row says what a tap costs**: the file's size from the listing's stat (a placeholder carries the remote size), `VibeNotDownloadedMark` on a file not downloaded, and the Playlist tab's equalizer on the file now playing (`playbackDidMoveToCurrentTrack:`). That equalizer is held to the root guarantee as the Playlist tab's is (`../AGENTS.md`). The root sets the Files stack's exposure on its bottom browser (`equalizerSurfaceVisible`), each screen adds its own appearance, and the row must be in the viewport (`vibeIsInViewportOfTableView:`). **TRAP: nothing in a screen's initializer may touch the disk.** A screen is made on main as a folder opens, and for a provider's folder a stat or name lookup is IPC that can block.
- **A file's icon is its album art when the metadata cache holds it or its bytes are on the device, else a tile** (`VibeFileTileImage`). Every list row's icon slot (here, Recents, Search and Favorites) is set by `vibeApplyFileIconForName:folder:art:`. Names take two lines and truncate in the middle (`vibeApplyFileNameStyle`). These row pieces live in `FileRow`, not the browser, because every list screen shares them. The art comes from one `AudioTrackMetadataCache` per stack of folders (`stackArtCache`), asked for the rows on screen and a margin when a listing lands and when a scroll settles. **TRAP: a placeholder and a provider's dataless file are never parsed** (`loadArtForVisibleRows`). A parse's cache miss reads the tags from the file: ranged requests or a download for every row. They go to `loadCachedMetadata:`, which reads nothing on a miss. One cache serves the screen on top, and a screen that goes cancels its own scan, never its successor's. A mirrored folder on screen relists on `VibeDropboxDownloadsDidChangeNotification`, so a finished download drops its mark and gains its art.
- **A row being opened spins in its icon slot**, here and in Recents, Search and Favorites (`vibeApplyRowContent:opening:`). `PlaybackController.openingPath` names it from the tap (`replaceRequestTokenOpening:`, before any resolve) until the open lands, finds nothing, is superseded or is given up. `playbackDidChangeOpening:` redraws. A second tap gives it up (`cancelOpening`). A resolve still running is then dropped by the replace funnel, and an open the session holds is cancelled by `FolderSession.cancelOpen`, which settles like an empty open. `kOpeningTimeout` gives up too, with an alert from the root. A caller whose own work ends before the open (a failed resolve, Cancel or Add Instead, a favorite shown in Files) ends it with `endOpeningForReplaceRequest:`.
- **The filter field narrows a listing by name** (`applyFilter`), installed once a listing has a dozen rows. **TRAP: it is always shown, never hidden on scroll.** A collapsing search bar re-lays the bar out on the appearance callbacks the card forwards by hand, and the folder jumped under the card. It is `Stacked`, since iOS 26's integrated placement would put it in the bottom toolbar.
- **Select is multi-select Add.** It is a glyph, and named Select rather than Edit, since nothing is edited. While selecting, the title is the count, Select All takes the back button's place, and a listing or filter change is held. **TRAP: a row swipe sets `isEditing` too.** `isSelecting` excludes it through `_swipingRow`, or the bar flips into multi-select under the swipe.
- **The sort menu is titled "Sort folders by"**, the Settings row's own string, because it writes the one folder-open setting, not this folder's view. The add sheet has no sort menu; its bar carries Close at every level. The bar's items are absent, not disabled, in an empty folder.
- **A Dropbox directory draws from disk at once, then relists** (`DropboxMirror refreshDropboxFolder:`) when it appears, unless this screen listed it within `kRelistInterval`. Pull to refresh relists any directory. A relist that fails says so in a footer over rows already drawn, or in the empty state over none. An unlinked account pops the stack to the root. A sign-in started from the plus menu pushes the account's root when it lands.
- **Open URL… plays a web address** (`presentLinkSheet`). The sheet is `OpenURLSheetController`, modeled on the mac's window. It has a wrapping field with the URL keyboard, the system's Paste control, a spinner, and Cancel and Open. Open is disabled while the field is blank (`VibeLinkTextIsBlank`), and Return is Open. Open hands the field's text to the browser's `openLinkText:`, which takes a replace token through `PlaybackController`'s `openLinkString:replacingPlaylistFrom:completion:`. `LinkStore` resolves the link off main, and its file opens alone through `confirmReplacing…`. While it resolves, the field and Open are disabled. The browser says so through the sheet's `resolving`. Cancel or a swipe down cancels the resolve. A failure closes the sheet and shows `link.error.title` with `+[LinkStore messageForError:brief:]`. The completion runs before the replace question, so the sheet closes first and the question goes over `vibeTopmostPresenter`. The browser holds the resolve's cancel block, not `openingPath`, since a link names no file until it resolves. The paste row shares that block with the sheet. In the add sheet the add token is taken before the resolve and the file goes to `addURLs:token:`. A link never takes the inbox road, which does not persist. `open_url` drives the same method (`Loading/Net/AGENTS.md` has the store).

  **TRAP: the sheet is dismissed by its presenter** (`dismissThen:`). Asked of the sheet itself, a dismiss closes only an alert it presents. **TRAP: the system draws its Paste control out of process, blank and ignoring taps, when its content does not fit.** Its height scales with the text size, and it spans the field.
- **The paste row opens a copied link.** It shows only while the clipboard probably holds a web link: `UIPasteboard`'s `detectPatternsForPatterns:` for `ProbableWebURL`, or `hasURLs`. Neither reads the clipboard, so neither raises the paste prompt. The check runs when the root appears, when a scene activates and on `UIPasteboardChangedNotification`, and skips a `changeCount` already checked. A tap hands the clipboard's item providers to `pasteItemProviders:` (`pasteClipboardLink`). Loading one shows iOS's Allow Paste prompt unless the user allowed pasting in the Settings app (`../Settings/AGENTS.md`). It opens the first web link (`VibePasteLinkOfItems`) through `openLinkText:`, and text that is no link shows the invalid-link alert. **TRAP: a denied paste still lists its items, with their types.** Only the loads fail (`PBErrorDomain` 13). A paste whose items yielded nothing therefore says nothing. A second tap while it resolves cancels it. **TRAP: the action rows take the dynamic `UIColor.tintColor`**, never `self.view.tintColor`'s value, which is gray while a sheet dims the tint.
- **The system pickers remain for two jobs only.** Add Folder… grants a location (`SearchFolderStore addFolderURL:`, which refuses a covered one with a message), and Choose File… is a one-off multi-select pick. iCloud Drive has no item of its own, because public API cannot point the picker at it. A granted location opens in the browser, and nothing plays. A location is forgotten by the swipe Delete or the long press's Remove Location.
- **The play button plays this folder alone. Its long press plays it with its subfolders** (`openDirectoryWithSubfolders`; Add with Subfolders in the sheet). The walk goes depth first in the listing's order, asks Dropbox for each mirror folder first, and stops at `kMaximumSubfolderTracks` songs or `kMaximumSubfolders` folders and says so. The folders with songs open as one multi-URL open: the first is the base and the rest are additions. In a folder with no song directly inside, the button is its menu alone.
- **Recents is `FolderSession`'s list**: every file and folder opened or added, newest first, at most `kMaximumRecentItems`. **An open that brought more than five things is one entry, the folder they share**, or Play with Subfolders would replace the whole list in one tap. Each entry is recorded where the open lands, with the bookmark the open minted and its folder's display name. A restore records nothing, and Clear Playlist keeps them. The name is recorded, not derived, since the path can outlive the app container it names. `RecentsViewController` lists them. A file plays alone, a folder opens in the browser, and the long press adds Play, Play in Folder, Add to Playlist and Open Folder. **A link (`LinkStore`'s `containsURL:`) has neither folder action**, since its folder is the Links store's, named by a hash. Its second line is the link's host (`LinkStore hostOfLinkFileURL:`, recorded when the open lands). The bar's Clear opens a one-item destructive menu. It is absent while the list is empty, and in the add sheet.
- **An Add's rows fly into the Playlist tab** (`addedRowsHandler`, set by the shell on the root browser). The rows asked for are snapshotted and handed over before the request. `RootViewController` lifts them and flies them to the Playlist tab's item on `playback:didAppendTracksAtIndexes:`. It sets them back down when the settle says nothing landed, or when a superseding open lands empty or is cancelled (`playbackDidCancelOpening:`). There is no timer: every Add ends in `playback:didSettleAddLanding:`, and `check_consistency` reports rows never settled (`liftedRowTimes`). The flight is a UIKit keyframe animation, not a `CAAnimation`, because an iPhone caps an app's own Core Animation at 60 Hz without an Info.plist opt-out. `UITab` has no view, so the target is found by the label the bar draws.
- **Open Folder** (Search and Recents) is `showDirectory:highlighting:` on the root browser. The stack becomes one screen per folder from the covering source, built before the tab switches, and the file it came from is scrolled to and selected for a moment. A folder no persistent root covers (a one-off pick, from Recents) is listed under a scope the bottom screen holds for its lifetime (`_holdsScope`). An open made inside it takes the session's own hold from the recent's bookmark, so the playlist outlives the screen.
