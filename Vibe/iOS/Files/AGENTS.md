# The Files tab (iOS)

This directory holds the Files tab's browser. Its root is `FilesRootViewController`, with the paste row and the Open URL sheet (`OpenURLSheetController`). Each directory is a `FolderViewController`.
It holds `RecentsViewController` and the list it shows (`RecentsStore`).
It holds the Locations store (`LocationStore`) and the tab's rules (`BrowserRules.h`).
It holds `CueFolderGrantPrompt`, the folder picker a CUE sheet's open asks for (`../AGENTS.md`, FolderSession).
It also holds `FileRow`, the row pieces that Search, Favorites, the Playlist tab and the mini player share too.

The shell, `PlaybackController` and `FolderSession` are `../AGENTS.md`.

## The browser

The Files tab. It is also the Playlist tab's add sheet (`appending:YES`), where every action appends and closes the sheet; it is titled Add to Playlist at its root. One `UITableViewController` per level sits in a navigation controller.

**The root and the folders are two classes.** `FilesRootViewController` is the root: the Locations and action rows, the plus menu, the pickers, Open URL…, the paste row and `showDirectory:highlighting:`. `FolderViewController` is one directory: its listing, art, filter, bar, Select and sort, the subfolder walk, the equalizer and the row actions. The root makes each folder screen it pushes and hands it what the stack shares: the playback, the add sheet's flag, a block that answers the art cache, `addedRowsHandler` and `equalizerSurfaceVisible`. A folder pushes the next one with the same values. No folder screen reads the root through the navigation stack. `+Art` holds the album art. `+Actions` holds the bar, Select, a row's tap, and its swipe and long press. The listing, the filter, the opens, the table and the equalizer stay in `FolderViewController.m`. Their shared state is declared in `FolderViewControllerInternal.h`.

**The root's groups** are Locations (On My iPhone, then Dropbox once linked, then `LocationStore`'s folders), then Recents, then Choose File… and Open URL…, then the paste row while the clipboard holds a link. `VibeBrowserRootRows` (`BrowserRules.h`, tested from the macOS suite) is the one answer to what a root row is. `VibeBrowserRootLocationIndex` beside it maps a Locations row to its folder in the store. Both read whether Dropbox was linked at the root's last reload, never the live account. The account flips off main before its change is posted. A live read in that gap would open or delete the folder beside the one shown. The root's plus menu holds Add Folder… and, until an account is linked, Connect to Dropbox…. It is built each time it opens. It then follows the account. **A directory lists its folders, then its M3U playlists, then its playable files and CUE sheets**, each in `AppSettings.folderOpenSort`'s order through `FolderWalk listDirectory:sortedBy:folders:playlists:audio:`. That is the open's own filter and sort, so a song row shown is a row that plays, in the order shown. A playlist is not part of its folder's play: a tap plays it, and its long press has no Play in Folder.

- **A file tap plays that file alone, where it was tapped. A folder tap opens it.** The browser, Search and Recents share this rule. A one-track open presents the card but keeps the tab (`playbackDidOpenNewFolder:`). A folder, a file in its folder, or several picks bring the Playlist tab forward first. The long press has Play in Folder on a file and Play on a folder. Every open is a `PlaybackController` road: `openFileURL:inFolder:` for a tap, `addURLs:` for an Add, and `bookmarkFolderURL:` then `FavoritesStore` for a folder's star.
- **A replace asks first when the playlist was built by hand.** Every replacing tap (the browser's, Recents', Search's and Favorites') goes through `PlaybackController`'s `confirmReplacingPlaylistFrom:openingURLs:inFolder:token:`. `PlaybackController.playlistHasAdditions` is `FolderSession.hasAdditions`, YES once an Add has landed or for a playlist restored with additions. The alert offers Replace, Add Instead and Cancel. Any other playlist is replaced at once.
- **A row says what a tap costs**: the file's size from the listing's stat (a placeholder carries the remote size), `VibeNotDownloadedMark` on a file not downloaded, and the Playlist tab's equalizer on the file now playing (`playbackDidMoveToCurrentTrack:`). That equalizer is held to the root guarantee as the Playlist tab's is (`../AGENTS.md`). The shell sets the Files stack's exposure on the root (`equalizerSurfaceVisible`). The root sets it on every folder screen of its stack. Each screen adds its own appearance, and the row must be in the viewport (`vibeIsInViewportOfTableView:`). **TRAP: nothing in a screen's initializer may touch the disk.** A screen is made on main as a folder opens, and for a provider's folder a stat or name lookup is IPC that can block.
- **A file's icon is its album art when the metadata cache holds it or its bytes are on the device, else a tile** (`VibeFileTileImage`). Every list row's icon slot (here, Recents, Search and Favorites) is set by `vibeApplyFileIconForName:folder:art:`. Names take two lines and truncate in the middle (`vibeApplyFileNameStyle`). These row pieces live in `FileRow`, not the browser, because every list screen shares them. The art comes from one `AudioTrackMetadataCache` per stack of folders (`stackArtCache`). The root makes it when a folder screen first asks. It is asked for the rows on screen and a margin when a listing lands and when a scroll settles. **TRAP: a placeholder and a provider's dataless file are never parsed** (`loadArtForVisibleRows`). A parse's cache miss reads the tags from the file: ranged requests or a download for every row. They go to `loadCachedMetadata:`. It reads file attributes and the cache but never parses the audio file on a miss. One cache serves the screen on top, and a screen that goes cancels its own scan, never its successor's. A mirrored folder on screen relists on `VibeDropboxDownloadsDidChangeNotification`, so a finished download drops its mark and gains its art.
- **A row being opened spins in its icon slot**, here and in Recents, Search and Favorites (`vibeApplyRowContent:opening:`). `PlaybackController.openingPath` names it from the tap (`replaceRequestTokenOpening:`, before any resolve) until the open lands, finds nothing, is superseded or is given up. `playbackDidChangeOpening:` redraws. A second tap gives it up (`cancelOpening`). A resolve still running is then dropped by the replace funnel, and an open the session holds is cancelled by `FolderSession.cancelOpen`, which settles like an empty open. `kOpeningTimeout` gives up too, with an alert from the root. A caller whose own work ends before the open (a failed resolve, Cancel or Add Instead, a favorite shown in Files) ends it with `endOpeningForReplaceRequest:`.
- **The filter field narrows a listing by name** (`applyFilter`), installed once a listing has a dozen rows (`kFilterThreshold`). What an empty listing says is `VibeBrowserFolderEmptyStateFor` (`BrowserRules.h`). **TRAP: it is always shown, never hidden on scroll.** A collapsing search bar re-lays the bar out on the appearance callbacks the card forwards by hand, and the folder jumped under the card. It is `Stacked`, since iOS 26's integrated placement would put it in the bottom toolbar.
- **Select is multi-select Add.** It is a glyph, and named Select rather than Edit, since nothing is edited. While selecting, the title is the count, Select All takes the back button's place, and a listing or filter change is held. **TRAP: a row swipe sets `isEditing` too.** `isSelecting` excludes it through `_swipingRow`, or the bar flips into multi-select under the swipe.
- **The sort menu is titled "Sort folders by"**, the Settings row's own string, because it writes the one folder-open setting, not this folder's view. The add sheet has no sort menu; its bar carries Close at every level. The bar's items are absent, not disabled, in an empty folder.
- **A Dropbox directory draws from disk at once, then relists** (`DropboxMirror refreshDropboxFolder:`) when it appears, unless this screen listed it within `kRelistInterval`. Pull to refresh relists any directory. A relist that fails says so in a footer over rows already drawn, or in the empty state over none. An unlinked account pops the stack to the root. A sign-in started from the plus menu pushes the account's root when it lands.
- **Open URL… plays a web address** (`presentLinkSheet`). The sheet is `OpenURLSheetController`, modeled on the mac's window. It has a wrapping field with the URL keyboard, the system's Paste control, a spinner, and Cancel and Open. Open is disabled while the field is blank (`VibeLinkTextIsBlank`), and Return is Open. Open hands the field's text to the root's `openLinkText:`, which takes a replace token through `PlaybackController`'s `openLinkString:replacingPlaylistFrom:completion:`. `LinkStore` resolves the link off main, and its file opens alone through `confirmReplacing…`. While it resolves, the field and Open are disabled. The root says so through the sheet's `resolving`. Cancel or a swipe down cancels the resolve. A failure closes the sheet and shows `link.error.title` with `+[LinkStore messageForError:brief:]`. The completion runs before the replace question, so the sheet closes first and the question goes over `vibeTopmostPresenter`. The root holds the resolve's cancel block, not `openingPath`, since a link names no file until it resolves. The paste row shares that block with the sheet. In the add sheet the add token is taken before the resolve and the file goes to `addURLs:token:`. A link never takes the inbox road, which does not persist. `open_url` calls `openLinkString:replacingPlaylistFrom:completion:` directly (`Loading/Net/AGENTS.md` has the store).

  **TRAP: the sheet is dismissed by its presenter** (`dismissThen:`). Asked of the sheet itself, a dismiss closes only an alert it presents. **TRAP: the system draws its Paste control out of process, blank and ignoring taps, when its content does not fit.** Its height scales with the text size, and it spans the field.
- **The paste row opens a copied link.** It shows only while the clipboard probably holds a web link: `UIPasteboard`'s `detectPatternsForPatterns:` for `ProbableWebURL`, or `hasURLs`. Neither reads the clipboard, so neither raises the paste prompt. The check runs when the root appears, when a scene activates and on `UIPasteboardChangedNotification`, and skips a `changeCount` already checked. A tap hands the clipboard's item providers to `pasteItemProviders:` (`pasteClipboardLink`). Loading one shows iOS's Allow Paste prompt unless the user allowed pasting in the Settings app (`../Settings/AGENTS.md`). It opens the first web link (`VibePasteLinkOfItems`) through `openLinkText:`, and text that is no link shows the invalid-link alert. **TRAP: a denied paste still lists its items, with their types.** Only the loads fail (`PBErrorDomain` 13). A paste whose items yielded nothing therefore says nothing. A second tap while it resolves cancels it. **TRAP: the action rows take the dynamic `UIColor.tintColor`**, never `self.view.tintColor`'s value, which is gray while a sheet dims the tint.
- **The root uses system pickers for two jobs.** Add Folder… grants a location (`LocationStore addFolderURL:`, which refuses a covered one with a message), and Choose File… is a one-off multi-select pick. iCloud Drive has no item of its own, because public API cannot point the picker at it. A granted location opens in the browser, and nothing plays. A location is forgotten by the swipe Delete or the long press's Remove Location. A third picker grants the folder of a CUE sheet whose open found nothing (`CueFolderGrantPrompt`). The shell holds the prompt, because a picker's delegate is weak and the Files tab may never have been built.
- **The play button plays this folder alone. Its long press plays it with its subfolders** (`openDirectoryWithSubfolders`; Add with Subfolders in the sheet). The walk goes depth first in the listing's order, asks Dropbox for each mirror folder first, and stops after a folder reaches `kMaximumSubfolderTracks` listed audio entries or `kMaximumSubfolders` visited folders. Whole folders can exceed the entry limit. CUE expansion can add more rows. A capped walk reports the limit. The folders with songs open as one multi-URL open: the first is the base and the rest are additions. In a folder with no song directly inside, the button is its menu alone.
- **Recents is `RecentsStore`'s list**: every file and folder opened or added, newest first, at most `kMaximumRecentItems`. It is one `NSUserDefaults` key, `VibeiOSRecentItems`. Every screen reaches it through `RecentsStore.shared`, as Favorites reach `FavoritesStore`. **An open with more than five contributors records one recent.** It uses their common folder when a root covers it, otherwise the first contributor. `FolderSession` records each entry where the open lands, with the bookmark the open minted and its folder's display name (`recordRecentsOfOpen:`). A restore records nothing, and Clear Playlist keeps them. The name is recorded, not derived, since the path can outlive the app container it names. `RecentsViewController` lists them. A file plays alone, a folder opens in the browser, and the long press adds Play, Play in Folder, Add to Playlist and Open Folder (`VibeBrowserRowActionsFor`, `BrowserRules.h`, which Search shares). **A link (`LinkStore`'s `containsURL:`) has neither folder action**, since its folder is the Links store's, named by a hash. Its second line is the link's host (`LinkStore hostOfLinkFileURL:`, recorded when the open lands). The bar's Clear opens a one-item destructive menu. It is absent while the list is empty, and in the add sheet.
- **An Add's rows fly into the Playlist tab** (`addedRowsHandler`, set by the shell on the root and handed to each folder screen). The rows asked for are snapshotted and handed over before the request. `RootViewController+AddedRows` lifts them and flies them to the Playlist tab's item when `playback:didSettleAddLanding:` says the tracks landed. It sets them back down when the settle says nothing landed, or when a superseding open lands empty or is cancelled (`playbackDidCancelOpening:`). The animation has no timeout. Append settlements and superseding open events release the lifted rows. `check_consistency` reports rows left lifted (`liftedRowTimes`). The flight is a UIKit keyframe animation, not a `CAAnimation`, because an iPhone caps an app's own Core Animation at 60 Hz without an Info.plist opt-out. `UITab` has no view, so the target is found by the label the bar draws.
- **Open Folder** (Search and Recents) is `showDirectory:highlighting:` on the root. The stack becomes one screen per folder from the covering source, built before the tab switches, and the file it came from is scrolled to and selected for a moment. A folder no persistent root covers (a one-off pick, from Recents) is listed under a scope its screen holds for its lifetime (`FolderViewController`'s `holdsScope:`). An open made inside it takes the session's own hold from the recent's bookmark, so the playlist outlives the screen.

## LocationStore

The Files tab's Locations: the folders the user handed the app, as persisted security-scoped bookmarks. Each scope starts at launch and is held for the session. It is the iOS twin of the mac's `FolderAccessManager`, with its own `NSUserDefaults` key. **It is not only the search scope.** The Files tab lists its folders, Search walks them, and every folder the app shows is named here.

- **Coverage is tested against the persistent roots, never the open folder.** A subfolder of a listed folder, or anything inside Documents, is refused with a message. The open folder is transient, so refusing against it would drop a grant the user wants later. A folder that covers existing rows replaces them, and a restored folder some root now covers is dropped.
- **Bookmark work never blocks main, and one provider cannot hold up every root.** Launch restoration resolves at most `kMaximumConcurrentBookmarkRestorations` at once and merges on main in original order. New bookmarks are minted on a separate serial queue. Restore workers refresh stale bookmarks after opening their scopes. A replacing parent owns the narrower rows' scopes until its own mint lands. Pending identities remember a removed parent, so a late child cannot bring it back.
- **Removing a row hides it at once but defers `stopAccessingSecurityScopedResource`** until the playlist and every overlapping open release the grant object `FolderSession` was handed. Later metadata and waveform reads keep the access that made the playlist valid.
- **It posts `VibeSearchFoldersDidChangeNotification`, and the Files tab's root and Search derive their rows from that one delivery.** Launch resolves can land while either screen is up, and a local animation beside the notification would mutate the table twice.
- **A folder is named on screen by `displayNameForFolderURL:` and nowhere else**: the browser's titles and rows, the Playlist tab's title, a favorite's name and location, a recent's folder line. The Dropbox mirror's directory is the account id and reads "Dropbox". Documents reads "On My iPhone", with the model name the app delegate sets at launch (`deviceModelName`), so the store needs no UIKit. **Naming never touches the disk**, since asking a provider's folder for its name is IPC that can block main. The two roots are recognized by spelling, a location by the name resolved with its bookmark, and any other folder is its own path component. So a provider root reached through a one-off pick reads as its directory name (`com~apple~CloudDocs`), not "iCloud Drive".
- `restorePersistedFolders` runs at launch beside restore-or-adopt. It opens and plays nothing.
- The channel cannot drive the document picker, so `dump_search`, `add_search_folder` and `remove_search_folder` set up a scope for a test. **TRAP: a folder added through the channel is not security-scoped, yet it outlives the session.** `addFolderURL:` persists a plain bookmark whatever `startAccessingSecurityScopedResource` answered, and the next launch restores it. A test removes what it added, or later runs inherit the scope.
