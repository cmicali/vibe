# The Files tab (iOS)

The Files tab's browser and the Locations store (`VibeLocationStore`) are vibe-libs' `ui/FilesBrowser`. Its `AGENTS.md` is the authority for them and their traps.
This directory holds Vibe's side: its host over the playback (`PlaybackBrowserHost`), which also makes the Files tab's root and the add sheet's (`rootWithPlayback:appending:`), Vibe's groups below Locations (`FilesTabRows`, with the paste row and the Open URL sheet, `OpenURLSheetController`), its Dropbox source (`DropboxBrowserSource`), the Locations' keys and root names (`VibeLocationStore+Vibe`), and the tab's own rules (`FilesTabRules.h`).
It holds `RecentsViewController` and the list it shows (`RecentsStore`).
It holds `CueFolderGrantPrompt`, the folder picker a CUE sheet's open asks for (`../AGENTS.md`, FolderSession).

The shell, `PlaybackController` and `FolderSession` are `../AGENTS.md`.

## The browser

The Files tab. It is also the Playlist tab's add sheet (`appending:YES`), where every action appends and closes the sheet; it is titled Add to Playlist at its root.

**Vibe's host is `PlaybackBrowserHost`**, one per stack, made by the root. It offers Play, Play in Folder, Add to Playlist, and the star, or Add alone in the add sheet. Its words are `VibeStrings.h`'s, its sort is `AppSettings.folderOpenSort`, and its art holder is an `AudioTrack`. Its sources are Documents (a `VibeBrowserFolderSource`) and Dropbox (`DropboxBrowserSource`). It turns the Dropbox account's and downloads' notifications into the host's two source events. The root's Choose File… opens through it too.

**The root's groups** are Locations (the host's sources with a root, so On My iPhone, then Dropbox once linked, then `VibeLocationStore`'s folders), then Recents, then Choose File… and Open URL…, then the paste row while the clipboard holds a link. Vibe's groups are `FilesTabRows`, which the host hands the root as its `rootSections`. The root's plus menu holds Add Folder… and, while Dropbox is not linked, `DropboxBrowserSource`'s Connect to Dropbox…. **A directory lists in the host's sort, `AppSettings.folderOpenSort`, through `FolderWalk`.** That is the open's own filter and sort, so a song row shown is a row that plays, in the order shown. A playlist is not part of its folder's play: a tap plays it, and its long press has no Play in Folder.

- **A file tap plays that file alone, where it was tapped. A folder tap opens it.** The browser, Search and Recents share this rule. A one-track open presents the card but keeps the tab (`playbackDidOpenNewFolder:`). A folder, a file in its folder, or several picks bring the Playlist tab forward first. The long press has Play in Folder on a file and Play on a folder. Every open is a `PlaybackController` road, which the browser reaches through `PlaybackBrowserHost`: `openFileURL:inFolder:` for a tap, `addURLs:` for an Add, and `bookmarkFolderURL:` then `FavoritesStore` for a folder's star.
- **A replace asks first when the playlist was built by hand.** Every replacing tap (the browser's, Recents', Search's and Favorites') goes through `PlaybackController`'s `confirmReplacingPlaylistFrom:openingURLs:inFolder:token:`. `PlaybackController.playlistHasAdditions` is `FolderSession.hasAdditions`, YES once an Add has landed or for a playlist restored with additions. The alert offers Replace, Add Instead and Cancel. Any other playlist is replaced at once.
- **The playing file's row carries the Playlist tab's equalizer** (`playbackDidMoveToCurrentTrack:`). That equalizer is held to the root guarantee as the Playlist tab's is (`../AGENTS.md`). The shell sets the Files stack's exposure on the root (`equalizerSurfaceVisible`).
- **A file's icon is its album art when the metadata cache holds it or its bytes are on the device, else a tile.** Every list row's icon slot (the browser's, Recents', Search's and Favorites') is set by `vibeApplyFileIconForFolder:playlist:art:`, from vibe-libs' `ui/Rows`. The caller says whether the name is a playlist file (`VibeBrowserIsPlaylistName`, `BrowserRules.h`). A mirrored folder on screen relists on the host's `browserHostSourceFilesDidChange`, which Vibe's host sends on `VibeDropboxDownloadsDidChangeNotification`, so a finished download drops its mark and gains its art.
- **A row being opened spins in its icon slot**, here and in Recents, Search and Favorites (`vibeApplyRowContent:opening:`). `PlaybackController.openingPath` names it from the tap (`replaceRequestTokenOpening:`, before any resolve) until the open lands, finds nothing, is superseded or is given up. `playbackDidChangeOpening:` redraws. A second tap gives it up (`cancelOpening`). A resolve still running is then dropped by the replace funnel, and an open the session holds is cancelled by `FolderSession.cancelOpen`, which settles like an empty open. `kOpeningTimeout` gives up too, with an alert from the root. A caller whose own work ends before the open (a failed resolve, Cancel or Add Instead, a favorite shown in Files) ends it with `endOpeningForReplaceRequest:`.
- **The sort menu is titled "Sort folders by"**, the Settings row's string, because it writes the one folder-open setting, not this folder's view. The add sheet has no sort menu.
- **A Dropbox directory draws from disk at once, then relists** through `DropboxBrowserSource`, whose refresh is `DropboxMirror refreshDropboxFolder:`. Unlinking the account leaves Dropbox with no root, which pops its screens to the root. A sign-in started from the plus menu pushes the account's root when it lands.
- **Open URL… plays a web address** (`presentLinkSheet`). The sheet is `OpenURLSheetController`, modeled on the mac's window. It has a wrapping field with the URL keyboard, the system's Paste control, a spinner, and Cancel and Open. Open is disabled while the field is blank (`VibeLinkTextIsBlank`), and Return is Open. Open hands the field's text to `FilesTabRows`' `openLinkText:`, which takes a replace token through `PlaybackController`'s `openLinkString:replacingPlaylistFrom:completion:`. `LinkStore` resolves the link off main, and its file opens alone through `confirmReplacing…`. While it resolves, the field and Open are disabled. The rows say so through the sheet's `resolving`. Cancel or a swipe down cancels the resolve. A failure closes the sheet and shows `link.error.title` with `VibeLinkMessageForError` (`Common/StringRules.h`). The completion runs before the replace question, so the sheet closes first and the question goes over `vibeTopmostPresenter`. The rows hold the resolve's cancel block, not `openingPath`, since a link names no file until it resolves. The paste row shares that block with the sheet. In the add sheet the add token is taken before the resolve and the file goes to `addURLs:token:`. A link never takes the inbox road, which does not persist. `open_url` calls `openLinkString:replacingPlaylistFrom:completion:` directly (`Loading/Net/AGENTS.md` has the store).

  **TRAP: the sheet is dismissed by its presenter** (`dismissThen:`). Asked of the sheet itself, a dismiss closes only an alert it presents. **TRAP: the system draws its Paste control out of process, blank and ignoring taps, when its content does not fit.** Its height scales with the text size, and it spans the field.
- **The paste row opens a copied link.** It shows only while the clipboard probably holds a web link: `UIPasteboard`'s `detectPatternsForPatterns:` for `ProbableWebURL`, or `hasURLs`. Neither reads the clipboard, so neither raises the paste prompt. The check runs when the root appears, when a scene activates and on `UIPasteboardChangedNotification`, and skips a `changeCount` already checked. A tap hands the clipboard's item providers to `pasteItemProviders:` (`pasteClipboardLink`). Loading one shows iOS's Allow Paste prompt unless the user allowed pasting in the Settings app (`../Settings/AGENTS.md`). It opens the first web link (`VibePasteLinkOfItems`) through `openLinkText:`, and text that is no link shows the invalid-link alert. **TRAP: a denied paste still lists its items, with their types.** Only the loads fail (`PBErrorDomain` 13). A paste whose items yielded nothing therefore says nothing. A second tap while it resolves cancels it. The action rows take the dynamic tint color (the piece's trap).
- **Choose File… is a one-off multi-select pick.** It is `FilesTabRows`', with a picker delegate of its own. Add Folder… is the root's, and grants a location (`VibeLocationStore addFolderURL:`, which refuses a covered one with a message). iCloud Drive has no item of its own, because public API cannot point the picker at it. A third picker grants the folder of a CUE sheet whose open found nothing (`CueFolderGrantPrompt`). The shell holds the prompt, because a picker's delegate is weak and the Files tab may never have been built.
- **The play button plays this folder alone. Its long press plays it with its subfolders** (Add with Subfolders in the sheet). The walk is the piece's. Vibe's handler opens the folders with songs as one multi-URL open: the first is the base and the rest are additions.
- **Recents is `RecentsStore`'s list**: every file and folder opened or added, newest first, at most `kMaximumRecentItems`. It is one `NSUserDefaults` key, `VibeiOSRecentItems`. Every screen reaches it through `RecentsStore.shared`, as Favorites reach `FavoritesStore`. **An open with more than five contributors records one recent.** It uses their common folder when a root covers it, otherwise the first contributor. `FolderSession` records each entry where the open lands, with the bookmark the open minted and its folder's display name (`recordRecentsOfOpen:`). A restore records nothing, and Clear Playlist keeps them. The name is recorded, not derived, since the path can outlive the app container it names. `RecentsViewController` lists them. A file plays alone, a folder opens in the browser, and the long press adds Play, Play in Folder, Add to Playlist and Open Folder (`VibeFilesTabRowActionsFor`, `FilesTabRules.h`, which Search shares). **A link (`LinkStore`'s `containsURL:`) has neither folder action**, since its folder is the Links store's, named by a hash. Its second line is the link's host (`LinkStore hostOfLinkFileURL:`, recorded when the open lands). The bar's Clear opens a one-item destructive menu. It is absent while the list is empty, and in the add sheet.
- **An Add's rows fly into the Playlist tab** (`addedRowsHandler`, set by `PlaybackShellHost` on the root and handed to each folder screen). The rows asked for are snapshotted and handed over before the request. `PlaybackShellHost+AddedRows` lifts them and flies them to the Playlist tab's item when `playback:didSettleAddLanding:` says the tracks landed. It sets them back down when the settle says nothing landed, or when a superseding open lands empty or is cancelled (`playbackDidCancelOpening:`). The animation has no timeout. Append settlements and superseding open events release the lifted rows. `check_consistency` reports rows left lifted (`liftedRowTimes`). The flight is a UIKit keyframe animation, not a `CAAnimation`, because an iPhone caps an app's own Core Animation at 60 Hz without an Info.plist opt-out. `UITab` has no view, so the target is found by the label the bar draws.
- **Open Folder** (Search and Recents) is the root's `showDirectory:highlighting:`, called before the tab switches. A folder no persistent root covers, such as a one-off pick from Recents, is listed under a scope its screen holds. An open made inside it takes the session's own hold from the recent's bookmark, so the playlist outlives the screen.

## The Locations

`VibeLocationStore` is the piece's, and its rules are in its header and code. Vibe configures it at launch through `VibeLocationStore+Vibe` (`installVibeWithDeviceModelName:`), before the store is first used. That sets Vibe's `NSUserDefaults` keys and its root namer. The namer reads the Dropbox mirror's directory, which is the account id, as "Dropbox". It reads Documents as "On My iPhone", with the model name the app delegate passes in. So a provider root reached through a one-off pick reads as its directory name (`com~apple~CloudDocs`), not "iCloud Drive".

- **It is not only the search scope.** The Files tab lists its folders, Search walks them, and every folder the app shows is named by `displayNameForFolderURL:`: the browser's titles and rows, the Playlist tab's title, a favorite's name and location, and a recent's folder line.
- **The Files tab's root and Search derive their rows from one delivery of `VibeLocationsDidChangeNotification`.** Launch resolves can land while either screen is up, and a local animation beside the notification would mutate the table twice.
- **A removed row's scope outlives the playlist.** `FolderSession` holds the grant object the store hands it, so the scope stays open until the playlist and every overlapping open let it go.
- `restorePersistedFolders` runs at launch beside restore-or-adopt. It opens and plays nothing.
- The channel cannot drive the document picker, so `dump_search`, `add_search_folder` and `remove_search_folder` set up a scope for a test. **TRAP: a folder added through the channel is not security-scoped, yet it outlives the session.** `addFolderURL:` persists a plain bookmark whatever `startAccessingSecurityScopedResource` answered, and the next launch restores it. A test removes what it added, or later runs inherit the scope.
