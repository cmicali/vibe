# Settings window

- `Settings/` holds the Settings window (Vibe > Settings…, ⌘,): `SettingsWindowController`, a toolbar-style `NSTabViewController` in the standard macOS settings-window shape, created lazily by `AppDelegate` and kept alive across closes. ⌘W closes it: File > Close is nil-targeted, and the window controller's own `closeFile:` catches it ahead of the player's.
- **The window title is the title-propagation chain, never set directly**: each pane's `NSViewController.title` names its tab AND, through the tab controller's selected-child propagation and the window's contentViewController title binding, the window. A manually set window title loses to that chain — the propagation clears it to nil on every tab switch (the "Untitled" bug).
- One pane per `SettingsPaneViewController` subclass, one file each, on the shared scaffolding in the base class: the pane size (width/height constraints AND `preferredContentSize`; a bare frame yields an arbitrary window size — and the design size is a *minimum*, grown to the form grid's fitting size so a long localization widens the pane instead of clipping, which Greek was the first to do) and the top-centered two-column form grid. Panes reload control state in `refreshFromSettings`, which the base runs on every appearance, whenever the window regains key (a system panel returned), and after any menu-bar tracking ends (a menu changed a mirrored setting while the pane stayed visible). The window is deliberately not resizable.
- **The tab-switch resize is animated by exactly one path**, `SettingsTabViewController`'s `didSelectTabViewItem:`, at the app's fixed `kWindowResizeAnimationDuration` through `[window animator] setFrame:` in an explicit `NSAnimationContext` — NOT `setFrame:display:animate:`, whose legacy blocking stepper consumes its duration here without rendering a single intermediate frame. Two AppKit mechanisms each snap the window to the incoming pane's size before the animation can run — turning it into a no-op — and both are disarmed: the panes' size constraints sit at 999, just below required (a required size forces the window there in one layout pass, while at 999 they still define the fitting size and stretch during the animation), and the tab controller swallows `setPreferredContentSize:` (AppKit resizes a window immediately when its `contentViewController`'s preferredContentSize changes). Because nothing else corrects the size anymore, the window controller re-asserts the selected pane's size after the frame autosave restores — the autosaved frame carries a possibly different pane's size.
- Tab titles reuse menu strings where the word is the same (Playback, Appearance, Convert); settings-only strings live in the `settings.*` key family.

## Panes

- **General**: the Output popup — mirrors the menu bar's Output menu (same layout, checkmark rule and change action) by using its own `OutputDevicesMenuController` instance as the popup menu's delegate and builder; the controller's device observation refreshes it while open, the pane's own observation plus appear/key refreshes cover it closed — and the default-player button. `DefaultAppClaim` (here; the type list is `DocumentTypes` in `Common/`) claims every declared audio type one at a time, because each request can raise its own system confirmation panel and a refusal stops the walk. No alert of our own: the system's panel is the whole conversation, and the button reports the result — disabled "Vibe Is the Default Music Player" once it holds them all, refreshed when the window regains key after the system panel. The folder declaration is excluded on purpose: Vibe must never become the default folder handler.
- **Playback**: pitch range (the menu funnels through the same `applyPitchRange`), the skip-step presets (`AppSettings.skipBaseBars`: base/2×/4× bars), the crossfade length (`AppSettings.crossfadeMilliseconds`, pushed live to `AudioPlayer.crossfadeMilliseconds`; see `Audio/CLAUDE.md`), and the BPM- and key-analysis toggles (`AppSettings.analyzeBPM`, default on, and `.analyzeKey`, default **off** — see `Audio/CLAUDE.md` — both read by the waveform loader). How a key is *written* is Appearance's business, not this pane's: this one only decides whether it is detected.
- **Appearance**: appearance (writes the setting, then `setAppearance:` with a non-menu sender applies without rewriting), waveform style (identifiers ride `representedObject`, localized names display-only — the registry re-exposed through `MainPlayerController+Menus`), the time-display mode (`showRemainingTime` + `refreshTimeDisplay`, the discoverable form of clicking the right time label), and the two key-label choices: notation (`AppSettings.keyNotation`, Camelot or musical, identifiers on `representedObject` like the waveform styles) and `keyColorsEnabled` (default off, the CDJ-style coloring). Both push live through `refreshKeyDisplay`, and both govern *every* key shown including a tagged one, since a tag is parsed to a `VibeMusicalKey` when read and never displayed as written.
- **Convert**: where Convert to FLAC writes (`AppSettings.convertAsksWhereToSave` — the converter skips its silent placement rungs and goes straight to the save panel) and Delete Original After Convert, the same setting as the Convert menu's checkmarked item.
- **Advanced**: the cache-size readout (both stores summed through each cache's `diskUsageWithCompletion:`, generation-guarded against a stale reply landing after a clear), the Clear Cache button (the same two `invalidateWithCompletion:` calls as the debug channel's `clear_caches`), and the lifetime `AppStats` readouts, with listening time spelled through `Formatters.spelledDurationString:`.
