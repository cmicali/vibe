# Settings window

- `Settings/` holds the Settings window (Vibe > Settings…, ⌘,): `SettingsWindowController`, a toolbar-style `NSTabViewController` in the standard macOS settings-window shape, created lazily by `AppDelegate` and kept alive across closes. ⌘W closes it: File > Close is nil-targeted, and the window controller's own `closeFile:` catches it ahead of the player's.
- **The window title is the title-propagation chain, never set directly**: each pane's `NSViewController.title` names its tab AND, through the tab controller's selected-child propagation and the window's contentViewController title binding, the window. A manually set window title loses to that chain — the propagation clears it to nil on every tab switch.
- One pane per `SettingsPaneViewController` subclass, one file each, on the shared scaffolding in the base class: the pane size (width/height constraints AND `preferredContentSize`; a bare frame yields an arbitrary window size — and the design size is a *minimum*, grown to the form grid's fitting size so a long localization widens the pane instead of clipping) and the top-centered two-column form grid. Panes reload control state in `refreshFromSettings`, which the base runs on every appearance, whenever the window regains key (a system panel returned), and after any menu-bar tracking ends (a menu changed a mirrored setting while the pane stayed visible). The window is deliberately not resizable.
- **The tab-switch resize is animated by exactly one path**, `SettingsTabViewController`'s `didSelectTabViewItem:`, at the app's fixed `kWindowResizeAnimationDuration` through `[window animator] setFrame:` in an explicit `NSAnimationContext` — NOT `setFrame:display:animate:`, whose legacy blocking stepper consumes its duration here without rendering a single intermediate frame. Two AppKit mechanisms each snap the window to the incoming pane's size before the animation can run — turning it into a no-op — and both are disarmed: the panes' size constraints sit at 999, just below required (a required size forces the window there in one layout pass, while at 999 they still define the fitting size and stretch during the animation), and the tab controller swallows `setPreferredContentSize:` (AppKit resizes a window immediately when its `contentViewController`'s preferredContentSize changes). Because nothing else corrects the size anymore, the window controller re-asserts the selected pane's size after the frame autosave restores — the autosaved frame carries a possibly different pane's size.
- Tab titles reuse menu strings where the word is the same (Playback, Appearance, Convert); settings-only strings live in the `settings.*` key family.

## Panes

- **General**: the Output popup — mirrors the menu bar's Output menu (same layout, checkmark rule and change action) by using its own `OutputDevicesMenuController` instance as the popup menu's delegate and builder; the controller's device observation refreshes it while open, the pane's own observation plus appear/key refreshes cover it closed — and the default-player button. `DefaultAppClaim` (here; the type list is `DocumentTypes` in `Common/`) claims every declared audio type one at a time, because each request can raise its own system confirmation panel and a refusal stops the walk. No alert of our own: the system's panel is the whole conversation, and the button reports the result — disabled "Vibe Is the Default Music Player" once it holds them all, refreshed when the window regains key after the system panel. The folder declaration is excluded on purpose: Vibe must never become the default folder handler. The Always-on-top checkbox is `AppSettings.alwaysOnTop`, the same setting as View > Always on Top; the pane writes it and calls `MainPlayerController.applyAlwaysOnTop`, the one place that pushes it to window levels — the player's, and through `AppDelegate.applyAuxiliaryWindowLevels` the About and Settings windows', which must ride at the player's level or the floating player would bury them.
- **Playback**: pitch range (the menu funnels through the same `applyPitchRange`; `AppSettings` is the one place that normalizes — a persisted value that is not exactly 16 reads as 8, so a hand-edited plist cannot reach the fader's divisor), the skip-step presets (`AppSettings.skipBaseBars`: base/2×/4× bars), the crossfade length (`AppSettings.crossfadeMilliseconds`, pushed live to `AudioPlayer.crossfadeMilliseconds`; see `Audio/CLAUDE.md`), and the BPM- and key-analysis toggles (`AppSettings.analyzeBPM`, default on, and `.analyzeKey`, default **off** — see `Audio/CLAUDE.md` — both read by the waveform loader). How a key is *written* is Appearance's business, not this pane's: this one only decides whether it is detected.
- **Appearance**: appearance (writes the setting, then `setAppearance:` with a non-menu sender applies without rewriting), waveform style (identifiers ride `representedObject`, localized names display-only — the registry re-exposed through `MainPlayerController+Menus`), the Show file info checkbox (`AppSettings.showFileInfo`, default on — off hides the header's codec and BPM/key readouts; the same setting as View > Show File Info, pushed live through `refreshFileInfoDisplay`), the time-display mode (`showRemainingTime` + `refreshTimeDisplay`, the discoverable form of clicking the right time label), and the two key-label choices: notation (`AppSettings.keyNotation`, Camelot or musical, identifiers on `representedObject` like the waveform styles) and `keyColorsEnabled` (default off, the CDJ-style coloring). Both push live through `refreshKeyDisplay`, and both govern *every* key shown including a tagged one, since a tag is parsed to a `VibeMusicalKey` when read and never displayed as written.
- **Convert**: where Convert to FLAC writes (`AppSettings.convertAsksWhereToSave` — the converter skips its silent placement rungs and goes straight to the save panel) and Delete Original After Convert, the same setting as the Convert menu's checkmarked item.
- **Permissions**: the granted-folder list over `FolderAccessManager` (here): every folder the user opens, drags onto the app, or adds through the pane's Add Folder panel is stored as an app-scoped security bookmark (`com.apple.security.files.bookmarks.app-scope` in `Vibe.entitlements`) and re-opened at the next launch, so a sandbox grant survives relaunch. A playlist file is the one open that has to *ask*: opening a .cue/.m3u grants that file alone, not the audio it names, so an unreadable entry raises `requestAccessForPlaylistFolder:` — the same picker and bookmark as Add Folder, serialized on its own gate because powerbox prompts must not stack, and blocking the expansion worker that called it. It lives here, with the other grants, rather than in `NSURLUtil`, which only detects that a grant is needed and reaches this through the handler `AppDelegate` installs at launch: `Vibe/Util` is in the future-shared, no-AppKit source group, and a modal panel in a path utility inverts that. The auto-add hooks live at the two open funnels — `AppDelegate.openURLs:appending:` and `MainWindow.performDragOperation:` (drops bypass the AppDelegate funnel) — and bookmark only directories, skipping anything under an existing grant or under ~/Music, which the `com.apple.security.assets.music.read-write` entitlement covers standing. Restore resolves bookmarks off the main thread (an unreachable mount can block), merges on main, and holds only opens covered by a still-restoring remembered folder until that specific scope settles; a failed resolve keeps its row so it can be removed. **Every wait for a grant is deadlined at the same two seconds** — the launch drain's and each open's alike. Waiting is an optimization: proceeding without the grant merely risks an unreadable folder, which every open path handles, while waiting forever on a mount that never answers leaves the window in its launch grace with a blank header and no way out. The coverage check that decides whether an open must wait is deliberately case-*insensitive* (`FolderAccessRules.h`), the opposite of `noteOpenedURLs:`'s: these URLs come straight off Launch Services rather than canonicalized, and over-matching only costs a wait that was not needed. The list is multiple-selection, so Remove takes a batch, and Edit > Select All (nil-targeted, `Menu/CLAUDE.md`) reaches it through the responder chain once a row has been clicked. Folders can also be dragged straight onto the list, which is the same `noteOpenedURLs:` funnel — the drag carries the grant the bookmark is made from, and coverage and ~/Music are skipped there as always. What counts as a folder is asked of the *pasteboard*, not the file system (`NSPasteboardURLReadingContentsConformToTypesKey` against `public.folder`): validation runs on the main thread for every mouse move of the drag, and a stat can block on an unreachable mount. A package is a directory but not a `public.folder`, so an app bundle is refused during the drag rather than silently discarded after it, and the drop retargets onto the list as a whole (`setDropRow:-1`) because the rows are in the order grants were added and an insertion point would promise something the store cannot honor. Add Common Folder is a pull-down over the same panel, staged on the home folder, Documents, iCloud Drive or Dropbox with nothing selected, since the sandbox grants nothing the user has not picked: confirming returns the displayed folder. **The real home comes from `getpwuid`** — inside the sandbox `NSHomeDirectory` *and* `NSHomeDirectoryForUser` both answer with the container, which silently made every candidate a path under `…/Containers/…/Data`. The button always opens; each item carries its own state instead, disabled and suffixed "(Not found)" when the folder is not on disk or "(Already accessible)" when a grant already covers it, so the menu says why rather than going quietly dead. Dropbox is offered at `~/Dropbox`, falling back to `~/Library/CloudStorage/Dropbox` where the file-provider install left no symlink. The pane uses the generic folder content-type icon, so displaying a dead remembered path never asks the mount for a path-specific icon, and refreshes from `FolderAccessManagerDidChangeNotification` on top of the base's refresh contract. Persistence is the manager's own `VibeGrantedFolders` defaults key — bookmark blobs, not settings, so deliberately not `AppSettings`.
- **Advanced**: the cache-size readout (both stores summed through each cache's `diskUsageWithCompletion:`, generation-guarded against a stale reply landing after a clear), the Clear Cache button (the same two `invalidateWithCompletion:` calls as the debug channel's `clear_caches`), and the lifetime `AppStats` readouts, with listening time spelled through `Formatters.spelledDurationString:`.
