# Playlist

- Row backgrounds are `PlaylistRowView`'s, not AppKit's: `drawSelectionInRect:` does NOT call super, replacing the system `selectedContentBackgroundColor` accent-blue fill with a neutral white/black wash at ~9%, and the playing row (`playingRow`, set in `rowViewForRow:` and re-stamped across the visible rows by `refreshRowViewPlayingStates` on every `currentIndex` change — `reloadDataForRowIndexes:` rebuilds cell views but keeps row views) draws the same wash. The artwork-derived accent lives only in the playing row's equalizer indicator (`EqualizerIndicatorView.barColor`) — deliberately never as a full-width saturated fill, and deliberately NOT on the title text, which keeps its normal label color like every other row (the indicator plus the neutral wash is the whole "playing" marking). The color arrives from `ArtworkDisplayController`'s `accentColorDidChangeHandler` (same dominant-color resolution as the header wash, clamped into an OKLCH band that stays legible over the playlist frost) via `PlaylistController.accentColor`, which reloads the playing row on change.
- `PlaylistController` (Playlist/) owns the track list as NSTableViewDataSource/Delegate; `PlaylistTableView` (same directory) owns everything structural about the table — columns, row metrics, the enclosing scroll view (`scrollViewWithFrame:`, placed by `MainPlayerContentView`), the code-built cell views (track number/equalizer, artwork thumbnail, title/artist, duration), and their text styling — so the controller only decides cell *content* (`cellViewForColumn:` + the formatting helpers). Attaching the table (`setTableView:`, from `MainPlayerController.windowDidLoad`) wires delegate/dataSource/double-click and installs the row context menu ("Show in Finder" for the *clicked* row — action and validation live in `PlaylistController`; the window-wide menu's item reveals the *current* track and stays with `MainPlayerController`). `play:` replaces the list; `append:` extends it without touching playback or `currentIndex` (rows never move otherwise, so the track→row map only ever grows). Every track change scrolls the playing row into view (`scrollCurrentTrackToVisible`, a no-op while it is already visible) — nothing else scrolls the table, so auto-advance used to lose the playhead off screen. Launch-Services opens are handled as a *burst* in `AppDelegate`: the first batch plays immediately (a double-clicked file must not wait out a coalescing delay) and later batches within a 0.3 s quiet period are appended via `MainPlayerController.addURLs:`, so a multi-file open that LaunchServices splits across events still lands as one playlist without restarting the first track. The ⌘O panel and Open Recent bypass the burst and always replace.
